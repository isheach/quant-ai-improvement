## 2. 本轮分析：两组参数（按 4/24 切样本外）

**两组只差 3 个趋势参数**（其余一致）：

| 完整参数名（释义）| eva010.1 训练最优 | eva010.2 测试最优 |
|---|---|---|
| `InpTrendBreakoutBars`（趋势突破窗口K线数）| 30（慢）| 10（快）|
| `InpTrendConfirmBars`（趋势确认所需连续K线数）| 4 | 2 |
| `InpTrendTrail_ATR_Mult`（趋势单移动止损 = ATR倍数）| 2.7 | 1.9 |

**绩效（全段 / 样本内25.01–26.04.24 / 样本外）**：

| | eva010.1（慢趋势）| eva010.2（快趋势）|
|---|---|---|
| 全段 | 1190 笔，净 +2365，PF 1.45 | 3527 笔，净 +1740，PF 1.17 |
| 样本内 | PF **1.65**，净 +2436 | PF 1.23，净 +1718 |
| 样本外·前(2024) | PF 1.06，净 +22 | PF 0.95，净 −72 |
| 样本外·后(26.04.25+) | PF **0.91，净 −94（亏）** | PF **1.06，净 +94** |
| 单仓 MAE 最深 | $199.7 | $113.8 |
| 簇级峰值浮亏 | $241.9（>200 的簇 7 个）| $200.1（>200 的簇 1 个）|

### 三个关键发现
1. **浮亏确实降下来了，但靠的不是趋势门控。**
   - `trend_close_opposite_grid`（趋势确认后平逆势网格）在**两组里都触发 0 次**。
   - 原因（看源码 2033 行）：close-opposite 只在状态机"刚切换到趋势"的那一刻触发；而真实暴跌里，**`InpMaxClusterFloatingUSD` 浮亏熔断跑得更快**（价格几分钟跌 $200，趋势要等 K 线确认），熔断先平了 → 轮不到趋势门控。
   - 即：你担心的"固定美元止损"反而成了实际起作用的保护。**eva010.1 里它触发 20 次、合计 realized −1851**（把本可能回归的单子也砍了，正是你顾虑的点）；但换来峰值浮亏从 $339→$242、账户活下来。
2. **真正高效的浮亏保护是"快趋势 + 禁止逆势加仓"**（eva010.2）。
   - 快趋势让 `InpBlockAgainstTrendGrid`（趋势中禁止逆势网格新单）**提前生效**，网格根本没机会堆深 → 熔断只触发 3 次、峰值仅 $200。**这是比"事后熔断"更好的机制。**
3. **两组都不够"稳"（OOS 弱）+ 训练/测试最优分歧 = 过拟合未解。**
   - eva010.1 样本内 PF 1.65 但**样本外·后亏 −94**；eva010.2 样本外·后才 +94（勉强正）。
   - 训练最优要"慢趋势"、测试最优要"快趋势"——同一策略两个窗口选出相反方向，本身就是过拟合信号。

### 一个 churn 问题
- eva010.2 开了 **2696 笔独立趋势单，只净赚 +313**（网格部分 +1427）。做了海量功、收益微薄，且**这就是回测变慢 5 倍的主因**（trade 数 1223→3527）。

## 3. 改进方案

### 优先级 1：砍掉趋势单 churn，但保留它的"门控/阻断"价值（下一步实验）
- **做法**：`InpEnableTrendOrders`（是否开独立顺势单）= **false**；但 `InpEnableStateMachine`（状态机）保持 **true**。
  - 这样：不再开 2696 笔趋势单（去 churn + 回测大幅提速），但 `InpBlockAgainstTrendGrid` 仍靠状态机生效、继续压低浮亏。
- **目的**：隔离出"网格 + 快趋势阻断 + 浮亏熔断（无趋势单）"单独的样本外表现——看网格本体到底能不能打。
- 已生成 `eva011_noTrendOrders.set`（基于 eva010.2，仅改这一项，控制变量）。

### 优先级 2：用"快趋势阻断"做主保护，熔断退居兜底
- eva010.2 的机制（block 逆势加仓）比 eva010.1 的"事后熔断"更优。方向上**选快趋势那支**。
- `InpMaxClusterFloatingUSD`（簇级浮亏硬熔断，美元）先维持 **200**；若样本外仍见深簇可收到 **150**（$500 账户≈30%）。

### 优先级 3：抗过拟合（OOS 弱是根问题）
- 选参数**别用单窗口最优**。用 walk-forward：滚动训练→样本外，挑"邻域是高原 + 两段样本外都≥打平"的参数，而非净利第一。
- 若 OOS 始终接近打平，说明边缘集中在高波动体制 → 考虑**只在 regime2/3 开仓**（高波动收割器定位），用频次换稳健。

## 4. EA 速度：代码已无大漏洞，瓶颈在"交易数"

你反映回测变慢（原 10000+ 次 8 小时 → 本次 2000+ 次也估 8 小时，约 5 倍/次）。排查结论：

- **EA 本身已优化到位**，没有明显可省的每-tick 浪费：
  - `UpdateDashboard`（仪表盘）在**优化模式直接 return**、不绘制；
  - 审计写盘（trade_events 等）在**优化模式自动关闭**（多 pass 抢文件+拖慢已规避）；
  - `UpdateVolatilityRegime`、`UpdateMarketState` 都**按新柱节流**，非每 tick 重算指标。
- **变慢是"内生"的**：快趋势配置让趋势单从 ~0 涨到 2696、总 trade 数 1223→3527，MT5 测试器耗时随 trade 数+下单开销上升 → 单次自然变慢。
- **真正的提速杠杆（无需改 EA 代码）**：
  1. **关掉独立趋势单**（优先级 1 的实验）→ trade 数掉回 ~1190，直接提速；
  2. **优化用更快的 tick 模型**：筛选阶段用「1 minute OHLC」而非「Every tick based on real ticks」，可快一个数量级；选出前几名再用真 tick 复跑验证；
  3. **缩小搜索空间**：先粗网格（大步长）定方向，再在小范围细网格——别一次 4 参数细网格全开。

> 因此本轮**不重编译 EA**：一是已无大优化空间，二是你在做控制变量，频繁改 EA 二进制会污染对照。微优化（如 `ManageTrendTrailing` 无趋势仓时早退）留到下次有实质改动时一起做。
