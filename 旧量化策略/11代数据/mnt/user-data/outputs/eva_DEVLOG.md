## 2. R2 修正（采纳你点 1 的批评）
- **你的批评正确**：网格距若乘"百分比波动"是无量纲的——$1000 与 $4000 金价上同为 1% 波动会得到相同间距，等于又要手工乘 2/4。
- **修正**：**判档用百分比（尺度无关），算间距用"绝对波动（价格单位）"**。
  - 绝对波动 \(=\) 百分比波动 \(\times\) 当前价位 \(=\) RV(点)×point。它**随价位天然放大**：$4000 时约为 $1000 时的 4 倍，**无需手工乘数**。
  - 即 R2 落地时：\(\text{网格间距}=k_{grid}\times \text{RV}_{\text{点}}\)（绝对波动，自动随价位），\(\text{止盈}=r_{tp}\times\text{网格间距}\)。
- 这条已并入 R2 规格，待 R1 验证后实现。

## 3. 本轮代码：R1 已实现（百分比波动率判档）

### eva012_VolumetricPulseGrid_StateMachine.mq5（在 eva010 基础上改）
- **改了什么**：`UpdateVolatilityRegime` 的判档量从"长短比值 \(RV_{short}/RV_{long}\)"改为"**百分比波动** \(=100\times RV_{short}\times point/价位\)"，用**绝对百分比阈值**判档；四阈值方向滞后状态机**逻辑不变**，只把比较量与阈值换成百分比版。
- **为什么**：①百分比与价位无关 → 黄金 $1k/$5k 通用，删除对 `InpFixedLongRVPoints/InpFixedLongRVRefPrice`（固定RV+价格缩放）的依赖；②绝对阈值在**持续高波动里不洗白**（一直高就一直判高），解决你说的"长短一起变大、波动看着不变"。
- **怎么开关（控制变量友好）**：新增 `InpUsePctVolRegime`（默认 true=新百分比判档；false=回旧比值判档）。旧的 `InpRVRatio_*`、`InpUseFixedLongRV` 在新模式下自动失效、保留不删（降低改动风险）。
- **新增 input**：
  - `InpUsePctVolRegime`（是否用百分比判档）
  - `InpVolPct_MidToLow / InpVolPct_LowToMid / InpVolPct_HighToMid / InpVolPct_MidToHigh`（四个%阈值，约束 MidToLow<LowToMid≤HighToMid<MidToHigh）
  - `InpVolPctHighAbs`（%绝对阈值，>0时超过强制高波动；0=关）
- **日志**：新模式下 `G_RVRatio` 字段改记"百分比波动"，开 `InpEnableVolRegimeLog` 即可在 Experts 日志看到真实%值（用于校准阈值）。

## 4. 回答你的其余问题

### 点 2：并行 / 多机
- **单机多核**：MT5 优化器**本身就并行**（开多个本地测试代理 = 用满 CPU 核）。Python 不必自己多线程跑回测，MT5 已经在做。
- **多台电脑**：两条路——
  1. **MT5 原生远程代理**：把其它 PC 装成 MetaTester 代理加入同一次优化，MT5 自动分发；
  2. **Python 分片**：把 walk-forward 的"窗口"或"参数子网格"切片分给各机，各跑各的、最后把结果 CSV 汇总合并（编排器留 `shard_id/total_shards` 配置即可）。
- 任选其一即可，简单稳妥的是 2。

### 点 3：怎么判定更优 / train好test差 / 中途爆仓 / 滚动方式
- **判定更优**：以**测试段(样本外)分数**排序，不是训练段；且不是"某一窗口最高"，而是**多个测试窗口聚合**（中位数/最差值）最好者。
- **train好test差**：正是要**淘汰**的过拟合，walk-forward 天然把它打低分剔除；若**所有**参数都 train好test差 → 判决"无全天候边缘"，转 A 路线。
- **中途爆仓跑不完**：研究阶段用**很高的回测本金**（如 $100k）。因为我们固定手数、不复利，**本金高低不改变下单行为**，只是避免提前爆仓中断；跑完后再看"最大回撤的美元/百分比"决定真实账户该放多少。同时把**最大回撤作为约束**（超过阈值的参数直接判负），把"会爆仓"的参数筛掉。
- **滚动方式**：**寻参范围(候选网格)在所有窗口固定不变**；每个窗口在**自己的训练段**里独立寻一次最优，**不在上一窗口基础上接着调**；最后跨窗口看稳健性。（2017→2018 那轮：用同一固定范围，在 2017 训练段优化、到 2018 测试段验证，然后滚动。）

### 点 4：评分指标要改（同意）
- 现有 `OnTester` 评分只惩罚**已实现**回撤、浮亏漏网，且权重手调。建议改成**风险调整 + 一致性**导向：
  - 用**净利/最大权益回撤**(含浮亏)而非裸净利；
  - 惩罚**最大浮亏(权益回撤)**；
  - 加**一致性因子**：按月盈亏算"盈利月占比"或惩罚集中度（如净利的基尼系数），直接压制"靠某一段赚"的解；
  - 对成交太少(不可靠)/太多(过度交易)略加惩罚。
- 这块我可在 R2 之后单独改 `OnTester`，给你一版新评分。

### 点 5：寻参总"靠某一段赚"（过拟合）的应对
- ①**把一致性写进评分**（点 4，最直接）：让优化器不偏好集中解；
- ②**walk-forward**：一段奇迹的参数在多数测试窗口失败 → 被剔除；
- ③**分段硬约束**：要求在若干子区间各自 PF≥1（或 N/M 个为正）才入选；
- ④**Bootstrap/蒙特卡洛**：重采样成交看净利/回撤分布，识别"靠几笔/一段"的运气解。
