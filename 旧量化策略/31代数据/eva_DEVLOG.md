## 1. 历代工作与结论回顾（供恢复对话）

### 1.1 策略骨架（三分类口径）
- **网格（现金牛）**：震荡态围绕"基线"双向布网，偏离 `grid_dist` 点开逆向网格单，`bid≥基线`(多)/`ask≤基线`(空) 即整篮止盈（`grid_tp_baseline_revert`）。高胜率小利的均值回归。
- **趋势（叠加层）**：M5 双 EMA(20/60)+突破+RVRatio 识别 RANGE/涨/跌。趋势确认后：①禁开逆势网格；②可选砍逆势网格（`InpCloseOppositeGridOnTrend`）；③开独立顺势趋势单（ATR 止损+移动止损，`InpTrendTP_ATR_Mult=0` 即无固定止盈）。
- **砍单**：网格开的单，因趋势确认被平掉。**与趋势单同信号同刻触发** → 趋势单对错 = 砍单准确率。
- **风控**：分级 L2/L3/L4、`last_order_stop`、`cutoff_line_stop`、周末保护、加仓延迟、冷静期。

### 1.2 历代关键结论（前几轮，已确认）
- **三分类（数据逐组确认）**：网格挣钱(胜率 84\~89%)、趋势挣钱(33\~40%)、砍单亏钱(11\~20%)；砍单本身亏，但**避免网格亏更多**（关砍对照证明砍仓有效，+$377\~+$1003/组）。
- **趋势侧占利润 \~40\~45%**（非小补贴）；提高趋势精度是高杠杆（同时改善趋势侧利润 + 砍单准确率）。
- **砍仓有效机制**：逆势网格堆积 → `AdjustBaseline` 把基线朝亏损方向拖 → 整篮 TP 漂移 + 回归质量塌 + 深尾灾难；砍掉逆势仓 = 基线干净重置。
- **eva025b（双趋势）教训**：严格砍仓参数被优化器拉低（breakout 50→2\~13），**双趋势没被真正验证**；且发现"**砍仓频次是零和**"——砍少了误砍↓但尾部↑，净额守恒。
- **反复出现的元问题**：所有"精度类"参数（突破窗/确认根/RV/ADX阈值/MTF）只要留在优化空间，**优化器必然把它们拉低去刷样本内分**。这是 eva024→eva025b→eva025a **第 4 次**看到同一现象。

**关键量化（这是砍单亏损的精确来源）**：
- 网格一旦深度浮亏，**约 2/3（66\~70%）最终仍回归基线获利**，只有 **约 1/3（30\~34%）被砍**——但被砍的这 1/3 **集中了几乎全部砍单亏损（−$3.1k\~−$3.4k/组）**。

> 引申：真正能同时"少砍误伤 + 不漏尾部"的，仍是"砍得更准"（提精度），而非"砍多砍少"。深水单剖析把这个判断的数量级钉死了：可争取的误伤上限≈那 2/3 里被误砍的部分，量级中等，属"小而稳"。

## 3. 核心问题定位（本轮最重要的判断）

### 3.1 问题①（决定性）：新机制被寻参器架空 —— 收益无法归因于机制
| 新机制(中文/英文) | 默认 | 8 组寻参取值 | 是否真生效 |
|---|---|---|---|
| 多周期确认 `InpUseMTFConfirm` | true | **全 false** | **完全关闭** |
| ADX 强度阈值 `InpMinADX` | 25 | **10 / 15** | ADX≥10\~15 几乎不过滤 |
| EMA 间距阈值 `InpMinEMASepATR` | 0.5 | **0.1\~0.2** | 虽开启但阈值太低，几乎不过滤 |
| （旧）趋势突破窗 `InpTrendBreakoutBars` | — | 9\~10 | 仍宽松（近 eva024 的 8） |
| （旧）趋势确认根 `InpTrendConfirmBars` | — | 2 | 最小 |

- **代码本身正确**（`up_signal = rv_ok && ema_up && breakout_up && mtf_up && adx_ok && sep_ok`，三机制正确 AND 进信号，读已收盘 bar 无未来函数）——问题**纯在寻参取值**。
- **推论**：eva025a 的领先**很可能不来自 MTF/ADX/EMA间距**（它们几乎没开），而来自**网格参数（倒挂解决）+ 趋势 SL/移动止损参数**。因此——
- **"新机制能否提高趋势精度"这个 eva025a 的立项目标，本轮实际上没有被验证。** 这是第 4 次优化器架空精度参数。
- **组间自然实验也救不了**：8 组里机制参数只在 `InpMinADX`(10 vs 15) 与 `InpMinEMASepATR`(0.1 vs 0.2) 上有微小差异，且与网格/马丁/移动止损参数（`UniGridExpCoef`、`GridZ/MinGridZ`、`TrendSL/Trail`）**混杂在一起**，无法干净地把"机制的贡献"从"网格参数的贡献"里剥离。组间业绩差异（+1926\~+2795）**主要由网格/马丁/止损参数驱动**（如 a8 靠更宽网格 GridZ=3000/MinGridZ=8000 拿到最高净利），而非机制。→ 只能靠**方法1 的刻意隔离**来验证机制，观察数据本身给不出结论。

### 3.2 问题②：edge 仍薄、真OOS 窗口太短
- 测试集仅 2 个月、且靠 5 月撑，6 月只是打平。**不能据此判定 edge 稳固**，只能说"较前代改善、方向对"。
- 月度仍 lumpy，利润集中在个别强现金牛月份。

### 3.3 问题③（结构性，跨代一致）：砍仓频次零和
- eva025b 已证：砍多→误砍浪费；砍少→尾部漏出；净额守恒。**单纯调"砍多砍少"动不了大局。**
- 能动针的只有"**砍得更准**"（砍对的那批）= 提高趋势精度 = **这正是 eva025a 想做但本轮没测到的事**。

## 5. 改进方案（下一步，方法1/方法2/方法3 命名）

### 方法1（主，零代码）：隔离验证新机制 —— 固定机制、只优化网格
目的：把"eva025a 的领先到底是不是机制带来的"这个问题**一次性钉死**。做法是**把机制参数从优化空间移出、固定成有意义的值**，只优化网格/趋势管理参数，然后与"机制全关"的同网格参数版对照：

- **多周期确认** `InpUseMTFConfirm = true`（固定开）
- **ADX 强度阈值** `InpMinADX = 25`（固定；也可各跑一版 22 / 25 / 30，但**每版内固定、不进优化器**）
- **EMA 间距** 先 `InpUseEMASepFilter = false`（关，避免多重共线），或固定 `InpMinEMASepATR = 0.5`
- **趋势突破窗** `InpTrendBreakoutBars = 30`、**确认根** `InpTrendConfirmBars = 3`（固定，别再被拉回 8/2）
- 只把 `InpGridZ / InpMinGridZ / InpTrend SL/Trail` 等放进优化器。

对照判据：机制固定开 vs 机制全关（网格参数相同），比 **全程净利 / PF / 6月 / 三分类里趋势单胜率与砍单准确率**。若"机制开"的趋势单胜率与 6 月同时更好 → 机制**真有用**，才继续深挖；若无差别 → 机制**无效**，eva025a 的领先只是网格参数功劳，下一步该主攻网格侧或结构改造。

### 方法2（推荐先做，零代码但需你补数据）：离线反事实诊断
用本轮新写的 `eva025_signal_diagnose.py` + 你的**原始 m1 行情**，**不重跑 EA** 就能看出机制值不值得开：
- 它把 ADX/MTF/EMA间距 落到每笔**趋势单**入场时刻（趋势单结果=砍单准确率），输出"按 ADX 分桶的胜率/净利"与"要求 ADX≥{20,25,30}/MTF同向 会移除哪些信号、移除集是净正(误伤)还是净负(该滤)"。
- **若移除集净利显著为负** → 机制确实滤掉坏信号，方法1 的固定阈值就有据可依（不用拍脑袋）。
- 需要你把 `eva_data/XAUUSDm/` 的 **m1**（1 分钟 OHLC）发我，或自己在本地跑（脚本带用法与格式说明）。

### 方法3（备选，若方法1证明机制无效才启用）：转向网格侧 / 结构改造
若隔离后机制无效、砍仓频次又是零和，说明当前"网格+趋势叠加"结构接近天花板，候选大改（eva026+）：
- **入场态过滤**：只在"现金牛友好"区间（真震荡确认）开网格，趋势态干脆不开网格也不砍（靠"不开"避损，而非靠"砍"止损）。
- **趋势侧独立**：趋势侧已占利润 \~45% 且本轮变强，可考虑单独成策略优化，或与网格解耦以简化归因。

### 5.1 关于选组（若要挑一组继续）
- **a7 / a8 综合最好**（全程 +2446/+2795、测试 +269/+293、PF 1.26/1.29）。但 **a8 训练最弱(+1146/47%胜)却验证/测试最强**——这种"训练弱、样本外强"要么是更抗过拟合，要么是运气，**需更长前向窗口复核**，不宜单凭它下结论。
- 稳健起见，**a2/a4**（训练/验证/测试都均匀为正、PF 1.27\~1.28）作为方法1 的基准网格参数更稳。

### 5.2 诚实预期
- eva025a 已是最好一代，但**领先未必来自机制**，且**真OOS 仅 2 个月**。任何单一改动都仍是"小而稳"。**最关键的下一步不是再寻参，而是①隔离验证机制（方法1/2）②用更长的、真正没参与挑选的前向窗口复核。**
