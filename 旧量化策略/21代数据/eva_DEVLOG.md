## 1. 止损机制逐字确认（点 1a —— 你的理解正确）
源码 `CheckCutoffLineStopAndCooldown`（截止虚拟末单线硬止损）逐字如下：
```
max_n   = max_total_positions                       // 例如 3
geom    = Σ_{k=0}^{max_n-1} coef^k                   // coef=grid_exp_coef=1.4 → 1+1.4+1.96=4.36
cum_dist= base_grid_z × point × mult_cap × geom      // 到"第 max_n 单"的累计网格距
last_line = baseline ∓ cum_dist                      // 虚拟末单线(多:基线下方; 空:上方)
loss_dist = last_order_loss_per_lot 换算成价格        // 越过末单线后再容忍的亏损缓冲
止损触发  = 价格越过 (last_line ∓ loss_dist)
```
**确认：完全是你说的那样。** 即使只开了第 1 单（之后判逆势/其它原因不再加仓），止损线**仍按"假设一直加到第 max_n(第3)单"的累计距离来算**，再加一段 `last_order_loss_per_lot` 缓冲。所以：
- 止损位 = "虚拟第3单线" + 额外亏损缓冲，**与实际开了几单无关**；
- 你把 `GridZ` 寻到 5500（宽）→ `cum_dist` 被放大 → 末单线离基线约 $33 → 逆势单要跑很远才止损 → 单笔尾亏 −$15~−$17（最差 −$106）。
这正是上一轮"宽网格高胜率、却尾亏巨大"的机制来源。

## 2. 趋势为什么从不触发 + 已修复（点 1b —— 是 bug，不只是调参）
你 set 里 `InpCloseOppositeGridOnTrend=true`（平逆势网格是开的），但整段回测**没有一笔 `trend_close_opposite_grid` 出场** → 状态机**从未确认过任何趋势**。读 `EvaluateTrendSignals` 找到根因：
```
if(InpTrendUseRVFilter)
   rv_ok = (G_RVRatio >= InpTrendMinRVRatio);   // 趋势信号必须 rv_ok
```
- `G_RVRatio` 自 **eva019** 起被改成"百分比波动" `= 100×rv_short×point/price`，实测分布：中位 **0.016**、95 分位 **0.025**（enrich 的 `rv_ratio` 列 = G_RVRatio，已逐行核对）。
- 而 `InpTrendMinRVRatio` 默认 **1.35**（你 set 用 1）。**0.01~0.03 永远 < 1** → `rv_ok` 恒 false → `up_signal/down_signal` 恒 false → **趋势永远不确认**。
- 这是 eva019 改 `G_RVRatio` 量纲后遗留的**单位错配**，不是普通调参问题。

**eva022 修复（唯一改动）**：`InpTrendMinRVRatio` 默认 `1.35 → 0.020`（与 G_RVRatio 同量级；0.020≈让最高约 7% 的高波动时段开闸；可再调）。修复后趋势才能真正确认、`InpCloseOppositeGridOnTrend` 才会真的去平逆势网格。
- 阈值参考：取 0.024 → 约 7% 时段开闸；0.015 → 约 50%；0.030 → 约 1%。先用 0.020 跑，看趋势是否把尾部那 394 笔逆势大亏在变成 −$17 之前就平掉。
- 也可直接 `InpTrendUseRVFilter=false` 完全去掉这道闸做对照。

## 3. 钳制函数到底怎么算（点 2 —— 具体公式）
网格距分三步算（在 `UpdateActiveParams`）：
```
① 波动因子(原始)  rn   = 当前波动% / 参考波动%       // = G_RVRatio / InpRefVolPct
                  vf   = rn ^ InpGridVolExp          // 指数, 例如 2.7
② 钳制(本轮新增)  vf   = clip(vf, InpVolFactorMin, InpVolFactorMax)
                       = max(0.5, min(3.0, vf))      // 锁在 [0.5, 3.0]
③ 网格距(点)      grid = InpGridZ × (当前价/参考价) × vf   // 再与 InpMinGridZ×价格比 取大
```
**`clip(x,a,b)` = 若 x<a 取 a；若 x>b 取 b；否则取 x。** 数值例（GridZ=350、RefVol=0.024、指数 2.7）：

| 当前波动% | rn=波动/0.024 | rn^2.7(原始vf) | 钳制后vf | 网格因子效果 |
|---|---|---|---|---|
| 0.006(极低) | 0.25 | 0.024 | **0.5**(被下限托住) | 不再塌成 1pt |
| 0.012(低) | 0.50 | 0.16 | **0.5** | 托住 |
| 0.024(参考) | 1.00 | 1.00 | 1.00 | 正好 350pt |
| 0.036(高) | 1.50 | 3.0 | **3.0**(达上限) | 封顶,不爆 |
| 0.060(极高) | 2.50 | 11.6 | **3.0**(被上限压住) | 不再冲到 $62 |

一句话：**指数 2.7 决定中间过渡陡不陡，钳制把两端削平**——低波动因子最低 0.5（网格不塌），高波动因子最高 3.0（网格不爆）。只作用于网格；追价(指数0.8)、持仓移动(指数0)本就平缓，不钳制。

## 4. 评分为什么不随回测时长变大（点 3 —— 你问得对，关键在"除法"）
你的直觉对：若用"累加"，跑越久惩罚越多。我在 OnTester 里把每一项都改成了**比率/平均**（除以段数或天数），所以与时长无关：
| 项 | 朴素写法(会随时长涨) | 实际写法(跨时长不变) |
|---|---|---|
| 利润 | 总利润 profit | **每笔期望 = profit / n_trades** |
| 多次回撤 | Σ 深度²(段数越多累加越大) | **平均 = Σ深度² ÷ 回撤段数 dd_episodes** |
| 频次 | 总交易笔数 n_trades | **每日笔数 = n_trades ÷ 天数 days** |
代码对应：`avg_sq_depth = sum_sq_depth / dd_episodes;`、`tpd = n_trades / days;`、`expectancy = profit / n_trades;`。
- 多次回撤惩罚 `Dfreq = 1/(1+w×avg_sq_depth)`：用**平均每段深度²**，跑 1 年和 2 个月若回撤形态相似，得分相近。
- 频次惩罚 `Tfreq`：用**每日笔数**和目标每日笔数比，也与总时长无关。
- 所以三项都是"率/均值"，回测拉长不会单纯把分数拉低。（这是 eva016 专门做的"跨度无关"改造。）
