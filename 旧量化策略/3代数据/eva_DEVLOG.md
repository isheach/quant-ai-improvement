## 1. 此前工作摘要（第 1～3 代，压缩版）

- **目标**：让每笔单“可审计”——signal、趋势/波动状态、点差、过滤器、开仓后路径、MFE/MAE、出场方式、属正常亏损还是逻辑错误；建立可复用、可流水线化的开发与诊断流程。
- **架构**：行情只导一次 → EA 只输出交易事件 + 信号状态 → 后处理按时间切片 → 分析与回测解耦。仓库按 `品种/周期/月` 分块。
- **第 1 代（eva001/eva002…）**：首版脚本导出器（只导到近月）；`eva002` 可审计层（原策略逻辑零改动，新增 trade_events 43 列 / decision_audit / run_config 三类 CSV，优化模式自动关闭，价格用 `_Digits` 自适应）。
- **第 2 代（eva005~eva007）**：脚本导出器 v2（强制下载+等待重试、写 meta.json）；pipeline v2（point 自动读 meta.json，“大顺向”阈值改按价格判定）；请求格式 v2（point 可省略）。
  - **关键教训**：实时脚本读“终端实时缓存”，深层历史拉不满，只能拿到近月。
- **第 3 代（eva008）核心修复**：把导出器改成**在策略测试器里运行的 EA**——测试器会装载完整历史(2014→今)，EA 在测试器里能看到每个 tick/bar 且能写文件，这才是拿到完整 Exness 数据的可靠途径；`tick_volume` 沿用 Exness 口径，不脱离实盘。配套 `eva008_data_pipeline.py`、`eva008_data_request_template.json`。

> 结论：到本轮为止，“数据问题”已彻底解决——用户用 eva008 EA 成功导出了 2017-05 起的完整四周期数据。**主线由“怎么拿数据”正式切换到“策略到底行不行”。**

## 2. 本轮代码变更记录（changelog）

### eva008_data_pipeline.py —— build v3.1（PyCharm 直接运行版）
- **改了什么**：
  1. **去掉命令行（argparse）**，改为文件顶部一个 **CONFIG 区** + `MODE` 开关。在 PyCharm 里改好参数，直接点 Run 即可，无需在终端敲命令。
  2. 五种模式收敛为一个 `MODE`：`enrich` / `aggregate` / `slice` / `request` / `cache`。
  3. `enrich` 增强为：逐笔切路径算 **MFE/MAE（美元口径）**、`capture_ratio`（顺向兑现率），并按互斥优先级打 **问题单标签**：`deep_underwater`（不利行程≥$3，马丁深水）、`gaveback_loss`（有大顺向却亏损）、`early_exit`（顺向到位但兑现<30%）、`normal`、`no_path`。同时自动产出 `signal_performance.csv` / `regime_performance.csv`。
  4. **tick 缺失自动回退 m1**（`path_source` 字段标注实际用了哪个），老年份没有 tick 也能算近似 MFE/MAE。
- **为什么改**：用户明确反馈“不擅长命令行，要在 PyCharm 里跑”。功能口径与 eva006/eva008 保持一致（point 自动读 meta.json 缺省 0.001、阈值按价格、问题单分类、聚合表），仅交互方式从 CLI 改为改配置点运行。
- **本轮自测**：`py_compile` 通过；用 3 位合成 m1 + meta.json + 迷你交易表实跑 `enrich`，tick 缺失正确回退 m1，4 个产物（trade_enriched / problem_trades / signal_performance / regime_performance）全部正常生成，问题单分类生效。

### 其它
- `eva002`（可审计 EA）、`eva008_TickDataExporterEA.mq5`（导出 EA）、`eva008_data_request_template.json`（请求格式）本轮**不变**。

## 3. 本轮回测结果审核（eva002 · true01_2 · 2024-01~2026-06 · $400）

> 数据来源：`eva_trade_events.csv`（成交事件层，已实现盈亏）。
> **重大口径提醒**：此表仅含**已平仓**事件，**不含开仓簇运行期间的浮亏**。马丁/网格真正的风险是“一簇单子深度浮亏时的最大不利偏移”，那需要逐 tick 路径（decision_audit / enrich）才能看到。**因此下面的权益曲线“看起来平滑”严重低估了真实风险，务必结合 §4 一起读。**

### 3.1 总体（$400 起）
| 指标 | 值 |
|---|---|
| 成交事件 | 1223 笔 |
| 净盈亏合计 | **+4316** 美元（profit +4330 / swap −14 / 手续费 0） |
| 终值权益 | **4716** 美元 |
| 胜率 | 63.7% |
| 盈亏比 PF | 2.19 |
| 已实现最大回撤 | **−245**（峰值 −24.2%）|
| 最低权益 | **346**（< 400 初始，发生在 2025-03-11，即大行情启动前）|

### 3.2 训练 / 样本外划分（关键判别）
| 区段 | 笔数 | 净PnL | 胜率 | PF |
|---|---|---|---|---|
| 前段样本外 2024 | 203 | **−40** | 41.9% | 0.90（亏）|
| 训练内 2025.01–2026.04 | 815 | **+4193** | 69.2% | 2.75 |
| 后段样本外 2026.05+ | 205 | **+163** | 63.4% | 1.20 |
| **样本外合并** | **408** | **+123** | 52.7% | **1.10** |

**判读**：利润几乎全部落在训练窗口内（PF 2.75）；样本外合并只有 PF 1.10、近乎打平，2024 甚至小亏。这是**典型的过拟合特征**——不是“方法稳定有效”，而是“参数被这段行情喂出来了”。

### 3.3 利润来源高度集中（脆弱）
- **真实波动 regime2（高波动）**：仅 122 笔却贡献 **+2817（占总利润 65%）**，胜率 83.6%，均 +23。
- **马丁深层（倍率≥3）**：贡献 **+2152（占 50%）**，倍率 5+ 那 18 笔胜率 94%、净 +1033。
- **月度**：**2026-02(+1227) + 2026-03(+1563) 两个月 = +2790 ≈ 65% 的总利润**，正好是高波动月、也正好在训练窗口内。
> 含义：系统的“边缘”本质是“在高波动行情里靠深度马丁吃回归”。这恰恰是马丁最危险的地方——大部分钱来自深度回补，而毁灭性风险也藏在同一处。

### 3.4 出场原因拆解（哪里在漏血）
| exit_reason | 笔数 | 净PnL | 胜率 | 说明 |
|---|---|---|---|---|
| grid_tp_baseline_revert | 879 | **+4445** | 74.6% | 主力盈利来源 |
| trend_state_exit | 116 | +338 | 31.9% | — |
| sl | 207 | +197 | 41.6% | 多为趋势单止损 |
| **pacing_panic_stop** | **18** | **−420** | **0%** | **18 笔全亏**，纯漏血点 |
| **cutoff_line_stop** | **3** | **−245** | **0%** | 均 **−82**，单簇灾难（见下）|

- **cutoff_line_stop**：3 笔全部发生在 **2026-03-31** 同一空头簇，持仓 7–18 小时，单笔最大 **−141.65**；这一簇 = 本轮最大回撤事件。
- **pacing_panic_stop**：18 笔 100% 亏损，平均 −23，是确定性的负期望模块。
- **趋势单整体**：280 笔仅净 **+68**、胜率 34%，方向无论多空都接近打平偏负——**趋势模块基本是“增加复杂度、几乎不贡献边缘”的拖累项**。

## 4. 结论与下一步（参数问题 vs 方法问题）

**初步结论（待 §4 的逐 tick 复核确认）**：
1. **过拟合明确**：训练内 PF 2.75 / 样本外合并 PF 1.10，利润 65% 集中在 2026-02~03 两个高波动月。当前 `true01_2` 参数不能视为“稳健有效”。
2. **真实风险被低估**：成交表平滑，但 2026-03-31 一个空头簇就 −245（占 $400 的 61%）；这还只是**已实现**部分，开仓簇运行中的**浮亏**只会更深。在 $400 这种小资金上，深层马丁（倍率到 5~7、avg_vol_per_min 到 628）有**实质性爆仓风险**。
3. **可立即动手的“减法”**：
   - `pacing_panic_stop`（18/18 全亏）与 `cutoff_line_stop`（灾难尾部）→ 逻辑需重审，至少前者疑似净负、可考虑禁用或改触发条件。
   - 趋势模块（280 笔 +68、胜率 34%）→ 边缘几乎为零，评估是否裁撤以降复杂度。

**下一步（务必做，才能从“参数问题”分离出“方法问题”）**：
1. 用 **eva008_data_pipeline.py（v3.1）`MODE="enrich"`** 把 `eva_trade_events.csv` 与导出的 tick 路径对齐，跑出 **MFE/MAE / capture_ratio / problem_trades**，看：
   - 高波动月的盈利簇，开仓期间**最大浮亏**到底多深（量化真实风险）；
   - `deep_underwater` 与 `gaveback_loss` 占比，定位“出场太晚/方向错”的系统性问题。
2. 用 `signal_performance / regime_performance` 按 **“档位 × 状态 × 年份”** 切片，落实“2017-05 起的旧年压力测试 / 近年开发 / 最近前向”的分段判别。
3. 把 `eva_decision_audit.csv` 想办法传进来（或分块），才能做开仓上下文级别的归因。
