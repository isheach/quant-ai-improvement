## 2. 回应"三段法选参"（你点 2）
- **你的直觉完全对、也是标准做法**（train 训练 / validation 验证 / test 测试）。
- **一个要避开的坑**：你说的"看 test 是否随训练+验证分提高而提高、test 不再提高就选它"——这里**用 test 来做停止决策，等于把 test 也纳入了选择 → 数据泄漏**，test 就不再是干净的最终估计了。
- **正确版本**：
  - 训练段：拟合/寻参；
  - **验证段：用来"选"**（挑验证分最高、或验证分不再提升的那组）；
  - **测试段：只在最后用一次**报告诚实表现，**绝不参与选择**。
  - 你"看改善何时不再传导"的洞察很好——但找这个拐点要用**验证段**(test 的代理)，不能偷看 test。
- **更稳的做法**：与其单一三段切分，不如**滚动 walk-forward**（多个验证折），让"选哪组"不依赖某一次切分；这正是 eva015 工具 + MT5 Forward 模式要支撑的。
- 同意"现在还没到调参阶段"——eva015/三段法都是**调参期**才用；现在先把机制(R2/评分)做对。

## 3. 本轮代码改动（changelog）

### eva016_VolumetricPulseGrid_StateMachine.mq5（基于 eva013）

**(A) R2：网格间距 ∝ 实时绝对波动（你点 3 的"接着做 R2"）**
- **改了什么**：网格基距
  \[
  \text{base\_dynamic\_grid}=k_{grid}\times \text{RV}_{\text{点}}\times point\times \text{multiplier\_a}
  \]
  即 `InpGridZperVol × G_RVShortPoints × point × multiplier_a`，替代旧的 `base_grid_z（三套硬编码 100/350/700）× point × multiplier_a`。两处（多/空）都改。
- **为什么**：①绝对波动 = 百分比×价位，**随价位天然放大**（$4000≈$1000 的 4 倍），高波动自动变宽——这就是你要的"递进"，一个系数取代三个绝对值；②实时波动比固定值更适配当下体制。
- **开关与安全**：新增 `InpUseVolGrid`（默认 true；false=回旧三档基距，便于 A/B 控制变量）、`InpGridZperVol`（系数，约 0.5~3）。加了**启动保护**：`G_RVShortPoints>0` 才用波动基距，否则回退旧基距，避免 RV 未就绪时网格距=0 乱开单。
- **本轮未动止盈**：`base_profit`（三套）暂留，TP 的波动化(R2b)延后，避免一次改太多难定位编译错误。

**(B) OnTester 评分改为跨度无关（你点 3）**
- **改了什么**：
  1. 利润项 `profit^p` → **每笔期望** `(profit/trades)^p`：跑 1 年和 2 个月的相近数据 → 得相近分（不再被总笔数/总额带偏）。
  2. 多次回撤项 `Σ深度²`（累加，随时长增长）→ **平均每段深度²** `Σ深度²/段数`：与回测时长无关。
  - 其余项本就跨度无关：`Dmax` 用相对回撤%、`Tfreq` 用每日交易数、`S` 用夏普。
- **为什么**：你要"得分与时间跨度无关"，核心就是把"总量型"指标换成"每笔/比率/平均型"指标。

- **自测**：去注释/字符串后括号平衡相对原文件**零净变化**；**无法在此编译 MQL5，请在 MetaEditor 编译，有报错贴我**。
