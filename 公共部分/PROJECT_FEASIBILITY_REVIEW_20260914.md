## 3. 四个收敛的失败机制

### 3.1 ① 成本拖累（Cost drag）

```
· 零售点差实测：黄金 160–260 点 · 日元 10–11 点 · BTC 1000–1540 点
· 往返成本 $0.13（日元）/ $0.32（黄金）/ $0.31（BTC）@0.01 手
· ★JSB30：2× 成本压力后【三个变体一律转负】
· ★日元网格：7/7 窗口"加交易"都低于"不做交易"
→ 在 0.01 手地板下，点差占每笔风险的比例被放大；
  提高频率以摊薄固定成本，反而放大了总成本。
```

### 3.2 ② 最小手地板（Minimum-lot floor）

```
· 500 USD + 0.01 手最小 + 1.0×ATR 止损 → 单笔实际风险常超出 1.5% 预算
· JSB30 实测：rej_risk = 104 / 251 / 562（V1/V2/V3）→ 拒单率 9%–53%
· 匹配 500 USD 的"理想手数"常低于 0.01 → 只能被拒或被迫超配
→ ★这是【资金规模与合约规格的不匹配】，不是策略问题；
  任何在此规模下的策略都会受同一约束。
```

### 3.3 ③ 尾部依赖（Tail dependence）

```
· 黄金：前 10 大单占 R 的 87–165%
· BTC C1：前 10 大单占净利 110.8%（train）/ 232.1%（valid）
· ★MR30 换了结构（固定收益上限）后仍为负
  → 说明在 BTC 上"尾单依赖"不是某策略的结构缺陷，而是【品种/资金规模】属性
```

### 3.4 ④ 结构性负期望（Structural negative expectancy）★最致命

```
★JSB30 V1 的完整解剖（1143 笔、6.4 年、成交跨度 99.8%）：
   胜率      36.9%（422/1143）
   平均盈利  +4.66 USD
   平均亏损  −3.25 USD
   实际盈亏比 1.43
   期望      = 0.369 × 1.43 − 0.631 × 1.00 = −0.10 R/笔

★设计意图是 TP = 1.5R（即需要胜率 > 40% 才保本），
  但【实际盈亏比只有 1.43】（达不到设计值），
  而突破类结构的胜率只有 36.9% ⇒ 期望为负。

★MR30 / JSB30 的 PF 分别是 0.73–0.87 / 0.73–0.84，
  三个变体各自一致 ⇒ 这是结构性的，不是参数噪声。
```

## 5. 核心问题：在当前约束下，"继续换简单规则 family"还有依据吗？

```
约束：
  · 500 USD 账户
  · 1:200 杠杆
  · 真实零售点差（日元 10–11 点 / 黄金 160–260 点 / BTC 1000–1540 点）
  · 0.01 最小手
  · 禁止使用 exposed_oos 与 user_holdout
```

**我的判断：依据已不足以支持继续"同类别"迭代。理由：**

```
① 【7 个族已覆盖单标的的日线与日内价格行为】
   趋势 / 均值回归 / 网格 / 时段突破 × H1/D1/M5/M30
   → 剩下未覆盖的只是"同样信息、不同参数"的排列，而不是新信息。

② 【失败模式收敛，不是分散】
   7 个族全部落在同一组机制（成本 / 地板 / 尾部 / 结构性负期望）。
   若机制相同，换 family 只是换一个方式撞同一面墙。

③ 【资金规模约束是硬的，且已被量化】
   0.01 手地板 + 1.5% 预算 → 理想手数常 < 0.01 → 拒单率最高到 53%。
   这不是策略能解决的，是【账户规模 vs 合约规格】的算术问题。

④ 【成本/收益比在日内频率上不成立】
   日元点差 10–11 点，而 M30 的 TP 若为 0.8R（R=1.0×ATR），
   点差占 TP 的比例在某些时段可达 4–9%；2× 成本压力即全面转负。

⑤ 【元方法层面也被否证】
   "用验证段挑参数"相对随机对照 p=0.063 → 优化流程本身未提供增益。
```

**★结论：继续"换简单规则 family"缺乏实验依据。
若继续，应当改变的是【问题设定】或【方法类别】，而不是规则组合。**

## 6. 下一层研究方向（最多 3 个，只做设计）

### 方向 A：把"资金/最小手约束"从常数改为研究对象（敏感性研究）

```
问题：当前所有失败都混合了两个因素 —— 策略无 edge vs 资金规模过小。
      两者从未被分离。

设计：
  · 不改变策略，只在【模拟】中扫不同 deposit（500 / 1,000 / 2,000 / 5,000 USD）
  · 观察同一策略的 DD、拒单率、PF 如何随资金变化
  · ★关键判据：若 PF 在更大资金下显著改善 → 约束在资金；
    若 PF 不改善 → 约束在策略
  · 该研究不需要新 family，只需要重跑已冻结的 EA

价值：一次性回答"是策略不行还是钱太少"，这是本项目最欠的一个答案。
代价：低（EA 已冻结、可复现、无新结构）
风险：不产生可交付策略，只产生结论
```

### 方向 B：从"规则策略"转向"统计 / ML 信号"

```
问题：7 个规则族都失败，可能说明人工设计的条件组合不是合适的信息表达方式。

设计：
  · 不做端到端 ML 交易（易过拟合、不可复核）
  · 只做【信号显著性检验】：用统计方法检验"哪些条件组合与未来收益有稳定相关"
  · 输入必须是可复核的（价格、波动率、时段、跨品种关系）
  · 必须保留同一套样本外纪律（train/valid/exposed_oos/user_holdout）
  · ★先做纯离线研究（不跑 MT5），只有当信号通过显著性检验才考虑落地为 EA

价值：把"找策略"变成"检验假设"，更接近科学的做法
代价：中高（需要新的分析方法与更严格的过拟合控制）
风险：很可能结论是"在这些特征上没有稳定信号"
```

### 方向 C：正式接受"当前约束下 no-deliverable"结论并固化

```
问题：本项目已投入 8,000+ 次回测。继续投入的期望收益是否为正？

设计：
  · 不新增实验
  · 把已完成的全部负面结果整理为【可引用的结论集】：
    哪些结构在哪些标的上被否证、失败机制是什么、约束边界在哪里
  · 明确写下"在 500 USD / 1:200 / 零售点差 / 0.01 手 / 禁用留白的约束下，
    简单规则型策略未能在三个标的上产生可交付正期望"
  · ★并给出【可交付的正面产出】：方法论纪律清单（本项目已积累 12 条方法纪律
    + 2 条元纪律 + 若干工程纪律），这些是跨项目可复用的

价值：把一个负面项目转化为可复用的知识资产，避免沉没成本继续扩大
代价：极低
风险：无（但也不再产生策略）
```

## 7. 我的建议（按优先级）

```
1. ★先做【方向 A】（资金敏感性）—— 代价最低、信息量最大，
   它能一次性区分"策略问题"与"资金问题"，是后续任何决定的前提。

2. 若 A 显示约束在资金 → 再讨论是否需要更小合约规格的标的，
   或调整可接受的资金规模。

3. 若 A 显示约束在策略 → 再考虑【方向 B】（统计信号检验），
   而不是继续换规则 family。

4. 【方向 C】应作为并行的"止损线"：无论 A/B 结果如何，
   本项目的负面结论与方法论产出都应固化并交付，不应因继续研究而丢失。

★★ 但以上都需要 GPT/用户裁定。我不自行启动任何新的 MT5 运行。
```
