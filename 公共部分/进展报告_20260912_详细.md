## 2. ★★ 实测硬知识（13 条，可直接复用，全部有实测证据）

### 2.1 `Sleep(InpLatencyMs)` 在 MT5 策略测试器里是**空操作**
- **机制**：测试器价格由 tick 驱动；`Sleep` 期间**不产生新 tick、价格不变** → "Sleep 后重读价"读到同一个价
- **证据**：A/B（同窗口同参数、只改 `InpLatencyMs` 0 vs 300）→ **144/144 pass 逐位完全相同**
- **后果**：任何"用 `Sleep` 实现 N 毫秒延迟"的回测，**那个延迟从未存在**

### 2.2 ★ `Model=2` 的真实 tick 密度：**1 根 M1 = 1 个 tick = 60 秒**
- **实测**（只测量不交易的探针 EA）：`ticks_total = 30,246`、`m1_buckets = 30,246` → `ticks_per_M1 = 1.000`
- `gap_hist` 显示 99.8% 落在 [60, 300) 秒；**日历平均 83 秒是含周末缺口的假象**
- **后果**：
  - **`300ms` = 0.005 tick → 在 `Model=2` 里完全无法表示**
  - **tick 级"延迟"模拟的是"行情推进一根 K 线"，不是网络延迟** → 建议改称 **"次根 K 线成交（next-bar open）"**
  - **全项目只有两个可选口径：「0 tick」与「1 tick（60 秒）」**；而 **0 tick 相对真实 300ms 只差 0.3 秒，是更忠实的近似**

### 2.3 MT5 优化模式的语义（**极易踩坑**）
```
Optimization=1 → 完整算法（穷举笛卡尔积，pass 数 == 声明组合数）★要这个
Optimization=2 → 快速遗传算法（GA）—— pass 数远小于组合数，且会收敛到局部
```
**实测事故**：误用 `=2` → 6 个网格只跑出 **8.9%** 的组合（1764 → 157 pass），GA 收敛到坏区域 → **全部 0 盈利**，浪费约 2 小时机时。

### 2.4 `.set` 文件的三条硬规则
```
① 位置必须是  MQL5\Profiles\Tester\<EA名>.set   （UTF-16LE）
② ini 用 Optimization=1 且【完全不写 [TesterInputs]】→ MT5 自动加载同名 .set
   （把 .set 路径塞进 [TesterInputs] → 优化空跑退出、0 agent）
③ ★MT5 跑完会把 <EA>.set【回写成"最后使用的参数"】
   → 若所有网格共用一个 EA 名，下一个网格读到的是上一个的残留
   → 修复：每个网格复制出一份唯一 EA 名（如 opt_<grid_id>.ex5）
```

### 2.5 `ENUM_TIMEFRAMES` 在 `.set` 里会被写成**符号名**
- 未被优化时 MT5 写回 `InpTF=PERIOD_M5`，测试器还原成数字**不可靠** → 变成 `0 = PERIOD_CURRENT`
- 在 M1 图表上就是 M1 → 触发 EA 守卫 → **静默 0 成交，而测试器报告"pass 成功"**
- **实测事故**：342 个 pass 里 **276 个是静默 0 成交**
- **修法**：改用纯 int 参数（如 `InpTFMinutes`），或把枚举写进 `fixed` 且**写数字**（`16385`=H1）

### 2.6 ★ 参数"基底"会静默注入
```python
# 编排器的典型行为（这是教训，不是推荐写法）
merged = dict(BASE)                       # 先套基线
merged.update(params)                     # 请求覆盖基线
fixed["InpLatencyMs"] = "0"               # 再无条件覆盖
if "InpLatencyTicks" not in fixed:
    fixed["InpLatencyTicks"] = "1"        # ★没写就默认 1 → 静默改变口径
```
**后果**：两个 run「看起来参数相同」却结果不同 → 我们曾因此**误判"测试器有随机性"**，实际是隐藏参数差异。
**纪律**：**两个 run 结果不同时，先穷举所有 input（含基线注入的）逐项比对，再谈环境/随机性。`Model=2` 没有随机源。**

### 2.7 审计文件的三个坑

```
   → entry=0（实测占比 98.1%）

② 优化模式【不写审计文件】（所有 opt_* 网格从未产出任何 CSV）

③ MT5 HTML 报告的【千位分隔符是空格】："1 620.86" → 会被解析成 1 和 620.86
```

### 2.8 `risk_money` 的正确语义（已自洽性验证）
```
源码： g_riskMoney = stopDist * MoneyPerPriceUnit(lot);   // lot = 最终成交手数
自洽检验： risk_money ≈ |pnl|（止损单在止损处平仓）
→ 它是【真实美元风险】，是正确的 R 分母（不是"风险预算"）
注意： SYMBOL_TRADE_TICK_VALUE 在 tester 里会漂移 → 用合约规格比手算
```

### 2.9 ★★ 最小手地板是"两向畸变器"（**本项目最根本的发现**）

**算术**（BTC valid 段 ATR≈430、SL=1.5×ATR → 每 1 手风险 ≈ $645）：
```
理想手数 = 本金 × RiskPct% ÷ (SL_ATR × ATR)

入金  300 → 理想手数 0.0070 < 0.01 → ★走【最小手超配分支】
            实际风险 = 0.01 × 645 = $6.45 = 账户 2.15%/笔（相对被【压低】）
入金 1000 → 理想手数 0.0233 > 0.01 → 走【正常分支】→ 1.5%/笔
入金 3000 → 理想手数 0.0698 > 0.01 → 走【正常分支】
```

**决定性证据**（入金固定 300、**只改 cap** → 最干净的变量分离）：
```
valid 段 cap 轴：
cap 2.0  → +101.61   PF 2.11
cap 2.4  → +153.80   PF 1.85
cap 2.5  → +130.16   PF 1.64
cap 3.0  →  +85.75   PF 1.32
cap 6.0  →  −84.12   PF 0.85   ← 转负
cap 100  → −161.31   PF 0.76   ← 更负
→ ★完美单调：cap 越大（拒单越少）→ 越差，直到转负
```
**→ 那一段的"正收益"来自"最小手地板恰好把仓位压得极小"这一畸变，不是 edge。**

**★更根本的推论**：
```
$300 账户 + 0.01 手最小手 → 手数长期贴地板
→ InpRiskPct / InpMinLotMaxRiskPct / InpSL_ATR 全部退化成【开关】而非【旋钮】
→ 提高本金虽恢复旋钮性质，但会暴露"某些段本来就没有 edge"
```

**★"波动尺度匹配准则"（可直接用于筛选标的）**：
```
匹配本金 ≈ (0.01 手在止损处的风险) ÷ 1.5%
BTC  ATR≈430 (2025-26) → ≈$287  |  2024 ATR≈545 → ≈$363  |  2018 ATR≈40 → ≈$27
GOLD 0.01手风险 ≈ $9.94          → ≈$660

→ ★0.01 手这个【不可再分的地板】，在不同波动 regime 下对应完全不同的美元风险
→ 在 300 账户上它使仓位参数在"贴地板"与"被 cap 拒单"两个极端间跳变，【中间没有可用区】
→ 这是三条线（黄金/日元/BTC）共同的约束，不是某个品种特有
```

### 2.10 ★★ 回测偏差的方向（**不要把它们说成"偏保守"**）
```
【无 bar 内价格路径】        乐观  ← 1 tick = 1 分钟，看不见分钟内的一切
【无滑点模型】              乐观  ← InpSlippagePoints 只是报价容忍度，不是滑点模型
【点差按快照固定】           乐观  ← 一律 10 点；干预时段真实点差会拉开数倍
【专家侧市价平仓超冲】        乐观  ← 实测：目标 200 点，中位实际 218、平均捕获高 35%
【延迟口径（若用 1 tick）】   悲观  ← 60 秒 vs 真实 300ms
→ 净偏差仍是【乐观】的
```

### 2.11 ★ "择时脆弱度" —— 一个值得推广的指标
```
点估计     = 0 tick 口径
择时脆弱度 = (0tick − 1tick) / |0tick|
实测：BTC 某配置 5.8% · JPY 某配置 38% · 某 M5 空间 0%（对延迟不敏感但是负期望）
→ 结论："对延迟不敏感"与"有正期望"是【两个独立维度】，不该用前者当后者的代理指标
```

### 2.12 参数被布尔门控 = 结构性死参数（而非"无影响"）
```cpp
// dsh_BtcSwing.mq5
L619: if(InpUseEntryQuality)                     // ★总开关
L623:    if(barRange < InpMinBarRangeATR * atr) { return 0; }
L627:    bool upStrong = (posInBar >= InpMinClosePosFrac);   // 也在这个 if 内
```
**→ 当 `InpUseEntryQuality=false`（基线）时，`InpMinBarRangeATR` 与 `InpMinClosePosFrac`【从未被读取】。**
**→ 25 组网格里这两个轴造成的差异 = 0，是**必然**的，不是"参数无影响"。**
**★定性纪律：「参数被门控」≠「参数无影响」** —— 前者结构性（换基线即生效），后者条件性（换窗口可能生效），**两者导致完全不同的设计决策。**

### 2.13 交易网格 EA 的特有陷阱
- **专家侧市价平仓会在 Model=2 下大幅超冲**（见 2.10 第四条）→ 目标 200 点实际中位 218 点
- **`BasketStopPct=0`（不止损）意味着观察到的 DD【不是上限，只是那条路径恰好走到的位置】**：
  同结构在 P2 达 55.17%、P1 36.37%、P4 32.63% —— P4 停在 32.63% 不是因为有什么机制挡住了它
- **层数与 PF 严格单调下降**：`PF 1.618(1层) → 1.417 → 1.273 → 0.572(4层)`，4 层时 **5/5 把 $300 打光**
- **`1 层 = 根本没有网格`**（只是单仓 + 止盈）—— **它却是最好的一档**

## 3. ★★★ 结构性诊断：本项目真正的瓶颈可能是「资金约束」

**由 §2.9 的地板算术推出**：
```
0.01 手是不可再分的最小单位 → 其美元风险 = 0.01 × contract × 止损距离
→ 在不同波动 regime 下这个美元风险【完全不同】（BTC 2018 年 ATR≈40 vs 2024 年 ATR≈545，差 13.6 倍）
→ 在 $300 账户上，它使仓位参数只能在"贴地板"与"被 cap 拒单"两个极端间跳变
→ 【中间没有可用区】
```

**实测印证**：比特币线把本金从 300 提到 1000/3000 后：
```
train 段 DD: 50.85% → 36.85%（cap3.0, 入金1000）→ 23.93%（cap2.5, 入金3000）
test  段 DD: 50.86% → 26.11%（入金1000）→ 26.02%（入金3000）
→ ★本金提高修好了 DD
```
**★但它同时暴露了 valid 段无 edge**：
```
三段兼容形态（btc-187/177/188）在入金 1000 下重跑：
train  +359.77 → +3147.11  ✅ 大幅改善
valid  + 85.75 →  −25.99   ❌ ★转负
test   + 75.69 → +166.93   ✅ 改善
→ "三段全正"【仅在"入金300 + 地板畸变"下成立】
```

**→ 结论**：**这不是策略问题，而是「标的波动尺度 vs 账户规模」的匹配问题。**
**→ 可行动作**：用 §2.9 的匹配本金准则重选标的/本金（**纯算术，零回测**）。

### 4.3 比特币（BTCUSDm）—— ✅ 已收官 · 299 次 · 32 份报告

- **但最终结论是**：
> **`BTCUSDm` 上的「唐奇安突破 + D1 EMA200 regime + Chandelier」形态，在 300 美元本金下无法同时满足「三段为正 + DD≤40% + 覆盖≥90% + 频率≥50笔/年」。根本原因不是参数没调好，而是【300 美元账户相对 BTC 的波动尺度太小】，0.01 手最小手地板把所有权参数退化成"开关"；而把本金提到足以恢复"旋钮"性质（≥1000）后，验证段暴露为负。**
- **它的四个选项（交回用户）**：
  ```
  ① 收窄交付范围（train+test 两段四门槛齐备，明确声明 valid 不成立）
  ② 接受"入金300 + 地板畸变"作前提（须写明"正收益依赖地板压仓，非 edge"）
  ③ 放弃该形态
  ④ ★换资金/换标的（它建议优先）
  → ★它明确【不建议 ②】："我不建议把畸变当能力交付。"
  ```
- **已验证的正面结果（train + test 两段四门槛齐备）**：
  ```
  train btc-284 (入金1000/cap3.0): +3147.11  PF 1.28  94笔/年   DD 36.85%  ✅✅✅✅
  train btc-277 (入金1000/cap2.5): +4407.02  PF 1.46  86笔/年   DD 23.76%  ✅✅✅✅
  test  btc-283 (入金1000/cap3.0):  +166.93  PF 1.15 107笔/年   DD 26.11%  ✅✅✅✅
  → 唯一缺口是 valid
  ```
- **它拒绝的两种"解法"（立场）**：
  ```
  ① 按时间段切参数 —— train/valid/test 是人为时段、非可观测 regime → 用未来信息
  ② 按 ATR 分位切换 —— train 的 ATR P10=$45，test/valid 的 P10 都是 $300+
     → 两个样本外段不含低波动区制 → 规则永远不会被触发 → 【不可检验】
     → "我不提交无法证伪的规则。"
  ```

### 4.4 滚动优化（方法论，BTC）—— ✅ 已否证方法 · 4,176 pass · 5 份
- 产出拼接 OOS 曲线 `+89.41`（9 个月、68 笔/年）
- **但随机选参对照否证了它**：
  ```
  【该方法】三窗口合计 +81.26
  【随机分布】中位 +17.19  σ=40.68  95% +85.79  最大 +149.07
  ★ P(随机 >= 该方法) = 0.063 → 未达显著
  ```
- **验证段选参与测试段的 Spearman ρ：3/5 接近 0 或为负**
- **"漂移完胜锁定"也被撤回**（"锁定一套参数"统计上就等于"随机抽一次"）
- **它自己撤回了"验证段加长会改善"的建议**：`Spearman(验证段笔数, ρ) = +0.000`（零支持）
- **新假设（H2）**：**测试段（靶子）本身是噪声** —— 最差窗口的测试段平均只有 **1.4 笔**

### 4.5 日元滚动 · 网格（用户新授权方向）—— 🔄 收官在即 · 1,700+ 次 · 8 份

  ```
  ② 方向对照:  只做空 −300.20 / DD 100.07%（同期 USDJPY 上行）

  ```
- **7 个独立窗口，7/7「加交易」都低于同口径的「不做交易」**（收益/回撤）
- **一个比策略更重要的数字**：`0.01 手买入持有 USDJPY 三年` = `+104.41 / DD 36.37% / 年化 11.61%`
- **杠杆映射表**（要把每个窗口都推到年化 30%，需要的杠杆对应这样的 DD）：
  ```
  w16 需 42.12× → DD 1355%   |  P2 需 6.35× → DD 350%
  P1  需  2.59× → DD   94%   |  P3 需 1.81× → DD  57%
  w20 需  1.16× → DD   27% ✅ |  P4 需 0.88× → DD  21% ✅
  → 达标 2/8
  ```
  **→ 「年化 30% + 回撤 ≤40%」在 USDJPY 上不是"策略能不能做到"，而是"你能不能预知自己处在顺风窗口"**
- **反直觉事实**：8 个窗口里买入持有 **7 个都是正的**（USDJPY 2014–2026 整体上行），年化从 0.71% 到 33.92%（**47 倍**）—— **问题不是"赚不赚"，是"赚多少完全由窗口决定"**

## 5. ★★★ 十二条方法纪律（**本文最有价值的部分**）

> 这些全部来自**被实测否证的假设**，每一条都对应一次真实的错误。

```
1. 凡按【美元金额】排序/加权的统计，必须先确认【仓位是否随时间变化】
   （否则"前 N 大单"必然偏向测试后段 —— 因为仓位随净值增长）

2. 凡"整段成立"的结论，【必须做分段检验】
   （实测：某段 +80R 拆成两半后是 −61.6R 与 +5.0R）

3. 复现自检必须【逐项抄权威运行记录】（run_<tag>.ini 的 [TesterInputs]），
   【不能凭记忆重建配置】（多次参数错配、26% 数值差异，根因都是这个）

4. 在同一函数内新增逻辑前，必须【完整读该函数的分支/返回链】，
   确认没有既有同类门禁
   （实测：新增的 regime 切换被已有的两条门禁完全覆盖 → 100% 冗余）

5. 出现【异常高/好的 PF、Sharpe 或相关系数】时，先算三件事再下结论：
   ① 笔数是否达标 ② 前5大单占净利比 ③ 最大单笔盈亏 R
   （实测：PF 2.81 的配置只有 24 笔、前5大单占 123%）

6. 调整"按账户百分比"的参数时，必须检查【同量纲参数的耦合】
   （InpRiskPct / InpDailyLossPct / InpMaxDDPct / InpMinLotMaxRiskPct）
   快速判据：先算「日损上限 ÷ 单笔美元风险」，< 3 说明日损闸门会成为主约束

7. 当"提高参数值"导致"交易数下降"时，优先怀疑【手数/风险闸门】，而非日损/回撤闸门
   快速判据：比较各档的 vol 中位与单笔 |pnl| 中位 —— 若不随参数变化，
   则该参数没改变实际风险，笔数下降必来自"拒单"

8. ★ 机制推断必须用【逐笔数据】验算，不能用汇总数字猜测
   （trades.csv 是唯一可信的机制证据来源）

9. ★ 当数据点呈"分簇/阶跃"时，先按【所有可能的分类变量】（段/品种/年份/参数档）分层，
   确认簇不是分层的副产品                    【归属：比特币线自纠】

10. ★ 写判定规则时，必须【逐条列出全部门槛并逐条校验】，
    不能只写最容易满足的那几条               【归属：比特币线自纠】

11. ★ 【流程教训】不要凭记忆或片段重建配置/机制，先读权威记录
    （run_<tag>.ini 的 [TesterInputs] 是每个 run 实际喂给 MT5 的输入）
    （实测：某线 22 次自我更正里，至少 6 次根因是同一个坏习惯）

12. ★ 【流程教训】用自动化搜索前，先问清"优化模式是穷举还是遗传算法"
    （实测：误用 GA 导致 6 个网格只跑 8.9%、全部 0 盈利，浪费约 2 小时机时）
```

### 5.1 两条"元纪律"（关于如何看数字，**最重要**）
```
A. 报告中每个"惊人数字"必须标注它是【分布统计量】还是【单次抽样】；
   后者不得作为方法有效性的证据。
   · 分布统计量（ρ、命中率、方差分解、多档扫描）→ 换口径后方向和量级应稳定
   · 单次抽样（某一次选参的 OOS 值、"第 k 名的成绩"）→ 换口径就能翻转
   实测：某"随机 94.1% 优于它"在换口径后翻转成 11.5% —— 因为那只是一个 n=1 的抽样

B. 任何正收益，先设计两个同口径的【控制组】，再谈 edge：
   ① 「不做交易」（买入持有）
   ② 「方向反做」（只做空）
   实测：这两个控制直接否证了整条网格线
```

### 5.2 一条"纪律的纪律"
```
当多个参数"零影响"时，优先检查【门控/开关关系】，再怀疑传递链：
  ① 读源码确认是否被布尔门控
  ② 用极端值做单点探测（如把振幅门槛设成 5×ATR）
  ③ 只有①②都排除后才怀疑通道 bug
```

## 6. 已确认"有用"的工程做法

| 做法 | 效果 |
|---|---|
| **MT5 原生优化并行**（`Optimization=1`） | **28 agent 满负载**；25 组参数 = 29.6 秒（对比逐条串行 ~3.8 tests/min，**快约 13 倍**） |
| **每网格唯一 EA 名**（`opt_<grid_id>.ex5`） | 隔离 `.set` 回写覆盖 |
| **`bases` 目录用 NTFS 联接共享** | N 个 worker 省 N×1.6 GB |
| **目录联接 + 凭据克隆** | 多实例可行（但**注意：MT5 terminal 对同一数据目录是单实例**；`/portable` + 独立数据目录才能多开） |
| **容量约束预检**（静态检查） | 提交前拦住"参数名不存在 / `opt` 起点为 0 / 档数 ≤1"三类必失败请求 |
| **回填时标注"实际 pass < 声明组合数"** | 立刻发现 GA / 配置错误 |
| **可复现的复现锚点**（固定 PF/笔数/DD 三个数） | **实测抓到了"EA 重编译导致数据不连续"** —— 本项目最有用的一个自检设计 |
| **只测量不交易的探针 EA** | 用 8.8 KB 的 EA 定案了"1 tick = 60 秒"这个全项目口径缺口 |
