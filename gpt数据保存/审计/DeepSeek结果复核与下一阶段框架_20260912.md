## 1. 本轮结论

目前仍没有一条可以按“约 500 USD、真实 Exness 品种、三段独立检验、可承受回撤”交付的策略。DeepSeek 这一轮最有价值的产出是实验纪律和失败机制，而不是某个高收益参数。

最重要的判断有三个：

1. **不要再把不同本金、不同 EA、不同延迟口径的结果拼成一个候选。** DeepSeek 主线大量使用 300 USD，用户目标约 500 USD；这足以改变最小手数闸门和成交样本。
2. **BTC 的“最接近交付”形态不能交付。** 原始 outbox 中 `btc-282…287` 的结果确实存在，但 300 USD 的正收益依赖 0.01 手地板；提高到 1000 USD 后验证段转负。它说明了资金/最小手约束，不是稳健 edge。
3. **USDJPY 不能仅凭现有回测排除或推荐。** 测试器曾出现约 143 倍的跨货币盈亏异常；在 `OrderCalcProfit`、成交报告和独立换算没有三方一致前，任何 JPY 收益结论都只能是线索。

## 3. 必须先解决的口径冲突

### 3.1 300ms 与 1 tick 不是同一件事

公共详细报告和 DeepSeek 代码审计一致指出：`Model=2` 大约每根 M1 只有一个合成 tick，1 tick 约等于 60 秒；`Sleep(InpLatencyMs=300)` 不推进测试器模拟时间。因此：

- `InpLatencyMs=300` 不是已模拟的 300ms；
- `InpLatencyTicks=1` 也不是 300ms，而是“晚一个合成 tick/近似下一根 K 线”的压力口径；
- `dsh_TrendCore` 仍主要使用 `Sleep`，不能把它的结果写成 300ms 延迟结果；
- 后续报告应同时给出 **0 tick 基线** 与 **1 tick（次根 K 线）压力**，明确标注两者，不再使用“真实 300ms 已模拟”的措辞。

### 3.2 审计行目前不能支撑完整归因

`dsh_BtcSwing.mq5` 的 `RecordExitDeal()` 虽已补上 `OnTradeTransaction`，但当前写入的 `entry` 是 `0.0`，`risk_money`/ATR 依赖全局状态（源码约 398–402 行）。这会阻断持仓时长、止损距离、点差占比和逐笔 R 的可靠计算。必须先按 `DEAL_POSITION_ID` 反查开仓腿，并为每个 position 保存独立状态；部分平仓/`OUT_BY` 也要拆分核对。

### 3.3 研究与用户约束不一致

- DeepSeek 新线大量使用 300/600/1000/3000 USD；用户目标仍是约 500 USD。下一轮必须把 500 USD 设为主口径，其他本金只能做“资金尺度诊断”。
- 公共文档里同时出现“保守 DD≤20%”和“用户已放宽到 40%”。后续报告应同时列 **首选门槛 DD≤20%** 与 **探索上限 DD≤40%**，不能静默切换。
- `2026-06-01～2026-09-30` 留白必须继续保护；不能因为 DeepSeek 把它称作唯一真样本外，就提前消耗。
- DeepSeek 旧 `MEMORY.md`、`接力说明.md` 仍保留自建品种/Model=1 的历史说法；以当前真实符号、Model=2 的最新详细报告为工作口径，但旧说法不能被当作当前结论。

## 4. 我建议的下一阶段框架

### 阶段 0：证据闸门（先做，不耗回测机时）

为每个已有结果建立一条 canonical manifest，至少包含：

`run_id / symbol / deposit / model / from / to / all inputs / source SHA256 / EX5 SHA256 / report path+SHA256 / audit path+SHA256 / first-trade / last-trade / actual trade count / latency label / status`。

内部日期晚于当前时间、报告声明与 outbox 不一致、或只有“分析文字”没有原始文件的记录，统一标为 `lead_only`，不参与候选排名。

### 阶段 1：先修执行与审计，再比较信号

1. 统一一个交易核心：手数向下取整、取整后用 `OrderCalcProfit`/合约规格复核、超预算拒单。
2. 修 `dsh_BtcSwing` 的入场腿反查、position 状态和异步成交映射；把 `entry=0`、全局风险状态、重复 `OUT_BY` 处理写成单元测试。
3. 给 TrendCore/MeanRev 明确的延迟模式：`0tick` 基线与 `1tick` 压力，不再伪称 300ms。
4. 对 USDJPY 做固定价格差的四方对账：独立公式、`OrderCalcProfit`、MT5 deal/report、审计 CSV。未四方一致前，JPY 不进入收益排名。

### 阶段 2：冻结研究协议

主口径固定为真实 `XAUUSDm/BTCUSDm/USDJPYm`、入金 500 USD、Model=2、真实服务器历史；时间段固定为训练至 2024-05-31、验证 2024-06-01～2025-05-31、测试 2025-06-01～2026-05-31，留白完全不触碰。

每个新假设最多预注册 3 个结构变体，并必须有：

- 不交易控制组；
- 方向反做控制组；
- 固定 0.01 手与风险比例两种口径；
- 0 tick 与 1 tick 压力；
- 实际成交跨度、频率、权益 DD、浮动 DD、恢复时间、连续亏损；
- 按 R 的前 5/10 大单占比、去尾结果和 block-bootstrap/Monte Carlo 区间；
- 点差/滑点压力，不把 `deviation` 参数误当作滑点模型。

### 阶段 3：策略路线选择

1. **黄金网格/旧 eva 混合体不再作为主线。** 现有证据显示网格毛边际被往返点差和灾难单吃掉；黄金新趋势线又有严重收益集中，只有在留白结束后才能做一次固定参数前向检验。
2. **BTC 不再做同一 EA 的无止境调参。** 先用固定信号参数做“500 USD 地板诊断”；若单一参数不能在三段同时过门槛，就关闭该形态，转向全新的机制假设，而不是继续扫 cap/确认根数。
3. **JPY 只做 P&L 环境修复，不做参数搜索。** 若对账后测试器仍不可信，保留为待验证品种；若对账通过，再从一个极简、无加仓的基线重新开始。
4. **只有在单品种 edge 通过后才做组合。** 组合层采用中央风险预算，三个 EA 不得各自按总权益独立放大风险；相关性、同时持仓和总止损必须统一计算。
5. **账户/最小手数是一级设计变量。** 若用户能使用 Cent 账户或更细的最小手数，优先重做风险尺度实验；若只能标准账户 0.01 手，则必须接受“500 USD 下有些参数只能是开关”的事实，不能用高风险放大去制造 50% 年化。

### 阶段 4：留白后的前向验证与 demo

在 2026-10-01 之后，用户先独立测试 2026-06～09；AI 只能对预先冻结的配置做一次读取和复盘，不能据此调参。只有三段历史、成本压力、审计、风险对账全部通过，才进入至少两周 demo 前向；真钱继续禁止。

## 5. 交付判定（建议）

候选要同时满足：真实 symbol；入金 500 主口径；三段净利方向一致；年化交易数达到项目暂定门槛（≥50/年）；首选权益 DD≤20%，探索上限不超过 40%；成本压力后 PF 仍>1；不是单一尾部事件支撑；参数邻域不是针尖；审计与 P&L 四方一致。只通过 DD≤40% 而不通过 DD≤20% 的结果，必须标为“探索候选”，不能直接交付。

## 6. 结语

下一步最有价值的动作是**整理证据和修正测量口径**，不是再跑数百个参数。当前数据已经足够说明：在标准账户、约 500 USD、0.01 手地板下，年化 50%～100% 不能当作已实现目标；任何达到它的结果都要先证明不是最小手畸变、收益集中、延迟误标或跨货币盈亏错误。
