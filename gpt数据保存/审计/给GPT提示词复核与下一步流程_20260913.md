## 2. 对提示词 Q1–Q5 的明确回答

### Q1：`TRADE_COUNT_MISMATCH` 是否可以判为“不阻断”？

不能接受提示词中的原判定措辞。可以暂时不把它作为“所有历史文件全部作废”的全局阻断，但必须将它标成 `audit_reconcile_required`，任何受影响 run 不得进入候选排名或逐笔统计。

直接证据：

- `provenance_inventory.csv` 共 400 行同时有 MT5 笔数和审计行数，其中 202 行不等；
- 202 行中 80 行绝对差大于 5，17 行绝对差大于 20；
- 最大差为 `BT_btc-117`：`362` 对 `592`，比值约 `0.611`；
- 比值小于 `0.95` 的有 47 行，小于 `0.98` 的有 174 行；
- 中位数约 `0.962` 只能说明中心位置，不能证明尾部或逐笔归因正确。

可能存在“MT5 持仓笔数 vs 审计 deal 行数”的口径差，但必须用 `position_id`、`DEAL_ENTRY`、部分平仓和 `OUT_BY` 做映射后才能确认。旧记录没有这些字段时只能 `lead_only`。`S1CHK2` 的 99=99 是新审计格式的局部证据，不能 retroactively 修复旧的 202 行。

### Q2：P1 `partial_pass` 是否允许推进？

允许推进 **P2 的独立测量工作**，不允许推进正式策略比较、冻结 C1 或运行测试集。

进入候选比较前必须完成 BTC 线 P1-R2：

1. 对当前源码重新编译，封存实际使用的 `.mq5` 和 `.ex5` SHA-256；
2. 逐笔保存 `raw_lot/final_lot/final_risk/reject_reason`，并明确 `InpAllowMinLotOvershoot`；
3. 将 `profit`、`commission`、`swap` 分列，同时保留净 P&L；
4. 用夹具测试覆盖最小手、向下取整、超预算拒单、部分平仓、重复 deal、日损和 DD kill；
5. 重新跑一个固定 500 USD、真实 `BTCUSDm` 的验收区间，检查 HTML、deal、audit、signals 四者；
6. 其他 EA 尚未同步修复时，明确标记“BTC scope pass”，不能宣称全项目 P1 完成。

### Q3：C1 保持 H1，另建 M30 C2 是否正确？

正确，不应为了迎合文字把 C1 改成 M30。C1 和 C2 必须是不同预注册结构、分别统计、不得合并排名。

但要修正命名：C2 只是把 `InpTF` 改为 M30、仍保留 D1 EMA 过滤，并不是最初提议的完整“ M30 EMA 趋势方向”策略。它应标作“ M30 周期诊断变体”，且因验证失败已经关闭。若以后研究真正的 M30 EMA 结构，必须另建新的 family/run，不得重开 C2。

### Q4：C1 应先补门槛、解释入金扫描，还是直接跑测试？

顺序必须是：

1. **先修 P0 v2 和 P1-R2 的 provenance/审计链；**

4. 对入金扫描只做解释性分析，不再扩大参数/入金网格：报告信号是否相同、接受/拒绝比例、lot 分布、实际风险%、R 结果和 DD kill 次数。净美元随 Deposit 非单调并不等于 edge 消失，因为风险比例、最小手取整和拒单改变了交易路径；

## 3. 必须更正的证据问题

### 3.1 P0 的“519 条结果”和状态统计不准确

`stage0_provenance.py` 以 `req_id/grid_id` 全局 `seen`，只保留首次记录。实际 outbox 有约 3780 条记录，网格同一 ID 包含多个 pass；因此 519 应写成“519 个唯一请求/网格 ID”。至少 37 个 ID 的首条与末条状态不同，其中包括 error→done 的重试；同一 tag 的报告和配置可能已被后续 pass 覆盖。

需要重新生成 `provenance_inventory_v2.csv`，每个实际 run/pass 使用复合唯一键（建议 `req_id + tag + pass/config_hash`），不能用首次 outbox 行代表最终产物。若首末记录、配置、报告无法一一对应，状态只能 `lead_only`。

### 3.2 `RUN_ERROR` 被错误标成 verified

现有分类规则没有把 `RUN_ERROR` 纳入 `lead_only` 条件；68 个 RUN_ERROR 中有 13 个被标成 verified。至少这些 run 必须改为 `lead_only`，并保留 retry lineage。没有净利/报告的失败 run 不得进入任何统计分母。

### 3.3 未知字段不是“无违规”

有 24 行 symbol、deposit、model、日期等字段为空，并且带 `NO_INI/NO_AUDIT_FILE/RUN_ERROR`。它们只能是 `provenance_unknown/lead_only`，不能支撑“全部真实品种、全部 Model=2、未触碰留白”的全局表述。

### 3.4 留白检查函数需要检查区间重叠

当前 `touches_holdout()` 只检查起点或终点是否落在留白；正确条件应是：

```text
from_date <= 2026-09-30 AND to_date >= 2026-06-01
```

同时扫描配置、报告、outbox 和交接 Markdown。当前 `交接\比特币\报告_032.md` 明确写有 `2026-09-14T09:00:00+08:00`，而当前日期为 2026-09-13；这至少使该报告 `lead_only`，所以不能宣称全局“报告未来日期=0”。这不等同于证明它使用了留白数据，但 provenance 必须先修正。
