# 量化交易 AI 改进

多 AI 协作的量化策略研究记录。**本仓库只保存研究过程、结论与方法论 —— 不包含行情数据与逐笔交易数据。**

---

## 这是什么

一个由多个 AI 代理协作完成的量化策略研究项目。项目采用「**执行代理 + 研究代理**」分工：

| 角色 | 职责 |
|---|---|
| **执行代理（DeepSeek）** | 只负责跑 MT5 回测、编译 EA、修工具、回填结果；**不做策略判断** |
| **研究代理（多个子代理）** | 负责策略设计、结果分析、假设检验；**不看代码，只看数据** |
| **主审（GPT）** | 独立复核执行结果、裁定方法学争议、发布执行协议 |
| **用户** | 最终决策者；设定硬约束与目标 |

**核心设计**：执行与研究分离，且**每个 AI 的结论都必须能被另一个 AI 用文件路径与哈希独立复核**。

## 研究结果（诚实结论）

**约 8,000+ 次回测、70+ 份报告之后：目前没有一条线产出可交付策略。**

| 线 | 状态 | 核心结论 |
|---|---|---|
| **黄金 XAUUSDm** | 已结项 | 四项硬约束全部满足，但**前 10 大单占 R 的 87–165%**，去掉后为负 |
| **日元 USDJPYm** | 已否证 | 趋势与反转两个策略族均无正期望（298/691 达标 pass 中 PF>1 **= 0**） |
| **比特币 BTCUSDm** | 已关闭 | 三段兼容形态存在，但**去前 10 大单后 train −354.74 / valid −247.67** |
| **滚动优化（方法论）** | 已否证 | 随机对照 **p=0.063** → 「用验证段挑参数」未显著优于随机 |
| **日元滚动·网格** | 已否证 | **7/7 窗口「加交易」都低于同口径的「不做交易」** |

### 跨三条线的共同结构问题

```
黄金：  前 10 大单占 R 的 87–165%
比特币：前 10 大单占净利 110.8% / 232.1%
日元：  唯一 PF>1 靠 5.41 年 16 笔噪声
→ 【趋势跟随类策略在小账户（$300–500）上，盈利由极少数大单承担】
```

## 本项目最有价值的产出：方法论

**结果全部为负面，但方法论层面的产出比策略更有价值。**

### 1. 十二条方法纪律（每条都对应一次被实测否证的真实错误）

```
 1. 凡按【美元金额】排序/加权的统计，必须先确认【仓位是否随时间变化】
 2. 凡「整段成立」的结论，【必须做分段检验】
 3. 复现自检必须【逐项抄权威运行记录】，不能凭记忆重建配置
 4. 在同一函数内新增逻辑前，必须【完整读该函数的分支/返回链】
 5. 出现异常高/好的 PF、Sharpe 或相关系数时，先算：笔数 / 前5大单占比 / 最大单笔 R
 6. 调整「按账户百分比」的参数时，必须检查【同量纲参数的耦合】
 7. 「提高参数值」导致「交易数下降」时，优先怀疑【手数/风险闸门】
 8. 机制推断必须用【逐笔数据】验算，不能用汇总数字猜测
 9. 数据呈「分簇/阶跃」时，先按【所有分类变量】分层
10. 写判定规则时，必须【逐条列出全部门槛并逐条校验】
11. 【流程】不要凭记忆重建配置，先读权威记录
12. 【流程】用自动化搜索前，先问清「优化模式是穷举还是遗传算法」
```

### 2. 两条「元纪律」

```
A. 报告中每个「惊人数字」必须标注是【分布统计量】还是【单次抽样】；
   后者不得作为方法有效性的证据
   （实测：某「随机 94.1% 优于它」换口径后翻转成 11.5%）

B. 任何正收益，先设计两个同口径的【控制组】再谈 edge：
   ①「不做交易」（买入持有） ②「方向反做」（只做空）
   （实测：这两个控制直接否证了整条网格线）
```

### 3. 一个可复用的工程纪律（本项目最新提炼）

```
审计去重标记必须放在【确认写入成功的路径】上，不能在函数入口标记 ——
否则任何提前 return 都造成「标记了但没写」的永久漏记，
而且漏记方向【不随机】（实测只丢止损单 → 审计净利虚高 57%）。
```

## 关于可复现性

本仓库的每份报告都遵循同一规范：

```
· 引用路径 + SHA-256（源码 / EX5 / INI / 报告 / 审计）
· 明确口径：symbol / from-to / dataset_role / deposit / Model / ticks / 完整 inputs
· 双轴状态分离：
    run_verification  = 执行链是否完整（execution_verified / invalid）
    strategy_stage    = 策略是否稳健（exploratory / deliverable_candidate /
                        acceptable_candidate / blocked_failed）
· 「执行链通过」不等于「策略验证通过」—— 这条在本项目被反复强调
```

**唯一的真样本外数据（2026-06-01 ~ 2026-09-30）自始至终未被 AI 使用**，保留给用户自行验证。
