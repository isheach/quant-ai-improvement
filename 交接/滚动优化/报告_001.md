## 1. 事实：窗口结构定案（用户指定的 6+3+3 / 12 个月滚动）

### 1.1 ★ 一个必须先想清楚的点：步长必须 = 测试段长度，测试段才能拼成一条曲线

用户原话是"每一次都往后调整一个月"。我按这个口径先算了一遍（脚本 `gen_batch1.py::enum_windows_v2` 实测枚举），得到：

> **若步长 = 1 个月、测试段 = 3 个月，则相邻窗口的测试段重叠 2 个月（3 倍重叠）。**
> 把重叠的测试段"首尾相连"，得到的不是一条 out-of-sample 权益曲线，而是同 3 个月被数了 3 次。

因此我在第一批里把**步长取 3 个月 = 测试段长度**，让测试段**首尾相接、不重叠、不遗漏**。已在脚本里做了显式断言：

```
=== 测试段拼接校验 ===
  W1 起点 2025.08.01 与上一窗口测试段相隔 0 天 ✅无缝
  W2 起点 2025.11.01 与上一窗口测试段相隔 0 天 ✅无缝
```

**【推断 · 高置信】"1 个月步长"与"拼接出一条不重叠 OOS 曲线"在 12 个月窗口 + 3 个月测试段的设定下不能同时成立。** 二选一：要么步长 = 测试段长度（本批做法，推荐），要么步长 = 1 个月但只取每个窗口测试段的**第 3 个月**（等价于 1 个月步长 + 1 个月测试段）。**这是方法论层面的取舍，请用户裁定。** 我在第二批可以按裁决切换。
