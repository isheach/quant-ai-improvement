## 2. ★设计依据：为什么这样设网格（不是拍脑袋）

### 2.1 `InpSL_ATR` 我压到 **0.25–1.25**，而不是模板建议的 1.0–3.0

依据是我自己的硬结论（保留在案）：
```
H1 的 ATR ≈ 1.4 × M30 的 ATR
0.01 手黄金单笔风险($) = InpSL_ATR × ATR(H1) × 1
在 300 账户上守 ≤1% ⇒ InpSL_ATR × ATR(H1) ≤ $3
```
实测锚点：2024-05 金价 2342 时 ATR(M30)=4.524 → ATR(H1)≈6.3
→ `2.0 × 6.3 = $12.6` = 300 的 **4.2%** ❌ ；`0.25 × 6.3 = $1.58` = **0.53%** ✅
→ **所以模板默认的 `SL_ATR=1.5~3.0` 在 300 账户上会被 `InpMinLotMaxRiskPct` 闸门大面积拒绝。
我改成 0.25–1.25，让网格落在"闸门能放行"的区域。**

**代价我也记录**：止损越小，点差占比越高（`REJECT-spread` 门槛 30%）。
`SL_ATR=0.25` 时止损距离约 $1.6，历史实测点差 $0.32–0.52 → **占 20–33%，已临界**。
→ **网格里同时有 `SL_ATR=1.25` 档，就是为了看"放宽止损换取更低点差占比"是否更划算。**

### 2.2 我**先关掉** `InpUseVolNormalize`（grid-001/002/003），再单独开（grid-004）

因为"是否归一化"本身是要测的变量。若混在一个网格里，无法归因。
grid-004 与 grid-001 **同窗口、同其余参数**，唯一差别是 `InpUseVolNormalize=true` + 扫 `VolNormMin/Max`
→ **可直接对照"归一化是否真的解开我发现的『金价越高→闸门越窄』病症"**（看笔数与 DD 变化）。

## 4. ★滚动优化：我的方案设计（你要的核心产出）

### 4.1 方案（严格按用户定义：6 训练 / 3 验证 / 3 测试，每次滑 1 个月）

```
第 k 个窗口（k=0,1,2,...）：
  训练  T0+k月  ~  T0+k月+6月       ← 选参（优化跑这里）
  验证  +6月    ~  +9月             ← 在训练胜出者中挑（不再拟合）
  测试  +9月    ~  +12月            ← 只测一次，记录
  然后 k += 1（滑 1 个月）
```
**每个窗口的产出**：该窗口 OOS 测试段的 net/PF/笔数/**期望R**/DD
**拼接后**：一条**完全样本外**的 10 年权益曲线 + 一条**参数漂移轨迹**。

### 4.2 判定标准（预先锁定，防事后选择）

| 问题 | 判据 | 含义 |
|---|---|---|
| 参数是**平滑游走**还是**随机跳变**？ | 相邻窗口最优参数的**游走幅度 / 该参数的网格步长的比值**；若比值 ≈ 均匀随机抽样的期望 → **噪声** | 平滑游走 = 真 regime 漂移，可跟随；随机跳变 = 网格在拟合噪声，**滚动优化无效** |
| 参数漂移方向是否**与金价/ATR 同向**？ | 与金价做秩相关 | 若 `SL_ATR` 随金价**单调下降**，则证明"量纲漂移"是真的、且**可被规则化跟随**（这是最有价值的可能结果） |
| 拼接 OOS 是否正？ | 拼接净利 > 0 且 **PF ≥ 1.2** 且各段胜率不塌 | 若拼接 PF ≈ 1.0 → **与固定参数的 0.99–1.01 无区别 → 滚动优化在黄金上不成立** |

**★我的先验（诚实说明）**：我**倾向认为滚动优化也救不了黄金**，理由是无锁 10,254 笔已收敛到 PF 1.00。
但你的论点（单一参数跨 3 倍价格区间本身荒谬）**在逻辑上成立且我此前确实没测过**，
而"参数是否随金价单调漂移"这个问题是**可证伪的**，值得用数据回答。**这正是我同意复工的原因。**
