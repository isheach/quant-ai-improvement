### 1.2 ★更严重的问题：**测试段的"窗口覆盖"只有 40%**

`btc-139`（测试段）**全部 37 笔成交的首末日期是 2025.06.02 → 2025.10.27**：

```
末笔 = 2025.10.27    窗口末 = 2026.05.31    →  空窗 215 天（0.59 年）
```

**逐月笔数（btc-139 只做多）**：2025.06 = 11 笔、07 = 7、08 = 5、09 = 9、10 = 5，**2025.11 起 = 0 笔**。

**对照 btc-134（双向、同参数、仅 `InpAllowShort` 不同）逐月**：
`06=11, 07=7, 08=5, 09=9, 10=5, **11=2, 12=5, 2026.01=9, 02=8, 03=8, 04=6, 05=4**` —— **全窗口都在交易。**

→ **结论：回填里的"测试段 +96.91 / PF 1.65 / 年化 32.41%"实际只覆盖测试窗口的前 40%（2025.06–10）。**
→ 这 5 个月恰是 BTC 从 ~105k 涨到 ~120k 的**上涨段**；而 2025.11–2026.02 那段 **~90k→~70k 的暴跌，该配置一笔未做**。
→ **`年化 32.41%` 是用 12 个月窗口名目算出来的，但收益只来自 5 个月 → 该年化数字失真，不能作为交付依据。**

## 2. 推断（标明强度）

**【推断 · 高置信｜核心机制】斜率闸门既"修复"了 2026 的失效，也"冻结"了整段下跌行情。**
这是同一枚硬币：D1 EMA200 的斜率一旦转负并长期为负，**"只做多 + 要求斜率>0"就变成了全面停牌**。
- 好处：**它确实躲过了 2025.11–2026.02 的暴跌**（那正是 btc-106 曾 17 连亏的地方）；
- 代价：**它同时也放弃了暴跌之后的所有反弹**，并且让策略在 215 天里完全不下单。

→ **所以我此前"修复成功"的表述需要收紧**：修复的**真实机制是"不去参与"**，而不是"在下跌市里赚钱"。
**这不是一个能交付的持续交易系统**——它更像一个"只在牛市开机的开关"。用户要的是**能持续交易**的策略（≥50 笔/年），而不是一年里有 7 个月关机的系统。

**【推断 · 高置信】双向形态（btc-134）才是当前唯一"覆盖完整"的形态。**
它全窗口 12 个月都在交易（79.2 笔/年），测试段 PF 1.27 / DD 22.87%。
→ **交付候选应优先考虑双向形态并把频率/期望值同时做上去**，而不是把"只做多"当答案。

**【推断 · 中置信】1-tick 代价被正确标定为 −5.76%，我接受该更正。**
`btc-134`(1 tick) vs `btc-140`(0 tick)：net 98.09 vs 104.08 = **−5.76%**，笔数 77→76 = −1.3%；
`btc-141`(5 tick) = 71.58 → **0 > 1 > 5 单调恶化**。
→ 总调度早先给的 −33% 是**别的配置、别的窗口**（valid 全段、`InpSL_ATR=1.5` 单跑）。**我在报告_010 §4 坚持"不可套用"是对的，实测证实。**
→ **实测换算系数 ≈ 0.94**：我此前全部 0-tick 结果 ×0.94 ≈ 对应的 1-tick 净值。**这个系数可用于量级换算，但不改变任何排序结论。**

**【推断 · 中置信】"仅入场质量闸门"路线在 1-tick 下被证伪。**
`btc-135`（仅质量闸门，test）**−78.17 / PF 0.66**，而其 0-tick 版本 `btc-115` 是 **+108.82 / PF 1.48** → **从正翻负**。
→ 而"斜率+质量"（btc-134/139）在 1-tick 下保持为正。
→ **说明斜率闸门是必需的，质量闸门单独不够。** 我此前（报告_008 §2.3）把质量闸门当作"更干净的形态"，**这个判断在 1-tick 下不成立，我更正。**

## 5. 判定规则（回填前写好）

1. **新增硬性前置条件——"窗口覆盖率"**：任何候选必须满足 **成交跨度 ≥ 窗口的 90%**，否则标 `REJECT-coverage`。
   → 这是本次教训的直接产物：**名目年化不能建立在 40% 覆盖上。**
   （btc-139 覆盖率 40% → `REJECT-coverage`，即使它净利为正。）
2. **频率门槛 ≥50 笔/年**，且**三段都要满足**（btc-137/139 未达，已标记）。

4. **优先交付形态：双向**（btc-134 类），因为它是唯一全窗口活跃的形态；除非只做多形态能同时满足 §5.1–5.3。
5. 报告必须给出**七件套 + 覆盖率 + 回撤事件（次数/每次深度/恢复时间）**。
