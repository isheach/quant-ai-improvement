## 2. ★★单一 `cap` 三段解 —— **可判定为无解（空集）**

**用你的实测数据，三段各自的约束是**：
```
test : 需 cap ≥ 2.5   （cap2.2=49.0 差1笔；cap2.5=74.0 达标）
valid: 需 cap ≥ 2.6   （cap2.5=49.0 差1笔；cap2.6=51.0 达标）
train: 需 cap ≤ 1.8   （cap1.8=33.30% DD 达标；cap2.0=45.32% 超限）
```
**→ 可行区间 = [2.6, +∞) ∩ (-∞, 1.8] = ∅ → 单一 cap 无解。**

**★★并且这个"无解"是结构性的，不是采样不足**：因为
- **`cap` 同时承担两个互相冲突的职责**：①**放行更多信号（提频率）** ②**限制单笔美元损失（压 DD）**；
- 两个样本外段（各 1 年）**信号稀少 → 需要更宽松的 cap 才有足够笔数**；
- 训练段（6.31 年）**信号充足 → 频率早已达标，cap 越高 DD 越大**。
**→ 两者由同一参数承担，所以"单一参数解"必然不存在。**

## 3. ★我发现的**未试杠杆**（这是本批的核心）

**重读源码（L37-38, L293-296）确认 `InpMinLotMaxRiskPct` 的语义**：
```
L38  input double InpMinLotMaxRiskPct = 3.0;   // 风险硬上限（占净值%），超过放弃信号
L293 if(!InpAllowMinLotOvershoot) return 0.0;
L294 if(riskPctActual > InpMinLotMaxRiskPct) return 0.0;
L296 if(riskPctActual > InpMinLotMaxRiskPct) return 0.0;
```
**→ 它是"单笔最大损失的硬上限（占净值%）"，即源码里唯一直接限制"单笔能亏多少美元"的闸门。**

**★关键经济关系（我验算过）**：
```
理想手数 = 净值 × InpRiskPct% ÷ 止损距离      ← 与 cap 无关
cap 则限制：单笔损失 ≤ 净值 × cap%
```
**→ 所以"频率"由【理想手数是否落在可用区间】决定，"DD"由【单笔损失上限 × 连亏笔数】决定 —— 但两者目前都由 `cap` 一个数控制。**

**→ 我此前 22 批一直在做的事，本质是"用同一个旋钮同时调两个互相冲突的目标"。**
**→ 这也解释了为什么"收锁 / 收日损 / 降 RiskPct / 缩短冷却"全都低效**：它们都没触及这个耦合。
