## 2. 推断（标明强度）

**【推断 · 高置信】btc-048 是"高风险低效率"配置，不是"好配置"。**
年化对照：btc-035 = 6.42%、btc-042 = 58.65%、btc-048 = 151.36%。
但 **btc-042 只用 4.3% 净值的单笔风险就拿到 58.65% 年化**，而 **btc-048 用了约 2.47%（均值口径，起始时 8.7%）换 151%**。
按「每单位风险的收益」算，**btc-042 明显优于 btc-048**。btc-048 的 151% 是用 46.95% 回撤换来的，而 btc-042 的回撤是 65.18%（也高，但它的绝对风险敞口小得多）。
→ **结论：不该围绕 btc-048 做"压回撤"，而应该把 btc-042/035 这一族放大到合适的风险预算。** 这直接决定了批量3 的重心。

**【推断 · 高置信】edge 极薄（0.203R/笔），这是测试段失败的根因候选。**
0.203R 的期望值意味着：**只要有 2–3 个百分点的胜率漂移，期望值就归零**。测试段 93 笔、PF 0.81 完全落在这种漂移的正常范围内——它未必证明"策略失效"，但证明**这个 edge 没有厚到能跨 regime 存活**。
→ **唯一可信的改进方向是抬高期望 R**，而抬高的办法只有两个：提高胜率，或拉长右尾（平均赢 3.20R → 5R+）。批量3 的 btc-056（胜率侧）与 btc-053/054/055（右尾侧）就是这两条路。

**【推断 · 中置信】原「EMA 交叉退场把赢家钉死在 1R」的假设被数据修正。**
trend_exit 实际是 **+1.53R**（不是 1R）。所以右尾并非完全被截断，但 1.53R 确实偏小——这解释了为什么我仍要测跟踪止盈，但**不能指望它带来数量级改善**。btc-052（固定止盈 1.5R）就是用来直接判定"1.5R 附近到底还有没有更多空间"的否证实验。

**【推断 · 中置信】回撤 46.95% 的主因是风险预算而非策略质量。**
dd_events 显示 `recovered=593, avg_depth=1.6%, over20=7, over25=5, over30=3, worst=42.49%`。即**日常回撤很浅（1.6%），但有 7 次超过 20% 的深坑**。这种"浅日常 + 偶发深坑"是薄 edge 在趋势策略上的典型形态。
→ btc-065（把基础风险 1.5% → 0.6%）直接检验"风险-收益近似线性"是否成立。**若成立，年化应落到约 50–60%、回撤约 20%**，正好命中用户 50–100% 目标。**这是本批价值最高的一条。**

## 3. 新 EA：`dsh_BtcSwing.mq5`（比特币线自研 v1）

**文件**：`D:\desktop\新量化策略\deepseek数据保存\mql5\dshtools\dsh_BtcSwing.mq5`
**建议注册名**：`btcswing`（→ `"expert":"btcswing"`）

### 3.1 为什么写新 EA
四个针对性缺陷（全部来自上面**实测**的 R 画像，不是猜测）：
1. **右尾偏短**（平均赢仅 3.20R）→ 用 **Chandelier 宽跟踪止盈**（默认 3.5×ATR）取代 EMA 交叉退场。
2. **无 regime 过滤**（2021/2022/2024 是亏损年）→ 用 **D1 EMA50 宏观趋势过滤**，只做与宏观同向的突破。
3. **×ATR 尺度不稳定**（BTC 的 M5 ATR 在 2018/2019 相差 2.5 倍；M30 更长）→ **波动率归一化仓位**：按 `ATR14 / ATR14(240根前)` 反向缩放风险，系数限幅 0.6–1.8。
4. **信号只用唐奇安突破**（去掉 EMA 趋势判定的双重条件），并把**持仓时长交给跟踪止盈**，避免"单仓制下持仓过久压制入场机会"。

### 3.2 关键实现要点（供你审阅编译）
- **K线聚合照抄已验证的安全做法**：只用 M1 序列 + `CopyRates(_Symbol, PERIOD_M1, ...)` 自行合成大周期 bar（沿用 `dsh_TrendCore` 的 `TFMinutes` 安全写法，含 H1=16385 的 switch）。
- **手数**：`AlignLot` **严格向下取整到 `SYMBOL_VOLUME_STEP`**（不用四舍五入，避开已知坑 #2），取整后按最终手数**重算实际风险**并复核 `InpMinLotMaxRiskPct` 硬上限。使用 `SYMBOL_TRADE_CONTRACT_SIZE` 的合约口径算钱，**不依赖 `SYMBOL_TRADE_TICK_VALUE`**（避开已知坑 #1）。
- **审计 CSV 路径与 TrendCore 一致**：`Common\Files\dshtrend\<InpRunTag>\trades.csv`，表头与列序**完全同构**（`run_tag,symbol,time,dir,entry,exit,vol,pnl,risk_money,atr_at_entry,exit_reason`），因此**你现有的 dd_events / monthly 分析脚本可直接复用**。
- **DD 冷却锁**：实现为 `InpDDCooldownMin`（默认 1440，`=0` 为永久锁），与你给 TrendCore 打的补丁语义一致。
- **入场评估**：按 `TimeCurrent()` 的 `InpTF` 时间桶判断新根（这样 `InpTF` 短于图表周期时也准确）。

## 5. 事前验收规则（不变，不放宽）

1. **覆盖率**：成交跨度 / 6.315 年；< 6.0 年标 `REJECT-truncated`，净利/年化不作排序依据。
2. **频率窗口**：`100 ≤ 笔/年 ≤ 2000`；低于 `REJECT-lowfreq`，高于 `REJECT-churn`。
3. **点差占比**：`0.10 ÷ 止损距离` > 30% 标 `REJECT-spread`。
4. **持仓门槛**：按用户新指令，中位持仓 **< 5 分钟**标 `REJECT-scalp`。（btc-048 中位 2610 分钟，全批无风险。）

6. 回撤事件：次数/深度/恢复时间齐全；检查"最后成交日距段末 > 1 年"的静止。
