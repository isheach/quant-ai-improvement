### 1.4 ★`jpyg-028` 与 `jpyg-033` 逐位相同 —— 说明延迟差异**没有生效**

```
jpyg-028  pass=36  trades[65~2514]  PF[0.528~0.959]  maxNet=-1.38
jpyg-033  pass=36  trades[65~2514]  PF[0.528~0.959]  maxNet=-1.38
```
两者**完全一致**，而 `jpyg-033` 的 `fixed` 里写的是 `"InpLatencyMs":"0"`。

**两种可能（我无法区分，两种都值得你知道）**：
- **（a）延迟确实无影响** —— 那么 `InpLatencyMs=300` 在这套数据上是个**空操作**，它保护的"300ms 延迟"从未真正施加。
- **（b）`fixed` 里的 `InpLatencyMs=0` 没被传进 `.set`**，两条网格实际都跑 300ms（或都跑 0）。

**我倾向于需要你查一下**：`opt_jpyg-033.set` 里 `InpLatencyMs` 那一行写的是 `0` 还是 `300`。
**这条重要，因为规范 §五.4 把 `InpLatencyMs=300` 列为硬约束，而如果它实际是空操作，那么三条线所有"已模拟延迟"的声明都需要重新表述。**

### 1.5 我此前一处判断被本批数据修正

`报告_004` §4.4 我说"真正的主旋钮是周期（TF）"。本批显示：**周期仍是主导（M15 优于 M5），但在同一周期内 `InpExitFrac` / `InpMaxER` / `InpAdverseATR` 都无法把 PF 推过 1.0。**
→ **不是"哪个旋钮没调对"，而是"这个信号结构本身在 JPY 上没有正期望"。**

## 2. ★正式结论（对应 I-21 的预声明）

**依据**：691 个 pass / 2 个独立策略族 / 5.41 年窗口 / 版本已哈希对齐。

1. **`dsh_TrendCore`（趋势突破）在 JPY 上无正期望** —— 训练段唯一正期望是 `jpy-007`（PF 1.18），但**任何把频率推向门槛的尝试都使 PF 掉到 0.6–0.9**。
2. **`dsh_JPYRev`（我自研的区间反转）在 JPY 上同样无正期望** —— 291 个新 pass 里 **`net > 0` 的数量 = 0**，最高 PF 0.974。
3. **"频率"与"正期望"在 JPY 上不可兼得**，而且这不是"没找到"：**边界已被量化**（§1.2 表）。要 PF 接近 1，就必须把频率压到 ≤25 笔/年；一旦到 ≥50 笔/年，PF 上限是 0.859。
4. **用户的"低频=拟合"警告方向是对的，但结论要反着读**：JPY 上**低频的 PF 1.18/1.20 才是被样本量撑不住的假象**（16 笔/5.41 年 = 赚 1.33 美元），**而高频不是拟合，是噪声被放大**。两边都不可交付。

**→ 我建议停止在 JPY 上调参。** 继续扫描只会产出更多 PF 0.9x 的 pass，不会改变结论。
