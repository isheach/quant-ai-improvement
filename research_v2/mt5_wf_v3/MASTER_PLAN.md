# WF3：MT5 原生品种、月度滚动调参与缓慢自适应总计划

版本：WF3.0 · 2026-09-25

性质：根据用户本轮新要求重新建立的研究协议与分阶段实施计划；不是已有盈利证明。规划依据分支 `repair/xamr30-v1-daily-r1`，审核基线 `492e15c1b847f32d2d7295f08a9647ec386c3dd4`。旧源码、旧运行和旧失败证据保留，不改写。

**唯一新方向：黄金单标的；趋势和受限网格先独立；所有用于选参数、排名或评价盈利的收益必须来自 MT5 Strategy Tester。Python 只做编排、解析、统计和检查，不再生成交易收益曲线。**

本计划的具体参数是事前研究设计，不是已验证最优参数。当前执行提示词只放行 S0 建设与最多两个有边界的工程 smoke；S1 及以后需完成 S0 后一次明确开工批准，不因读到完整路线图就自动全跑。

## 1. 先把旧结果放回正确位置

旧 15 组 Python 回放存在已登记的会计与执行缺陷，保留为问题证据，不作为参数优劣依据。R20/R21 等快速筛选与旧 MT5 EA 不是天然同一策略。最新 R23 报告明确使用 `XAUUSD_HIST` 自定义品种、导入 M1 和简化执行条件；报告正收益不等于原生品种核验通过，更不等于实盘盈利。

本轮不宣称旧盈利全部为假，也不宣称已经找到可靠盈利策略。统一四种结果身份：

- `ENGINEERING_ONLY`：工程测试，不谈策略盈利。
- `MT5_BACKTEST_PROVISIONAL`：确实由 MT5 原生品种运行，但数据、成本或对账尚有未闭合项。
- `MT5_RESEARCH_EVIDENCE_VERIFIED`：身份、成本、行情模式、成交与净值证据闭合的历史模拟，仍不是实盘。
- `LIVE/PAPER_FORWARD`：另有真实或模拟前向记录，不能由历史回测冒充。本阶段只研究历史，不实盘。

旧结果永远保留原 run_id；新策略、新引擎模式、新数据版本使用新身份，不覆盖结果以制造改善。

## 2. 两个阶段，两个问题

### 阶段一：每月重新选参数，验证这种更新方法是否有效

在同一个标的上分别研究 T 趋势、G 受限网格。每轮以前 6 个月训练、后 3 个月验证、再后 3 个月测试，起点每次移动 1 个月。每月从一个小而固定的候选集合选配置；没有合格配置就 Cash。先不叠加成交频率反馈、方向盈亏反馈、网格间距反馈。

### 阶段二：月度基准上叠加缓慢自适应

只有阶段一有可复核依据后，研究一个小的更新步长，让网格间距或趋势入场严格度缓慢变化。更新只使用当时已知信息；修改只作用于未来新仓，不扩大已有仓风险。验证的是更新规则，不是寻找一张事后最优参数时间表。

**趋势、网格是并列研究对象；趋势未通过不自动否决网格，也不强迫网格成为收益主力。**

## 3. 用户新授权的数据范围与诚实的样本标签

本轮用户明确指定的开发与滚动评价范围：`2024-01-01 <= t < 2026-07-01`，共 30 个月，不是完整 36 个月。

这一新范围对 WF3 有效：允许在批准的 WF3 任务中使用原来被禁止的部分历史区间，包括 2026 年 6 月。它不追溯改变旧协议下的违规或暴露记录，也不重新授权旧 XAMR30/旧 calendar 探针。

`2026-07-01` 及之后的行情不纳入 WF3 历史开发；不自动读取 2026 年 7—9 月留白。原测试区间很多已被历史实验使用，全部写 `historically_exposed / retrospective_walk_forward`，不能称“完全空白留出”。新一轮真正前向只能在协议与参数冻结后，另行批准未来观察期。

指标预热只使用决策时已有的过去 bar，不下单、不计收益、不选参。第一轮优先在 2024 年内完成预热；如必须使用此前价格，仅允许已有 2023 年第四季度数据用于最多 500 根所需周期 bar 的指标初始化，单独登记。不得借预热增加训练样本或访问未来。

MT5 可能同步区间之外的底层缓存；缓存存在不是研究使用证明。EA 与分析程序必须限制消费区间，禁止策略读取未来价格或 Python 全量分析受保护缓存。所有比较使用明确的 UTC/服务器时间映射，不沿用未经核实的 DST 假设。

## 4. MT5 成为唯一收益生成引擎

### 4.1 固定基础

真实券商品种 `XAUUSDm`；核查 `SYMBOL_CUSTOM=false`。禁止 `XAUUSD_HIST`、CustomSymbol、CSV 回灌或自建品种。券商、服务器、合约规格和交易成本必须记录，不自动换账户或服务器。初始模拟资金 500 USD、杠杆 1:200；不能通过改变本金或杠杆掩盖策略问题。

第一批直接使用 `Model=4`（Every tick based on real ticks），避免筛选与评价偷偷换引擎。若真实 tick 缺失或混入生成 tick，报告覆盖和缺失，不能仅凭配置为 4 或 History Quality 百分比声称全程真实 tick。无法核实会阻止最终结论，不自动改用 Python。

将来确有性能瓶颈时，可另行批准 MT5 `Model=0` 的模拟 tick 或 `Model=1` 的分钟 OHLC 筛选；同一批选参必须使用相同模式，最终锁定候选仍要原生品种验证。当前未授权这种降级。`Model=2` 是仅开盘价，本计划不用它判定网格、止损或追踪退出的盈利。

### 4.2 Python 可以做什么

生成窗口表与 INI；逐项调用 MT5；读取报告、成交、费用和权益；依据固定规则挑选已由 MT5 跑出的候选；生成下月参数表；计算统计、哈希与图表。不能运行自写 P&L 回放来排名参数，也不能拼接一条看似 MT5 的 Python 模拟收益曲线。

所有执行入口共用 run 身份与锁。禁止绕过正式 runner 直接调用另一套历史模拟脚本。

### 4.3 盈利证据的最低要求

每次保存：source/EX5/deployed EX5/完整 inputs/INI 哈希、原生 symbol 与规格、请求及实际日期、Model 与 tick 质量、MT5 原始报告、订单和成交、逐笔费用、每日含浮盈亏权益、决策及拒单日志。原始报告可本地保留，Git 提交清洗后的机器结果、完整必要 ledger、哈希和报告定位；不能只上传一段盈利摘要。

买入开仓 Ask、卖出平仓 Bid；卖空开仓 Bid、买回 Ask，实际价格以 MT5 成交为准。`net = profit + swap + commission + fee`，按平台各项有符号值汇总，手续费入场/出场不遗漏。OCP 初始风险用实际入场到初始 SL，而非实际平仓利润作分母。官方权益 DD 与 Python 复算分开标注。

日志成功或退出码 0 只是进程证据。必须验证报告确为本次、完整输入一致、交易数对账、净利对账、无悬空仓位/订单、无越界成交。unknown 不能被模板填成 PASS。

### 5.1 两张成绩单，不混算

A. 三个月固定参数测试：检验该月选出的参数保持三个月的表现。窗口重叠，19 个三个月结果不能加起来当 57 个月收益，也不是 19 个独立统计样本。

B. 月度部署主账户：每轮只提供其测试第一月的参数，按时间串行执行。完整覆盖 `2024-10-01 <= t < 2026-07-01` 的 21 个唯一月份。用一个 MT5 EA 读取事先生成的参数日程完成连续回放，余额、风险状态和高水位不每月重置为 500。最终净收益与 DD 来自这个 MT5 连续账户。

已有仓位带着入场时参数继续管理；月初新参数只管新仓。旧仓未结束不叠加冲突专家。不可把每个月独立初始化的收益率假装成连续真实账户。

### 5.2 防止重叠测试泄漏

测试结果不进入该月候选选择、阈值更新或人工修改。参数选择函数只接收截至部署月之前已完成的训练/验证结果。先完成所有批准窗口的月度参数日程与哈希，再运行/公开相应三个月诊断，避免先看到未来再“改下一个月”。

以前测试过的某个月，随着时间推进进入后续训练/验证属于合法时间前移；但程序只能使用新决策时已经发生的部分，不能借完整旧测试报告读到未来两个月。

重复同参数、同数据的确定性回测不是新的独立验证。工程复现、费用压力和下一时间窗口是不同任务，分开记 run_id 与目的。测试差就保留差结果，不能在同一测试段继续找参数直到变好。

## 6. 每月怎么选参数：不是只追最高收益

每个家族初始只 8 个候选（见第 8/9 节），风险参数不搜索。禁止遗传优化和不断扩大参数范围。MT5 单独顺序执行各候选，`Optimization=0`，保证每个配置都有完整证据；以后才考虑有完整 pass 身份的原生优化器。

### 6.1 训练六个月

先检查技术合法、无风险超配、费用完整、官方 Equity DD <=15%、净收益>0、PF>1。样本参考最低数：T 为 12 笔完整交易，G 为 30 个完整篮子；不足记 `INSUFFICIENT_SAMPLE`，不调低门槛凑数。

对满足门槛者按 `Q = return_pct - 0.5 * equity_dd_pct` 排序，两项都使用百分点。取前两名；再加入上一月配置作为 incumbent（必须本轮已跑且训练门槛合格），去重后最多三名。W01 可加入事前 anchor，规则相同。若零名，不进入验证选参，部署 Cash。

### 6.2 验证三个月

只跑训练留下的最多三名，不重新搜索。门槛相同，最低样本 T=6 笔、G=15 篮。根据同一 Q 选一名；incumbent 距最好 Q 不超过 1 个百分点时优先保留，以减少无意义换参。相同分数按低 DD、固定候选 ID 排序。若无人合格，Cash，不拿测试结果救活候选。

允许一段亏损，并不要求每一个自然月盈利；这些净利门槛针对整段训练或验证。短期样本不足时结论有限，不说明模型永久无效。

### 6.3 测试三个月

配置与 selection manifest 已冻结后，锁定一次运行。测试不选择第二名，不返工重训，不调风控。全部通过仅表示值得继续研究，不表示方法“没有问题”或保证赚钱。

### 6.4 固定参数对照

每个家族都有预先指定 anchor（不是按测试选的最好参数），在同一部署主账户区间不换参数，并共享引擎、成本、初始资金和风险限制。比较 monthly update 与 fixed anchor，再与 Cash 比较。动态组只因降低交易暴露而改善回撤时，报告收益、资金占用与交易频率，不能把减仓效果自动当成预测优势。

## 7. 从旧方案提取机制，不搬运无法解释的成绩

主要参考 `旧量化策略/36代数据/eva028_STAGE1_PACKAGE_v2/eva028_VolumetricPulseGrid_CoreRiskV1.mq5`：EMA/斜率/突破确认、独立趋势仓、移动止损、Vol-Gate 滞后、网格基线、篮子止损、日损和高水位锁、周末保护、高波网格降档。

建立 `LEGACY_MECHANISM_MAP.md`，每项记录来源函数/inputs、保留/关闭/重写原因、单位、实际触发计数。注释中的历史盈利不是证据。未开启的 ADX/EMA间距等参数不允许进入搜索，必须验证参数实际生效。

旧代码最重要的教训：混合 EA 可能只有一个模块实际成交；RV 的 ratio 与 percent 混淆可能使趋势永远不触发；固定点数不跨价格尺度；四舍五入/最小手托底会超风险；审计不能漏止损；修改日志模板不等于修好了真实执行。

WF3 在独立 EA 命名空间实现两个模块，共用交易/风控/审计适配层。旧 EA/EX5/.set 不覆盖；不会把旧 `eva028` 的 MT5 成绩当成新 Python 原型的验证。第一阶段 T 和 G 分开跑，不先组合。

## 8. 趋势方案 T：低频、明确确认、保留趋势尾部

以下为 WF3 起始研究定义，不声称与某个旧赢家完全相同。

- 方向：已收盘 H1 EMA20/EMA60 同向，慢 EMA 与三根前比较的斜率同向；H1 ADX14>=20。只用已收盘 H1，不能在 M15 时点使用尚未结束的 H1。
- 信号：M15 收盘突破此前 N 根已收盘 M15 的高/低点。首次突破时冻结触发价位，之后要求 C 根收盘持续在该价位外且方向过滤成立，不要求每根都创新高。确认失败清空 pending 状态。
- 开仓：确认后下一可交易 tick 按真实 Ask/Bid，下单前检查所有公共风险闸门；单仓，多空对称，同日最多两次 actual entry，退出后四根完整 M15 冷却。目标偏低频（月约 2—12 笔仅观察目标，不强迫开单）。
- 风险：每笔初始风险上限为当前 equity 的 1%；数量向下对齐真实 step。ATR14(M15) 初始 SL=2.0ATR，初始风险与 ATR 在成交时记录；不能因手数下限提高风险。
- 退出：盈利达到初始 1R 后开启 Chandelier 类追踪，使用已知最高 Bid/最低 Ask 与最近已收盘 ATR；SL 只能收紧。H1 方向反转确认时下一 tick 离场；最长 192 根完整 M15；周末强平规则见公共风险；不固定封顶盈利，不加仓。
- 公共成本过滤：spread/初始 SL<=0.15；过低空间不能以高频补收益。

8 个候选：N∈{30,45} × C∈{2,3} × trailing ATR multiplier∈{2.5,3.5}。Anchor=(30,2,2.5)。EMA 对、初始 SL、风险、ADX、冷却不搜索。必须记录每个候选 signal funnel，零成交时报告原因，不自动放宽所有过滤器。

## 9. 网格方案 G：频率可高，但总损失预算先锁死

- 基线：已收盘 M5 EMA60；ATR14(M5) 作为空间尺度。新篮子只在非强趋势状态开仓：H1 的趋势确认条件未成立；若 H1 强趋势出现，取消新层并按风险退出规则处理逆向篮子。
- 入场：M5 close 相对 EMA60 的偏离达到 E×ATR，方向做回归；下一 tick 下单。一时只有一个方向、一个篮子，不双向锁仓掩盖风险。
- 层数：最多两层。首层前冻结 A0、首层计划价、层距 D、共同止损及全部计划层风险。第二层不大于第一层；不马丁。第二层只在之后的可交易事件达到预设逆向层位、公共风险仍合格且至少经过一根完整 M5 时进入；不能借同一 bar 不明先后直接填满。
- 总风险：完整两层在共同止损下的预计损失和已知费用<=首层前 equity 的 1.5%。按所有计划层到共同止损的 OCP 损失合计决定数量，实际首层/加仓价格再核查。若真实最小手不满足，拒绝整个篮子，不上调为 0.01，不用拆成不可交易的 0.005 伪造分层。
- 共同初始 SL：首层实际入场价逆向 3.0A0；以后只能收紧，不能随 ATR 变大、均价变化或加仓而外移。硬篮子现金止损与订单 SL 双层保护，缺 tick/跳空仍可能超计划损失，必须报告。
- 止盈：实际加权成本价顺向 TP×A0；新计划的 TP 距离须至少为当前 spread 的三倍，不满足则拒绝而非临时扩大 TP。加仓后可按真实 VWAP 重算目标，但不能扩大止损风险。费用后的净回归收益单独对账。
- 超时：最多 96 根完整 M5（八个交易小时）；退出后冷却三根 M5。同日最多四个新篮子；篮子数、leg 数和成交数分别报告。月 10—60 个篮子仅观察目标，不以多成交奖励模型。
- 防尾部：M5 已收盘 true range 超过此前 ATR14 的三倍时停止新仓/加层并处理未平仓风险；已确认 H1 强趋势反向时离场，不等回本；日损、高水位、周末规则始终优先。

8 个候选：E∈{1.0,1.5} × D/A0∈{0.75,1.0} × TP/A0∈{0.25,0.50}。Anchor=(1.0,0.75,0.50)。两层上限、3ATR 共同止损、1.5% 篮子风险不优化。

500 USD 不可行时先报告约束。可从规格算出所需最低资金作为诊断，但不自动换本金、账户或品种。网格模块的研究不保证短期高胜率，更不保证极端行情损失被硬封顶。

## 10. 公共账户风险：不能用杠杆优化掩盖策略无效

## 12. 第二阶段：一个步长，有限、缓慢、可回退的调整

月初参数 theta_m 仍由6/3训练验证得到；月内系数 q 调整实际宽度或门槛：`effective = base(theta_m) * q`。首次只研究 lambda∈{0.02,0.05}；q∈[0.80,1.25]；最多每个真实交易日更新一次，`log(q_new)=clip(log(q_old)+lambda*s, log(0.80), log(1.25))`，s∈{-1,0,+1}。q在新月起按预注册方式重置为1，持仓仍锁定入场参数。更新规则必须先冻结，再进入对应测试。

### 12.1 网格反馈

用户的“长期不开单应缩窄、经常到第二层应加宽”作为待检验假设，不直接当铁律。

- 不开单前先区分：真无回归机会、趋势/成本禁入、风险/最小手拒单、已有仓冲突、以及仅差间距条件。前三类不能通过缩窄解决。
- 计时使用MT5实际存在的交易日及可交易时段，不用48根bar=自然日。记录eligible_time、near_entry_reject、second_layer_rate、basket_stop_rate、mean_reversion_completion等。
- 提议更新条件：过去20个真实交易日内至少10个已结束篮子、第二层率>60%且没有结构性趋势告警时，下一新篮子q上调一步；若已出现尾部告警则停止开仓，不用加宽掩盖亏损。
- 缩窄只在连续5个eligible交易日无新篮子且至少20次机会只因距离不足被拒、成本/风险/趋势均合格时下调一步；没有机会或样本不足就q不动。
- 优先级：风险停止 > 加宽 > 缩窄 > 不变。所有阈值是阶段二待批准候选，不由测试结果决定。
- 绝不移动已有篮子的SL、层位或风险分母；只对新篮子生效。成交次数不是收益目标。

### 12.2 趋势反馈

首先只研究入场确认/强度门槛系数，不同时改EMA周期、止损、trail和风险。低频策略没有足够近期样本时不适配。EMA周期需改变时，只在空仓及冷却后重建、用截至当前数据预热，整数取整滞后和上下限都预注册；不是每tick抖动一组均线。

不要用“上个留出段多头亏了”制定专门削多规则。多空反馈属于以后单独实验。

### 12.3 对照

同一月度参数日程、同一MT5引擎和风险：月度固定（lambda=0）对比只网格反馈、只趋势反馈，最后才是二者同时。参数预算与更新的内部状态、理由、样本数全部记录。更新后不一定要收益提高；研究结果可以是否定自适应。
