## 2. 事实：我在参数核对时发现三处必须先纠正的事（否则会误判）

### 2.1 ★btc-072 与 btc-079 跑的是 **0 延迟**，与其它条不可比
我从 outbox 逐条核对参数时发现：**`btc-072` 与 `btc-079` 的 params 里完全没有 `InpLatencyMs`**，而 btc-087…btc-101 全部带 `300`。
→ **这两条是 0 延迟结果，不能与 300ms 的同族条目并列比较。** 总调度把它们标为"补跑"，但补跑时未加延迟参数。**这不影响其它条，但两条数字要单独看。**

### 2.2 ★btc-094 才是真正的 PF 1.59（不是我原先以为的其它条）
`btc-094` 的参数是 `InpSL_ATR=1.5, InpTrail_ATR=5.0, InpTrailStart_ATR=2.0`（**不是**我提交时设想的"跟踪启动阈值"单独变量——它与 btc-087 的差别同时包含跟踪 3.5→5.0）。
→ 因此 **btc-094 ≠ 「启动阈值 1.0→2.0 的单因子实验」**，它是"跟踪5.0 + 启动2.0"的**两参数组合**。我在设计批次 6 时已按实际参数（而非我的设计意图）提交。

### 2.3 ★由此浮现一个强信号：`InpTrailStart_ATR` 可能比跟踪距离本身更重要
| 对比 | Trail | TrailStart | PF | 笔数 | net |
|---|---:|---:|---:|---:|---:|
| btc-072（0延迟） | 6.0 | **0.0** | 1.35 | 358 | +726.68 |
| btc-094（300ms） | 5.0 | **2.0** | **1.59** | 855 | **+8423.23** |
| btc-087（300ms，基线） | 3.5 | 1.0 | 1.25 | 847 | +3018.41 |

`TrailStart=0.0`（**开仓即启用跟踪**）比 `=2.0`（等浮盈 2R 才启用）差很多。
→ **机制解释（推断）**：`TrailStart=0` 让跟踪止损从开仓瞬间就贴着价格，**任何一次正常回踩都会把单子打掉**，等于把"跟踪止盈"退化成"超紧止损"。这与我早前在批量1 发现的"移动止损一致变差"是同一机制。
→ **这条信号比"跟踪距离谱"更强**，值得在部署形态里优先固定 `InpTrailStart_ATR ≥ 1.5`。

## 4. 推断（标明强度）

**【推断 · 高置信】右尾修正有效，但"测试段能否翻正"仍是未验证的赌注。**
PF 1.43 → 1.96 是训练段的真实提升，样本 249–855 笔，**不是噪声**。但必须点明：**这是我们第 3 次走到"训练/验证好、测试失败"的位置**（btc-048 与 btcswing 全向版都是如此）。训练段 PF 提升**不构成**测试段会通过的证据——这正是我在 §5 立刻投入 test 段的原因。

**【推断 · 高置信】只有 btc-100 的"只做多"是我有独立证据支持的改动。**
依据是三重：
1. 训练段多头 +0.53R（371 笔）vs 空头 +0.24R（300 笔）；
2. **btc-080（纯空头）实测：225 笔、PF 1.04、年化 +1.18%** —— 空头单独几乎无 edge；
3. 测试段多头 −0.20R / 空头 +0.14R（空头那 23 笔样本太小，不足以推翻 1、2）。
→ 与之相比，**bcb-094 的"跟踪5.0+启动2.0"是纯拟合参数**（训练段挑出来的），它的可信度**远低于**只做多。

**【推断 · 中置信】btc-094 的高收益伴随高风险，且它的净利结构可能同样依赖右尾。**
btc-094：net +8423、DD **48.04%**、855 笔。它在训练段净利是所有候选里最大的，但 **48% 回撤**与用户"能睡着"的要求冲突。
→ 我会在回填后**先算它的"前5大单占净利比例"**。若这个比例很高（>100%），则 btc-094 是**又一个右尾依赖型**，其训练段 +8423 不具备可重复性。

**【推断 · 中置信】`InpMaxBarsInTrade` 是死参数这件事本身是个有用的结论。**
它把"大趋势通道萎缩"这个诊断（报告_005 §3）的解释收窄了：如果放宽时限到 240/无限与 96 无差别，那么测试段 time_exit 从 22 笔掉到 2 笔**不是因为时限太紧**，而是**确实没有大趋势存活到那么久**（或更早被跟踪打掉）。
→ 这意味着 **btc-099（关时限）与 btc-094（宽跟踪）修的是不同环节**：前者放开"持仓时间"，后者放开"出场距离"。测试段的答案是哪一个，本批正好能分辨。

## 5. 跨段终验批次（8 条，`btc-102…btc-109`）

按用户新指令（过验证 + 过测试 + ≥50 笔/年 可暂时留下），我选**4 个候选**，**每个都跑 valid + test**：

| 候选 | 配置 | 训练 PF / 笔每年 / DD | 入选理由 |
|---|---|---|---|
| **btc-100** | 只做多（SL1.5） | 1.83 / 57 / 26.93% | 唯一有**三重独立证据**的改动；PF 与频率兼顾好 |
| **btc-099** | SL3.0 + 跟踪7.0 + 关时限 | 1.73 / 69 / **19.97%** | **回撤最低**，频率更宽裕；修"出场距离+持仓时间" |
| **btc-094** | 跟踪5.0 + 启动2.0 | 1.59 / **135** / 48.04% | 频率最宽裕、训练净利最大；但 DD 高，作对照 |
| **btc-096** | 唐奇安96 + 关D1 | 1.44 / **101** / 37.20% | "低频重信号"路线的代表 |

**为什么 4 个候选都直接进 test（而不是先 valid 再挑）**：
- 单次回测 20–60 秒，8 条总机时约 5 分钟，不是瓶颈。
- **更重要的理由**：在只有 1 年、约 66 笔的段上，**单条候选的"过/不过"有相当大的运气成分**。与其逐条赌，不如**一次拿到 4×2 的矩阵**，看是否存在"系统性"信号（例如：4 个候选在 test 段是否**全部**失败）。这比"挑一个最好的去 test、失败了再挑下一个"更省 test 段读取，也更能区分"策略问题"与"单条运气"。

**全部 8 条均显式带 `InpLatencyMs=300`。** 段分布：valid 4 / test 4，**未触碰留白**。
