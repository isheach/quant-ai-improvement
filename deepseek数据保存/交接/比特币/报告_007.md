## 2. ★根因：`InpUseTrendFilter` 是**水平条件**，在趋势反转时严重滞后

源码（`dsh_BtcSwing.mq5`，我本次修改前的版本，L557-561）：
```
double fema = EMAOnArray(fc, InpFilterEMA, 1);   // D1 EMA50
trendUp = (fclose > fema) ? 1 : ((fclose < fema) ? -1 : 0);
```
**判定条件只有「价格 > MA」这一个水平比较，没有斜率、没有滞后补偿。**

BTC 从 120,570 跌到 69,979 的过程中，**价格长期仍在 D1 EMA50 上方**（因为 EMA50 是过去 50 天的均值，而 120k→90k 只用了约 2 个月）→ **过滤器在整段下跌初期一直判定"趋势向上"** → 策略持续做多"下跌中的反弹" → 2026 年胜率 5.6%。

**这就是为什么 7 个候选（覆盖 SL 1.5/3.0、Trail 3.5/5.0/7.0、Start 0/1.0/2.0、时限 96/240/关、唐奇安 48/96、D1 开关、只多/全向）在测试段**全部**失败**：**它们共用同一个滞后的方向判据。** 出场参数不可能修复入场方向错误。

## 3. ★★事实：总调度的"杠杆口径"假说 —— 我用三种独立方法检验，**假说被证否**

### 3.1 方法一：PF 是比值，与仓位大小无关（解析）
`PF = 总盈利 / 总亏损`。若把**每一笔**的盈亏同乘一个常数 k（即等比放大仓位），`PF = k·W / (k·L) = W/L` —— **完全不变**。
总调度的机制描述是"训练段走 overshoot 分支、按 0.01 手固定手数 → 风险是预算的 8.2 倍"。
→ **但"每笔风险大小"是每笔共享的同一个乘数效应，它改变美元金额与回撤，不改变 PF。**
**唯一能让 PF 变化的途径是改变"每笔之间的相对风险权重"**（即不同笔用不同倍数的仓位）。

### 3.2 方法二：`risk_money` 的分母口径被搞错了
总调度用 **$36.84 ÷ $300 = 12.3%** 得出"8.2 倍"。但 `risk_money` 是**按当期净值**算的（源码 `LotForRisk` 用 `AccountInfoDouble(ACCOUNT_EQUITY)`），而训练段净值是**增长的**，不能用起始 $300 当分母。

用我读到的实测值校验：`BS75tr2` 训练段 `risk_money` 最大 **$235.97**。若该笔真是"账户风险的 8.2 倍（12.3%）"，则触发 `InpMinLotMaxRiskPct=3.0%` 硬上限 → **L479 `if(riskUsed > cap) return 0.0` 会直接放弃该信号**。所以任何单笔风险都不可能超过当期净值的 3%。
→ 反推：**$235.97 只可能是当期净值 ≥ $7,866 时的 3% 以内**。而 `btc-094` 训练段净利 +8,423、起点 $300 → 当期净值确实达到过 $7,000–8,700 量级。**完全自洽。**
→ 结论：**训练段不存在"超配杠杆"，只是账户长大了、美元风险随净值同步增长。**

### 3.3 方法三：直接比较三段的"占净值风险"
| 段 | risk_money 中位 | 当期净值量级 | 占净值 |
|---|---:|---:|---:|
| 测试 BS75f | $6.43 | ~$450（本金 $300、段末附近曾 +$200） | **≈1.4%** |
| 验证 BS75va2 | $7.46 | ~$500 | **≈1.5%** |
| 训练 BS75tr2 | $36.84 | 该段净值从 $300 涨到数千 | **≈0.4–1.5%**（依年份） |

→ **测试段与验证段的占净值风险几乎相同（1.4% vs 1.5%），训练段反而更低。**
→ **"训练段由超配杠杆驱动"不成立。**

**我自己之前也犯过同型错误**：报告_003 §2 我用"2.47% 起始净值口径"给 btc-048 定性，总调度当场纠正过我；这次是同一类口径错误出现在相反方向。**我把这条登记为已证否的假说，不再使用。**

## 4. 事实：审计 CSV 的一个数据限制（必须记录，避免误用）

`BT_btc-106/trades.csv` 42 行里，**40 行的 `entry` 字段是 `0.00`**，只有 2 行（EA 主动平仓的 `dd_kill`）有真实开仓价。

- 原始行示例：`BT_btc-106,BTCUSDm,2025.06.03 16:58:40,1,0.00,105903.37,0.01,-7.21,7.21,480.71,sl`
- 原因：审计由 `OnTradeTransaction` 写入，**券商侧止损平仓时只有成交（exit）deal，取不到开仓价**。
- **影响**：`pnl` / `risk_money` / `exit` / `atr_at_entry` / `exit_reason` **可靠**（我的 R 分析全部只依赖这些）；**`entry` 字段不可用于点差/滑点分析**。
- 我上表的价格轨迹是用 **`exit` 价**重建的（可靠）。

## 5. 我做的 EA 修改（`dsh_BtcSwing.mq5`）

新增 6 个 input（**默认全部对旧行为不变**，避免破坏既有结果）：

```
input int    InpFilterSlopeBars    = 3;      // EMA 斜率回看根数
input bool   InpFilterRequireSlope = false;  // ★要求 EMA 斜率同向
input bool   InpUseEntryQuality    = false;  // ★要求突破K线本身足够强
input double InpMinBarRangeATR     = 1.2;    // 突破K线振幅 >= 此倍数 ATR
input double InpMinClosePosFrac    = 0.65;   // 收盘须位于区间上/下部的比例
input bool   InpRequireMomConfirm  = false;  // 要求前一根同向确认
```

两处新逻辑（位置：`EvalSignal()` 内，趋势过滤之后、突破判定之前）：

1. **斜率闸门**：`slope = EMA(1) − EMA(1+SlopeBars)`；做多要求 `slope > 0`，做空要求 `slope < 0`。
   → 拦截"价格仍在 EMA 上方、但 EMA 已经开始向下"的**趋势反转初期**（正是 2026 的形态）。
2. **入场质量闸门**：突破 K 线振幅 `≥ InpMinBarRangeATR × ATR`，且收盘须落在区间上 65%（多）/下 65%（空）。
   → 过滤"弱突破后立刻反转"的信号。

**自检结果**：字符级扫描（正确跳过块注释/行注释/字符串）**花括号 net=0、方括号 net=0、圆括号 net=0、块注释已闭合**；50 个 input；6 个新参数均已被引用。
