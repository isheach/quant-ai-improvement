## 4. ★★我认为存在一个比"参数无解"更根本的可能性（本报告的核心）

**观察**：`btc-271` 转负，而它在**入金 300** 下的同 cap 版本（`btc-263`）是正的（+130.16）。
**差额在哪？** 我算了一下两笔的关键差异：
```
btc-263 (valid, 入金300,  cap2.5): 49 笔,  PF 1.64
btc-271 (valid, 入金1000, cap2.5): 103 笔, PF 0.91   ← 笔数翻倍，PF 崩到 <1
```
**→ 入金提高后，之前被"最小手地板 + cap"联合拒掉的那 54 笔信号 【现在被执行了】，而它们的净贡献是负的。**

**★★这意味着一个比"参数无解"更根本的可能性**：
> **该策略在 valid 段（2024.06–2025.05）的"正收益"，可能来自"拒单"这一副作用 —— 而不是来自信号本身的 edge。**
> 即：**当资金太小、手数贴地板、cap 频繁拒单时，被留下的那部分信号恰好是盈利的；一旦去掉这个筛选（提高本金让更多信号通过），真实分布暴露为负。**

**★这个可能性的严重性**：如果成立，那么
- 本线此前所有"有效"配置（包括三段兼容形态 `btc-187/177/188`）都可能只是**"有效拒单"的产物**，而非"有效信号"；
- **"参数调优"这个方向本身就走到了尽头**，因为**没有 edge 可供调优**。

**★判定方法（我已提交 `btc-278/279/280`）**：
```
入金3000 下的 cap 三点（valid 段）：
  btc-279 cap1.6 (比值1.07, 强约束)   ← 最接近"频繁拒单"的状态
  btc-278 cap2.5 (比值1.67, 中约束)
  btc-280 cap6.0 (比值4.00, 弱约束 → 几乎不拒单)
```
**→ 若三点全为负**，则**"valid 段无 edge"被确认**（不是参数问题）；
**→ 若存在正值且有规律（例如 cap 越小越好）**，则说明**"拒单筛选"确实在起作用** —— 而这本身就是交付形态的一部分（**但必须在报告中明确写为"依赖拒单筛选"，并提示其脆弱性**）。
