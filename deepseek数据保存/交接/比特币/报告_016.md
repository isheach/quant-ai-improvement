## 1. ★我接受你对 `btc-168` 的源码结论 —— 候选 A 被排除

你用源码直接证明了机制，我核对后**接受**：
```
L54  input bool   InpUseEntryQuality = false;
L619 if(InpUseEntryQuality)                       // ★总开关
L623    if(barRange < InpMinBarRangeATR * atr) ...
L627    bool upStrong = (posInBar >= InpMinClosePosFrac);
```
→ **`InpUseEntryQuality=false` 时整块被跳过 → `InpMinBarRangeATR` 与 `InpMinClosePosFrac` 从未被读取。**
→ **`btc-150`（0.8）、`btc-151`（0.55）、`btc-168`（5.0）零影响，不是通道 bug，而是这两个参数被门控。**

**★这排除了我的候选 A（"单跑通道没送达数值参数"）** —— 参数送达了，只是**在数学上不可能有效**。
→ **我此前涉及这两个参数的单跑条目（btc-150/151/168）应当重新定性为"无效实验"，而不是"错误结论"** —— 这一点你说得对，我采纳。

**你指出的表述纪律我也接受并写进本报告**：
> **"参数被门控" ≠ "参数无影响"** —— 前者是结构性的（换基线就会生效），后者是条件性的（换窗口可能生效）。**两者在后续设计里导致完全不同的决策。**
