## 2. ★★但总调度的"DD 阶跃（cap 是二值开关）"结论 —— **我认为是分段混淆**

总调度观察到：
```
cap≈3 + 锁 : DD 20.0–28.1%   ← 合规簇
cap≥6      : DD 43.9–60.6%   ← 超限簇
cap 2.0    : DD 45.32%
→ 判为"阶跃，无过渡带"
```

**★我逐个核对了这些配置的所在段**：

| 簇 | req_id | **段** | DD% |
|---|---|---|---|
| **合规簇** | btc-226 / btc-229 | **test** | 27.55 / 28.14 |
| | btc-230 | **valid** | 20.03 |
| **超限簇** | btc-219 / 220 / 221 / 225 | **test** | 50.86 / 50.86 / 50.86 / 51.74 |
| | btc-222 / 224 / 232 | **valid** | 53.19 / 60.55 / 57.38 |
| | btc-227 / 228 / 233 / 235 | **train** | 43.11 / 45.32 / 45.56 / 51.75 |

**→ "合规簇"与"超限簇"不是按 cap 分的，而是按【段】分的**：
- **同一段内**（如 test）：`cap 3.0` → 27.55%，`cap 6.0` → 50.86%，`cap 9.0` → 50.86%，`cap 12.0` → 50.86%
- **`cap 6.0` 在 test 段是 43.91–50.86%，在 train 段是 42.86–45.56%** → **DD 水平主要由【段】决定，cap 只是次要调节**
- **`cap 2.0` 在 train 段是 41.48–45.32%** → **并非阶跃，而是"train 段整体在 41–48% 区间"**

**★结论更正**：**不存在"cap 的阶跃"**。真实情况是：
```
train 段:  DD 41.5–48.5%（无论 cap=1.5/2.0/3.0/6.0）
test 段:   cap=3.0 → 27.6% ;  cap≥6 → 43.9–51.7%
valid 段:  cap=3.0 → 20.0% ;  cap≥6 → 53.2–60.6%
```
→ **cap 确实影响 DD（在 test/valid 段影响很大），但不是"阶跃"，而是"按段的连续变化"。**
**→ 这是我第 15 次更正（对总调度结论的更正），依据是其自身给出的数据 + 我补充的段归属。**

## 3. ★★★我把训练段的回撤**逐笔重建**了 —— 它是**单一 2020 年事件**

**方法**：从 `BT_btc-187/trades.csv` 逐笔累加盈亏重建权益曲线（起点 300，并注明这是**近似口径**，未含未平仓浮亏）。

```
期末权益 = 867.29    峰值 = 904.59    最大回撤 = 48.46%（回填 50.85%）
★最深回撤：峰值 537.46 出现在 2019.11.21 → 谷底 276.99 出现在 2020.10.09
  历时 323 天
```

**按年分解（这是全报告最重要的一张表）**：

| 年 | 年末权益 | 年内净利 | **年内最大回撤** | 笔数 |
|---|---:|---:|---:|---:|
| 2018 | 420.25 | +45.54 | **7.15%** | 30 |
| 2019 | 507.72 | +95.50 | 25.27% | 107 |
| **2020** | 475.77 | **−23.46** | **44.52%** | 132 |
| **2021** | 381.70 | **−87.61** | 27.02% | 102 |
| 2022 | 522.31 | +145.87 | 17.48% | 101 |
| 2023 | 602.53 | +83.51 | 16.38% | 94 |
| 2024 | 867.29 | +202.36 | **6.59%** | 39 |

**★关键事实**：
1. **50.85% 训练回撤完全来自 2020–2021 那一次事件**（峰值 2019.11 → 谷底 2020.10）；
2. **2022 起每年为正**（+145.87 / +83.51 / +202.36），**且年内回撤逐年下降：17.48% → 16.38% → 6.59%**；
3. **最近三年（2022–2024）的年内最大回撤全部 ≤17.48%，远低于 40% 门槛**；
4. 2018 年（首个不完整年）回撤仅 7.15%。

**★三种压回撤配置，最深回撤落在同一时点**：

| 配置 | 期末权益 | 年末(2024) | 最大回撤 | **峰值→谷底** |
|---|---:|---:|---:|---|
| btc-187（cap3.0+锁25） | 867.29 | 867.29 | 48.46% | 2019.11.21 → 2020.10.09 |
| btc-233（cap6.0+锁20） | 1247.33 | 1247.33 | **42.86%** | **2019.11.21 → 2020.10.09** |
| **btc-228（cap2.0+锁25）** | **1422.08** | **1422.08** | **41.48%** | **2019.11.22 → 2020.10.09** |

**★读法**：
- **三者的最深回撤都精确落在 2019.11 → 2020.10 同一窗口** → **是同一个市场事件，不是三种不同的失效**；
- **cap=2.0 把该事件回撤压到 41.48%（距 40% 仅 1.48 pp），同时期末权益最高（1422 vs 867）** —— 与其他压回撤路径不同，**它没有牺牲收益**（PF 1.42，全批最高）；

## 4. ★我的判断：`cap=2.0` 是唯一"未牺牲收益"的压回撤路径

总调度结论是"所有压 DD 进 40% 的尝试全部失败"。**我基本同意，但要点出一个例外**：

| 路径 | 净利变化 | DD 变化 | 评价 |
|---|---|---|---|
| 收锁 25→20 (btc-227) | +663 → **+672** | 51.75 → **43.11%** | 中性，DD 未达标 |
| cap6+锁20 (btc-233) | +663 → **+669** | 51.75 → **45.56%** | 中性，DD 未达标 |
| **cap 3.0→2.0 (btc-228)** | +663 → **+868（+31%）** | 51.75 → **41.48%** | ★**收益大增 + 最接近门槛** |

**→ `btc-228` 是唯一"净利反而提升 31%、DD 降至最接近 40%"的配置**（PF 1.42 vs 1.24）。**
**→ 它与 40% 门槛差 1.48 pp。** 我已在 `btc-236`（cap 1.5）与 `btc-239`（cap 1.0）继续下探。

**★但我要说明白**：**把 cap 一路降到 1.0 会让 `cap/RiskPct = 0.67 < 1` → 触发放行分支的拒单 → 笔数会下降。**
**→ 所以"压进 40%"与"保住 50 笔/年"可能不可兼得** —— 这正是 `btc-239` 要回答的。

## 7. ★我要向总调度说明的一点方法论

总调度的"阶跃"结论依据是"DD 数值成两簇"。**但 DD 数值的簇完全可以由"段不同"造成**，而段的归属在总调度给出的表格里**没有标出**。
**→ 这正是我第 8 条纪律的适用场景**：「机制推断必须用数据验算，不能用汇总数字猜测」—— **段是把 DD 数值聚成两簇的隐藏变量。**
**→ 我在 §2 补上段归属后，阶跃现象消失**。**这不是总调度的错**（他给的是原始数字，没有宣称段归属），**而是我提醒：任何"数值分簇"结论都应先检查是否被第三个变量分层。**

**新增方法纪律（第 9 条）**：
> **当数据点呈现"分簇"或"阶跃"时，先按所有可能的分类变量（段 / 品种 / 年份 / 参数档）分层，确认簇不是分层的副产品。**
