## 1. 事实：`btcgrid-101` 为何全灭 —— 我读 `.set` 得到了确凿答案

`opt_btcgrid-101.set` 关键项：
```
InpUseEntryQuality=true||false||0||true||N      ← 我显式写的 true，被执行
InpAllowShort=false                             ← 我显式写的
InpSL_ATR=1.5                                   ← 我显式写的
InpFilterSlopeBars=3||6||4||10||Y               ← 优化中
InpFilterEMA=50||150||50||200||Y                ← 优化中
InpDonchianBars=48||24||24||72||Y               ← 优化中
InpUseDDKill=false
InpLatencyTicks=1
```
**`InpUseEntryQuality=true` 确实生效了** —— 这是我在 `fixed` 里显式写的。
→ **因此冒烟网格复现不出 `btc-138` 的 +412.52 是必然的**：**它跑的本来就不是 btc-138 的参数。**

**并且这给出了 `0 profitable` 的解释**：`InpUseEntryQuality=true` 时单组笔数 5,565–5,924、DD 99.96–99.98%；
而 `btc-138`（`UseEntryQuality=false`）是 336 笔、DD 50.21%、+412.52。
→ **`InpUseEntryQuality=true` 在 `btcswing` 的参数空间里是有害开关**（与 `btc-135` 的 −78.17/PF 0.66 方向一致）。

## 2. ★★事实更正：总调度 §二 的证据表里有一格是错的

总调度给出的对比表写：
| 参数 | btc-139 单跑 | btcgrid-101 网格 |
|---|---|---|
| `InpUseEntryQuality` | **`false`** | `true` |

**我核对了 outbox 实录，`btc-139` 的 `params` 是：**
```
btc-139 -> InpSL_ATR=1.5  InpFilterEMA=200  InpFilterRequireSlope=true
           InpFilterSlopeBars=10  InpAllowShort=false  InpLatencyTicks=1
```
→ **`btc-139` 的请求里根本没有 `InpUseEntryQuality` 这一项** —— 它既不是 `false` 也不是 `true`，而是**继承了单跑通道的 BASE 值**（即 `BASE_BTCSWING`，其中 `InpUseEntryQuality=false`）。
→ 所以那一格应写作「**未显式指定 → 继承 BASE = false**」，而不是「`false`」。

**这个区别很关键**，因为它直接指向真因（见 §3），而"`false` vs `true`"的表面差异会掩盖机制。

## 3. ★★真因：**两条通道的参数基底根本不同**

| 通道 | 未显式指定的参数取什么值 |
|---|---|
| **单跑（runexp）** | `BASE_BTCSWING`（我在 `btcswing.set` 里读到的） |
| **网格（grid，修复前）** | **EA 源码默认值** |

**两条基底在多个参数上不一致**（我从 `btcswing.set` 与源码逐项对比）：

| 参数 | `BASE_BTCSWING`（单跑用） | **源码默认值**（网格修复前用） | 是否一致 |
|---|---|---|---|
| `InpSL_ATR` | **0.5** | **2.0** | ❌ 差异 4 倍 |
| `InpUseVolNormalize` | **false** | **true** | ❌ |
| `InpWriteAudit` | **false** | **true** | ❌ |
| `InpLatencyMs` | **300** | 300 | ✅ |
| `InpLatencyTicks` | **（无此项）** | 1 | ❌ 缺失 |
| `InpFilterEMA` | `50 ‖ 20 ‖ 20 ‖ 80 ‖ **Y**` | 50（固定） | ❌ 带优化标记 |
| `InpFilterSlopeBars` | `3 ‖ 2 ‖ 2 ‖ 6 ‖ **Y**` | 3（固定） | ❌ 带优化标记 |
| `InpMaxBarsInTrade` | `96 ‖ 48 ‖ 48 ‖ 192 ‖ **Y**` | 96（固定） | ❌ 带优化标记 |
| `InpUseEntryQuality` | false | false | ✅ |
| `InpUseDDKill` | true | true | ✅ |

→ **`btcgrid-001…006` 全灭的机制**：它们未显式指定的参数**落回源码默认**，其中 **`InpSL_ATR` 变成 2.0（而非我调好的 1.5）**、`InpUseVolNormalize` 变 true —— 与我全部盈利配置的基底不符。
→ **总调度"网格通道与单跑通道参数口径不一致"的诊断方向正确**；我此前"担心通道有未发现差异"的顾虑**可以解除**：**通道没问题，是基底错配。**

## 4. ★★我不推荐"合并 `BASE_BTCSWING`"这个修法（两条理由，都有实测依据）

总调度把 `opt_runner.py` 改成"**先套 `BASE_BTCSWING`，再让请求的 `fixed` 覆盖**"。**我建议不要这样做**，理由：

### 4.1 `BASE_BTCSWING` 里带着**残留的优化范围标记**，会把声明组合数**悄悄放大**
`btcswing.set` 里有三行**不是固定值，而是带 `Y` 的优化范围**：
```
InpFilterEMA=50||20||20||80||Y          → 4 档
InpFilterSlopeBars=3||2||2||6||Y        → 3 档
InpMaxBarsInTrade=96||48||48||192||Y    → 4 档
```
**若把这份基线合并进网格 `.set`，我的 12 组合会变成 12 × 4 × 3 × 4 = 576 组**，而"声明组合数 = 12"仍然显示着。
→ 这正好会**制造出与 `btcgrid-001…006` 同型的新一轮"pass 数对不上"**，且**更难发现**（因为这次声明数是对的，只是被基底悄悄放大）。
→ **请确认 `.set` 生成逻辑是否会把带 `Y` 的行透传**；若会，**必须先把这三行清成固定值**。

### 4.2 `BASE_BTCSWING` 本身就与"我的盈利配置"不一致，合并它**会引入新的错配**
- `BASE_BTCSWING` 的 `InpSL_ATR=0.5`，而**我全部盈利配置用的是 1.5**（`btc-075` 训练 PF 1.58、`btc-138` +412.52 都是 1.5）。
- `BASE_BTCSWING` 的 `InpFilterRequireSlope=false`，而**我的修复配置要求 true**。
- `InpUseVolNormalize`：`BASE_BTCSWING` 是 **false**，而 `btc-138` 那次跑的是**源码默认 true**（见 §3）—— 也就是说 **`btc-138` 的 +412.52 是在 `UseVolNormalize=true` 下取得的**，与 `BASE_BTCSWING` 的 false 相反。
→ **合并 `BASE_BTCSWING` 会把 `btc-138` 赖以成立的那个值改掉**，等于**引入另一种错配**。

### 4.3 我的替代方案（已采用）：**网格显式写全部非优化参数**
**`btcgrid-102` 我把全部 42 个非优化参数都写进 `fixed`**，与 `btc-138` 单跑基底逐项对齐：
```
InpUseEntryQuality=false   InpUseDDKill=false    InpSL_ATR=1.5
InpAllowShort=false        InpUseVolNormalize=false   InpLatencyTicks=1
InpLatencyMs=0             InpWriteAudit=false    InpFilterRequireSlope=true
…（共 42 项，无遗漏）
```
→ **这样"隐式默认值"这个概念在网格里彻底消失**：无论基底怎么设，都只由 `fixed` 决定。
→ **代价**：每条网格请求变长（但这是 JSON，不占 MT5 机时）。

**★同时请确认**：修复后的合并逻辑是"**先套基底、再让 `fixed` 覆盖**"吗？
- 若是 → 我的 42 项 `fixed` 会**全部覆盖**基底，`btcgrid-102` 可正常运行；
- 若不是（例如基底反过来覆盖 `fixed`）→ **`btcgrid-102` 也会被污染**，请告知，我改用别的提交方式。
