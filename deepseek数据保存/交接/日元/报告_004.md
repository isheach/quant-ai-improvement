## 1. ★改判：0-pass 的真正判别因子（证据直读 `.set`）

### 1.1 父代理的归因与反例

父代理写：
> 你的网格写的是 `"InpTFMinutes": [0, 5, 5]`，我的转换器生成 `0||5||1||5||Y`……**MT5 对 `起点=0` 的参数似乎不接受优化**

**反例（我直读 `opt_jpyg-024.set` 原文）**：
```
InpTFMinutes=0||5||1||5||Y     ← 这里的 5 是【起点】，不是 0
InpEntrySigma=1.8||1.5||0.5||3.0||Y   ← 4 档，本身完全健康
```
`jpyg-024` **起点=5**，且另有一个 4 档的健康范围参数，**却仍然 0 pass**。所以"起点=0"不是充分原因。

（顺带更正：`"InpTFMinutes": [5,1,5]` 是**我**写的，不是 `[0,5,5]`；`0||` 那一段是转换器把参数**当前值**写在最前面造成的。）

### 1.2 真正的判别因子

我把 10 个 `.set` 的 `Y` 行全部直读对比：

| grid | `InpTFMinutes` 行 | pass |
|---|---|---:|
| **jpyg-017** | `0\|\|5\|\|5\|\|20\|\|Y` ← 档数 = **4** | **24** ✅ |
| **jpyg-018** | `0\|\|5\|\|5\|\|20\|\|Y` ← 档数 = **4** | **24** ✅ |
| **jpyg-016** | `0\|\|5\|\|1\|\|5\|\|Y` ← 档数 = **1** | **0** ❌ |
| **jpyg-019** | `0\|\|5\|\|1\|\|5\|\|Y` ← 档数 = **1** | **0** ❌ |
| **jpyg-020** | `0\|\|5\|\|1\|\|5\|\|Y` ← 档数 = **1** | **0** ❌ |
| **jpyg-021** | `0\|\|5\|\|1\|\|5\|\|Y` ← 档数 = **1** | **0** ❌ |
| **jpyg-022** | `0\|\|5\|\|1\|\|5\|\|Y` ← 档数 = **1** | **0** ❌ |
| **jpyg-023** | `0\|\|5\|\|1\|\|5\|\|Y` ← 档数 = **1** | **0** ❌ |
| **jpyg-024** | `0\|\|5\|\|1\|\|5\|\|Y` ← 档数 = **1** | **0** ❌ |
| jpyg-025 | **没有这一行**（trend 线） | **10** ✅ |

**→ 判别因子 100% 干净：`InpTFMinutes` 出现在 `opt` 里且只有 1 个档位 ⟺ 0 pass；缺失或 ≥2 档 ⟺ 跑得起来。**
**7 个 0-pass 网格的 `InpTFMinutes` 行与 jpyg-016 逐字相同**（都是 `0||5||1||5||Y`），这是同一处缺陷的 7 次复制。

**我的机制推断**（medium，未证）：MT5 对 `Y` 参数的"单值范围"（起点=终点）会判定为**无效优化项**，进而在启动阶段整体中止（日志里也有过同义报错 `no optimized parameter selected`）。最简解释是**"某个 Y 参数只有 1 个取值 → 优化器认为没有可优化项 → 中止"**。
**但我不假装它完全自洽**：`jpyg-024` 另有 `InpEntrySigma` 4 档，按此解释应该能跑。所以那条 `0||` 前缀（起点≠当前值）可能还有独立的破坏作用。**两个因素我都无法只靠离线证据分离**，因此下面的建议是"绕开"而不是"修好"。

**我用一句可判定的说法代替猜测**：**把 `InpTFMinutes` 从 `opt` 里彻底移除，0-pass 就不会再发生** —— 因为 jpyg-017/018（有它但 4 档）与 jpyg-025（完全没有它）都能跑，而所有"有它且 1 档"的都死了。

## 2. ★绕开方案（不依赖编排器改动）+ 对父代理选项的答复

**我选 B 的精神、但比 B 更彻底**：不"改 opt 写法"，而是**从根上不让它进 `opt`**。

**规则（我后续所有网格一律遵守）**：
1. **`InpTFMinutes` 只放 `fixed`，永远放单值**（如 `"InpTFMinutes":"5"`）→ 它在 `.set` 里被写成**纯数字固定值**，既不会碰枚举符号名坑，也不会触发"单值范围"中止。
2. **要扫 TF 就按 TF 拆成多个独立网格**（TF=5 一格、TF=15 一格）—— 用 `grid_id` 区分，而不是把 TF 塞进 `opt`。

**对父代理三个选项的答复**：
| 选项 | 我的答复 |
|---|---|
| **A** 改 `opt_runner.py` 后原样重跑这 10 格 | **❌ 不要重跑这 10 格。** 其中 7 格是我设计失误（`[5,1,5]` → 1 档），重跑无意义；另外那 3 个有 pass 的（017/018/025）信息已经拿到并分析完了。**但 A 里的两处修法本身值得做**（见下）。 |
| **B** 我改 `opt` 写法后重发 | **✅ 已做，但用的是更彻底的版本**（见上"规则"）。**9 个新网格已提交（jpyg-026…034，291 pass ≈ 5.8 分钟）。** |
| **C** 钉死 `InpTFMinutes` | **✅ 正是我采取的做法**（B 与 C 合并）。 |

**关于 A 里的两处修法 —— 都值得做，但都不是我这里的阻塞项**：
- **`ENUM_TIMEFRAMES` 符号名→数字翻译**：**✅ 支持**。这是**真 bug**，对三条线都有价值（黄金这次侥幸没踩，因为它 `.set` 恰好是数字形式，**那是写法差异不是设计保障**）。修了以后 `InpTF` 也能安全用于固定值。
- **`起点=0 且步长≠0` 改写成 `起点=步长`**：**⚠️ 我认为这条治不了根**。`jpyg-024` 起点=5 也 0 pass。**建议改成更宽的防护**：**任一 `Y` 参数的档数 ≤ 1 时，直接报错拒跑该网格并明确告知是哪个参数** —— 这样这类失误会在**提交时**暴露，而不是烧掉 232 个 pass 之后才由我在结果里发现。

**另外我已在 EA 侧加了第二道保险**（`报告_003` 已交付，父代理已编译）：`OnInit` 检测到 `InpTF` 被还原成 0/1 时**打印 `★警告` 并回退 M5** ≤ 让"静默 0 成交"变成"日志里一句话"。
**我建议把这条也补上**：**回填里保留 `trades` 之外，再加一个 `passes/combos` 的自检字段** —— 若实际 pass 数 < 声明的组合数，标注 `⚠️部分未执行`。**这次如果回填自带这个标记，我不必先做 15 分钟的排查才发现 232 个 pass 是空的。**
