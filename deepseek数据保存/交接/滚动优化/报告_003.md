## 1. 【事实】诊断：`档数<=1` 判据**不能解释**我的 0 pass

总调度转达 JPY 线的判据是"任一 `Y` 参数只有 1 档 ⟺ MT5 拒绝优化（0 pass、无 XML）"。
**我直接读了自己那 6 个失败网格生成的 `.set` 文件**（`MQL5\Profiles\Tester\opt_wf-w0-v-on.set`），逐轴数了档数：

| 失败网格 `opt_wf-w0-v-on.set` 的 `Y` 行 | `[起点,步长,终点]` | 档数 |
|---|---|---:|
| `InpDonchianBars=48\|\|24\|\|24\|\|72\|\|Y` | 24,24,72 | **3** |
| `InpFilterEMA=50\|\|50\|\|75\|\|200\|\|Y` | 50,75,200 | **3** |
| `InpSL_ATR=2.0\|\|1.0\|\|0.5\|\|2.5\|\|Y` | 1.0,0.5,2.5 | **4** |
| `InpMaxBarsInTrade=96\|\|48\|\|96\|\|240\|\|Y` | 48,96,240 | **3** |

→ **`4 × 3 × 3 × 3 = 108`，最小档数 = 3，没有一个是 ≤1。** 判据的前提在我这里不成立。

**反证（更强的证据）**：**已成功跑通 144 pass 的测试网格**里，`InpMaxBarsInTrade` 只有 **2 档**
（`48||192||240`）、`InpFilterSlopeBars` 只有 **2 档**（`5||5||10`）。
→ 若"档数 ≤1"才是判别因子，那么"**档数 ≤2 也能跑**"与之并不矛盾，但**它无法解释为什么档数最少为 3 的网格反而 0 pass**。
→ **【事实】我的 6 个验证网格在结构上比已成功的网格"更宽松"，却失败了。**

## 2. 【事实】我找到了 `opt_runner.py` 里两个真实缺陷（不论是否为本因，都该修）

### 2.1 ★每个被优化的参数都被**写了两遍**（`opt_runner.py` L134-135）

```python
134:                lines.append("%s=%s||%s||%s||%s||Y" % (name, dflt, s, st, e))
135:                lines.append("%s=%s||%s||%s||%s||Y" % (name, dflt, s, st, e))
```

两行**完全相同**，于是 `.set` 里每个 `Y` 参数都出现两次。我在 `opt_wf-w0-v-on.set` 里实测到：

```
 10| InpDonchianBars=48||24||24||72||Y
 11| InpDonchianBars=48||24||24||72||Y      ← 重复
```

**但我要诚实标注：这不是本因。** 同一份文件里，**成功的** `opt_wf-w0-t-on.set` 也有同样的重复。
→ **【推断 · 中置信】重复行本身不致命**，但它让 `.set` 失去 MT5 原生格式（MT5 自己保存的 `dsh_BtcSwing.set`
   是无重复的规范格式，我对比过），**属于应修的真实缺陷**，且它可能是"某些组合才踩到"的边界条件来源。

### 2.2 ★EA 名被截断到 24 字符 → 网格间**文件名碰撞**（`opt_runner.py` L221）

```python
221:    ea_name = "opt_" + gid[:24]
```

我的网格 id 长度：`wf-w0-v-on` = 10 字符 → `opt_wf-w0-v-on`（**15 字符，未触发截断**）。
→ **我的网格没有踩到这个坑**（id 都在 24 以内）。但顺带指出：
**同一个 `ea_name` 对应同一个 `.set` 与同一个 `.ex5`**；若将来 id 超过 24 字符，两个网格会共用 `.set` 文件，
后写的会覆盖先写的，**表现为"跑出来的结果属于另一个网格"** —— 这与总调度已发现的"去重跳过"是不同的一类静默错误，建议一并加防护。
