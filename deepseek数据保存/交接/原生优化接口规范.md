# MT5 原生并行优化接口规范（★v1，2026-09-12）

> **本文取代 `MT5运行请求协议.md` 里"逐条 jsonl 请求"的工作方式。**
> 原因：实测逐条串行 ≈ **3.81 tests/min**；MT5 原生优化 = **28 agent 并行，25 组 29.6 秒 ≈ 50 tests/min**，
> **快约 13 倍**，而且不需要自写调度器（MT5 自己知道怎么分配 agent）。

---

## 一、为什么改用原生优化（实测对比）

| 方案 | 吞吐 | 峰值并发 agent | 结论 |
|---|---:|---:|---|
| 逐条 `terminal64 /config:` 串行 | 3.81 tests/min | 1 | 基线 |
| 自写 Worker 池（多 portable 实例） | 1.59 tests/min | **1**（任务全压到一个 worker） | ❌ 更慢，废弃 |
| **MT5 原生优化**（`Optimization=2` + `.set`） | **~50 tests/min** | **28** | ✅ **采用** |

**关键约束（决定只能用原生优化）**：
- MT5 terminal 对同一数据目录**单实例**
- 同一账户**无法多实例并发登录**（每次登录顶掉前一个）
- → 唯一能真正跑满多核的路，就是**让 MT5 自己的 agent 池**去并行

## 二、你要提交什么（**参数网格 `.set`**，不是逐条请求）

### 2.1 `.set` 文件格式（UTF-16LE，MT5 原生）

```
; 注释行以 ; 开头
InpDonchianBars=48||24||12||72||Y     ← 参与优化：start=24, step=12, stop=72（含）
InpSL_ATR=1.5||1.0||0.5||3.0||Y       ← start=1.0, step=0.5, stop=3.0 → 1.0,1.5,2.0,2.5,3.0
InpTrail_ATR=3.5                      ← 无 || = 固定值
InpLatencyMs=300                      ← 固定（必须）
```

**语法**：`参数名=当前值||起点||步长||终点||Y/N`
- `Y` = 该参数参与优化（笛卡尔积）
- `N` 或无 `||` = 固定
- **bool 参数**：`InpUseTrendFilter=true||false||0||true||N`（固定）或 `...||Y`（优化，只有 true/false 两值）
- **枚举参数**（如 `InpTF`）：`InpTF=16385||0||0||49153||N`  —— 枚举优化要用**显式列表**（见 2.3）

### 2.2 ★位置与引用方式（这是之前失败的原因）

| 项 | 正确做法 |
|---|---|
| **`.set` 放哪** | `MQL5\Profiles\Tester\<EA名>.set`（如 `dsh_BtcSwing.set`） |
| **ini 怎么写** | `Optimization=2`，**并且完全不要写 `[TesterInputs]` 段** —— MT5 会自动加载同名 `.set` |
| **错误做法** | 把 `.set` 放自己目录、在 `[TesterInputs]` 里塞绝对路径 → **优化空跑退出、0 agent** |

**权威样本**：MT5 自己在 `MQL5\Profiles\Tester\dsh_BtcSwing.set` 生成过一份完整格式样本，
**你可以直接读它作为模板**（含全部 42 个参数的正确 range/step）。

### 2.3 显式列表（非等差参数）

MT5 `.set` 支持用 `||` 多值形式给**离散列表**：
```
InpTF=16385||16385||5||49153||Y      → 枚举优化建议改用多个 pass 手写列表
```
**若你不会写，就老实提交"等差网格"** —— 我们再用结果 XML 过滤出想要的组合。

## 三、你提交的请求格式（改造后的 jsonl）

每行一条**网格任务**：

```json
{"grid_id":"btcgrid-001","expert":"btcswing","symbol":"btc",
 "from":"2024.08.01","to":"2024.08.31",
 "fixed":{"InpTrail_ATR":"3.5","InpUseChandelier":"true"},
 "opt":{"InpSL_ATR":[1.0,0.5,3.0],"InpDonchianBars":[24,12,72]},
 "why":"网格：SL 3 档 × 唐奇安 3 档",
 "priority":"high"}
```

字段：
| 字段 | 说明 |
|---|---|
| `grid_id` | 唯一 ID |
| `expert` | `trend` / `meanrev` / `btcswing` / `jpyrev` |
| `symbol` | `btc` / `gold` / `jpy` |
| `from` / `to` | **必填**，窗口起止（滚动优化必需） |
| `fixed` | 固定参数（可选，走 EA 基线） |
| **`opt`** | **`{参数名: [起点, 步长, 终点]}`** — 我会转成 `.set` 的 `||` 语法 |
| `why` | 一句话理由 |

**⚠️ 组合数控制**：`各参数档数之积 ≤ 5000`（28 agent × 单窗口）。超过请拆成多个 `grid_id`。

## 四、我会回填什么

结果写回 `outbox_<线名>.jsonl`，每条 = **一个 pass（一组参数）**：

```json
{"grid_id":"btcgrid-001","pass":7,
 "params":{"InpSL_ATR":"1.5","InpDonchianBars":"48"},
 "profit":26.23,"net":326.23,"expected_payoff":4.371667,
 "profit_factor":2.2183,"recovery_factor":0.6664,"sharpe":0.5588,
 "from":"2024.08.01","to":"2024.08.31",
 "xml":"...\\rep_OPT3.xml","elapsed_s":29.6}
```

**`pass` → `params` 的映射由我负责**（解析 MT5 优化输出 + 反查），你直接用 `params` 即可。

## 七、已确认的环境陷阱（别踩）

1. **主终端 `accounts.dat` 存过期凭据** → `Invalid account`。修复：用已验证的凭据覆盖它
2. **标签不能含中文**（`Report=`/`InpRunTag=`）→ MT5 报"成功"但只跑 2.4 秒、无报告
3. **`Optimization=2` 时不要写 `[TesterInputs]`** → 否则 `.set` 不生效、0 agent
4. **`.set` 必须放 `MQL5\Profiles\Tester\`**
5. 实测 **并行度 4 的自写池比串行更慢**（任务全压到一个 worker），别再用它
