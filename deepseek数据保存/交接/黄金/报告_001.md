## 1. 事实（读源码/协议得出，不依赖回测）

### F1. EA 的风险闸门是"美元止损距离闸门"（源码级结论）

`dsh_TrendCore.mq5` L415–480 `LotForRisk()`：

```
riskMoney = equity × InpRiskPct / 100
perLot    = stopDist($) × MoneyPerPricePerLot()
lot       = riskMoney / perLot
若 lot < 最小手(0.01):
    若 InpAllowMinLotOvershoot=false → 直接放弃信号
    若 =true → 取 lot = 0.01，但要求  0.01 × perLot ≤ equity × InpMinLotMaxRiskPct/100
              否则放弃信号
```

**推论（这是本批最重要的一个设计发现）**：
`InpMinLotMaxRiskPct` 不只是"风险上限"，它**等价于一条美元止损距离闸门**：

```
最小手成交 ⇔ 止损距离($) ≤ equity × InpMinLotMaxRiskPct / 100
```

代入 equity=300：

| `InpMinLotMaxRiskPct` | 允许的最大止损距离 | 折合 0.01 手风险 | 占 300 账户 |
|---:|---:|---:|---:|
| 3.0（基线） | **$9.00** | $9.00 | 3.0% |
| 2.0 | **$6.00** | $6.00 | 2.0% |
| **1.0** | **$3.00** | $3.00 | **1.0%** ← 用户定义的目标 |
| 0.5 | $1.50 | $1.50 | 0.5% |

→ **所以 gold-004（只把 `InpMinLotMaxRiskPct` 改成 1.0）就是"单笔风险≤1%"这一约束的精确算子**，
不需要改入金、不需要近似。这比"按入金反推"更干净。**这是本批的核心探针。**

### F2. `InpSL_ATR` 的 ATR 是"趋势周期自己的 ATR"，不是固定的 M30 美元数

task 描述里 `InpTrendTF`（30/15/60）与 `runexp.py::BASE_PARAMS["InpTrendTF"]="30"` 一致；
但**源码 L60 的默认值是 `PERIOD_M5`（=5）**。→ 两者都是合法输入，但含义差 6 倍。
本批沿用 `runexp.py` 的基线 `30`，`gold-011/012` 才切到 5。

**ATR 按价格等比缩放**（用协议里两个实测锚点反推）：
- 锚点 A：金价 ~4000，ATR(M30) ≈ $10.9 → **0.273% of price**
- 锚点 B：金价 ~4560，ATR(M30) ≈ $16.38 → **0.359% of price**
→ 取 **ATR(M30) ≈ 0.30–0.36% × 金价** 作为解析估算口径（medium 可信度：两点外推，未做全样本实测）。
派生：ATR(M15) ≈ 0.52× ATR(M30)，ATR(M5) ≈ 0.19× ATR(M30)（标准 √t 缩放 + 轻微超额）。

### F3. 训练段的 ATR 美元量级（解析估算，非实测）

训练段 2014.01–2024.05 金价大致在 1200–2100，均值约 **$1400–1500**。

| 周期 | ATR 估算（金价$1500） | 0.25× | 0.5× | 1.0× | 2.5× | 3.0× |
|---|---:|---:|---:|---:|---:|---:|
| M30 | ≈ $4.8 | $1.20 | $2.40 | $4.80 | $12.0 | $14.4 |
| M15 | ≈ $2.5 | $0.63 | $1.25 | $2.50 | $6.25 | $7.5 |
| M5 | ≈ $0.9 | $0.23 | $0.45 | $0.90 | $2.25 | $2.7 |

**读法**：
- **M30 基线（2.5×ATR=$12.0）在 300 账户上是 4.0%/笔** → 超过 3.0% 硬上限 → **按 F1，这些信号会被直接放弃**。
  这正是历史报告"验证段 0 笔"的同一个机制，只是现在发生在**训练段**。
  → **本批 gold-001 的预期是"成交极少甚至 0 笔"**。若真如此，量纲难题在训练段就已经被证实，不需要等到验证段。

- **M5 的 2.5×ATR（$2.25）也落在 1% 带内** → gold-011 是另一条可成交路线。

### F4. ★收益目标的数学天花板（这一条与止损无关，独立成立）

0.01 手是**硬地板**，EA 无法开更小仓位。在"单笔风险 ≤ 1%（=$3）"下：

```
年化 = 年交易笔数 × 每笔期望R × $3 / $300
100% ⇔ 年交易笔数 × 期望R = 100
```

| 情形 | 期望R | 达到年化 100% 所需年交易笔数 |
|---|---:|---:|
| 胜率 55%，1:1 | +0.10R | **1000 笔/年** |
| 胜率 45%，1:1 | −0.10R | **不可能（负期望）** |
| 胜率 45%，2:1 | +0.35R | **286 笔/年** |
| 胜率 35%，3:1 | +0.40R | **250 笔/年** |
| 胜率 50%，3:1 | +1.00R | **100 笔/年** |
| 胜率 40%，3:1 | +0.60R | **167 笔/年** |

**历史事实核对**：历史最好配置训练段（2017.04–2023.12，6.75 年）**161 笔 = 24 笔/年**。
→ **要在这个频率下做到年化 100%，需要每笔期望 **+4.2R**（即 4R 以上的平均盈亏比）——不现实。**
→ **结论（high 可信度，纯算术）**：**"300 本金 + 年化 100%"要么需要把交易频率提高一个数量级（≥250 笔/年），
要么需要接受 3R+ 的盈亏比结构，要么必须放弃"单笔风险≤1%"。三者必选其一。**
这条约束**必须先告诉总调度**，因为它决定了后续整个搜索空间的方向（是找频率，还是找盈亏比）。

**I6 的解析预判（已读源码，修正如下 —— 这条比原预判更严重）**

源码核查（`dsh_MeanRev.mq5` L193–212、L221–248、L655–674）后我改了结论：

1. **σ 不是 ATR，也不是 bar 间波动**：`GetStats()` 算的是 **96 根 M30 收盘价对 48 根均值的标准差**
   （`sigma = sqrt( Σ(close_i − MA)^2 / 96 )`）。
   → 这个 σ **包含了趋势漂移**，量级是"bar 间波动的 √48 ≈ 6.9 倍"量级。
   → **σ(M30) 通常显著大于 ATR(M30)**，与 task 里"σ 可能比 ATR 小"的假设**相反**。
2. **止损距离在信号时刻用的是 `MA − 入场价`，不是 σ**（L669 有效）：
   `stopDist = MA − 入场价`（做多），而入场条件是 `|入场价 − MA| ≥ 2.0σ`。
   → 所以 `stopDist ≥ 2.0σ`，**通常 ≥ $20 @金价$1500** = **6.7%/笔**。
3. → **gold-016 基线几乎必然被 `InpMinLotMaxRiskPct=3.0` 全部拒绝 → 预期成交数 ≈ 0。**
4. `InpStopSigma` 在开仓路径上是**死参数**（无调用者），只影响审计字段 —— 所以
   **gold-018/gold-019 的 `InpStopSigma=0.5` 预期不改变成交**。这是对一个可能存在的 EA bug 的间接探针。

**该机制的正向用法（下一批会用到）**：止损距离 ≈ `σ × InpEntrySigma`，
所以 `InpEntrySigma` **就是** σ 尺度的止损闸门旋钮：

| 要让止损 ≤ $3 | 需要的 `InpEntrySigma`（在 σ≈$10 时） |
|---:|---:|
| 1% 风险带 | **≤ 0.3σ** |

→ **均值回归线上的真正旋钮是 `InpEntrySigma`（同时决定入场阈值与止损距离），不是 `InpStopSigma`。**
本批 gold-017 用的 2.5σ 是**测错方向的**（止损会更大 → 更不可能成交）。
→ 我把这条留到第二批（`InpEntrySigma=0.3/0.5`），**本批不改**，以保留"基线预期 0 成交"这一干净检验。
