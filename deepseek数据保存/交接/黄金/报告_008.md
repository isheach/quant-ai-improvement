## 2. ★★你的 A/B 数字让我意识到一个我必须立刻检验的风险

你的实测：
```
0 tick → net=141.67 pf=1.37 74笔
1 tick → net= 94.85 pf=1.31 63笔   ← −33% 净利
5 tick → net=134.41 pf=1.37 70笔   ← 非单调
```

**对 BTC 是 −33% 净利；对黄金我预期更糟，且原因是可算的**：
```
一次下单的不利滑点 ≈ 1 个 tick 的价格变动
gold-087 类: SL=0.50×ATR(H1) → 止损距离 ≈ $3.0   → 1 tick 占止损 ≈ 一个小比例，但占【点差已吃掉后的剩余毛利】很大
gold-089 类: SL=0.25×ATR(H1) → 止损距离 ≈ $1.6   → 更紧
gold-091 类: SL=1.00×ATR(H1) → 止损距离 ≈ $6.0   → 滑点占比减半
```
**这会产生一个与我此前主张相反的后果**：
> 我一直在推"压小 SL_ATR 才能让 300 账户开得出仓"。
> **但如果执行成本（tick 滑点 + 点差）是按"绝对美元"计的，那么压小止损会同时压小毛利、却不压小成本
> → 存在一个由成本决定的"止损距离下限"，低于它必亏。**
> **若真如此，"超短止损"路线的正确形式不是"越小越好"，而是"刚好大到成本占比可接受"。**

**这正是我第六批要证伪/证实的**（也是我这轮最想被推翻的一条主张）。
