### 【目录 1 代】eva005–eva007 · 导出器 v2（强制下载 + 位数自适应）

**改了什么 / 为什么**
- `eva005_TickDataExporter.mq5` v2.00：加**"强制下载+等待重试"**（`Bars()/CopyRates` 触发同步，`SERIES_FIRSTDATE` 判断回溯到位，各月/天带重试+Sleep，新增 `InpSyncWaitSec/InpMaxRetries/InpRetrySleepMs`）；**tick 与 K 线区间分离**（K 线可到 2014，tick 默认只取近几年，自动跳过早于券商可用 tick 起点的月份）；预检打印每周期**实际可用最早日期**；输出位数 = `max(品种Digits, InpForceMinDigits=3)`；**写 `meta.json`**（digits/point/各周期起点）。
- `eva006_data_pipeline.py` v2.0：**点值自动识别**（优先读 `meta.json`，缺省 0.001）；"大顺向"阈值由**按点写死 300** 改为**按价格（美元）** `--mfe-big-price` 默认 3.0。
- `eva007_data_request_template.json` v2：`point` 改为可省略。

**结果 / 结论**
- 根因确认：`CopyRates/CopyTicksRange` **只返回终端本地已下载的历史**，MT5 历史是**异步后台下载**的，脚本一次性调用只抓到已缓存部分 → 用户此前只拿到"最近若干月、各周期数量还不一致"。
- 位数实测：**用户图表上的黄金品种 MT5 报 2 位**（point=0.01），非代码 bug。位数 3 位迁移后，按点写死 300 会**误判问题单**（实测 pos102 在 3 位下用 $3 阈值正确归为 clean_loss/stopped_out，按点写死 300 会误判 gave_back）。
- 硬约束：Exness 黄金**真实 tick 仅回溯近几年**（2014 年真实 tick 大概率不存在）；M1/M5 可回溯到 2010 年代初。

### 【目录 2 代】eva008 · 导出器改为「测试器 EA」（数据问题终结）

**改了什么 / 为什么**
- `eva008_TickDataExporterEA.mq5` v3.00：把导出器从"实时脚本"改成**在策略测试器里运行的 EA**（Optimization=Disabled）。`OnTick` 逐 tick 写 + 逐 bar 写，按月轮转文件，`OnDeinit` 收尾并生成 meta.json，优化模式自动禁用。
- `eva008_data_pipeline.py` / `eva008_data_request_template.json`：仅统一改名，逻辑不变。

**结果 / 结论（关键根因）**
- 实时脚本读的是**终端实时缓存**（缓存深度有限、深层历史不自动拉满），测试器装载的是**测试器缓存**（完整 2014→今）。**两套缓存互不相通** —— 这就是用户"先跑 real-ticks 回测再跑脚本"也没用的原因。EA 在测试器里能看到完整历史且**可以写文件**，这是拿到完整 Exness 数据的可靠途径。
- 数据量口径澄清：`tick_volume` = **价格变化次数**，不是真实成交量；全程用 Exness 自己的数据，不换 Dukascopy（口径不同会脱离实盘）。

### 【目录 4 代】eva008 build v3.2 · 真实风险量化（浮亏 = 头号风险被证实）

**改了什么 / 为什么**

### 【目录 5 代】eva009 · 发现「趋势门控机制已存在但从未触发」+ 新增 followup

**改了什么 / 为什么**
- `eva009_data_pipeline.py`：新增 `MODE="followup"`（平仓后价格路径分析：给定出场原因，从 `exit_time` 往后扫多个时窗，输出是否/多久回到入场价、继续扛到各时窗的盈亏、继续扛期间额外浮亏）。新增 CONFIG：`FOLLOWUP_SRC` / `FOLLOWUP_EXIT_REASONS`（默认 pacing_panic_stop）/ `FOLLOWUP_HORIZONS_H`（默认 [1,2,4,8,24,48,72]）/ `FOLLOWUP_TF`。

**重大机制发现**
- 源码里**已经有**「趋势确认后平掉逆势网格」（`InpCloseOppositeGridOnTrend`，函数在状态机切换处触发 `trend_close_opposite_grid`），且 `true01_2.set` 里该开关 = **true**。
- **但全样本 1223 笔里 `trend_close_opposite_grid` 出现 0 次**——从未真正触发。原因：趋势状态机太慢（M5 周期、`InpTrendBreakoutBars=45` ≈ 3.75 小时突破窗、`InpTrendConfirmBars=4`、`InpTrendMinRVRatio=1.0`）。等它"官方确认"下跌趋势时，网格多单早被 `pacing_panic_stop`（**平均只扛 209 秒**）砍掉或已 TP 回归。
- **含义**：用户"用趋势决定网格平仓"的想法**正是该策略的设计本意**，只是探测器被调得太迟钝，等于没在保护网格；而粗暴的 `pacing_panic_stop` 在替它干活、且干得很糟。

**趋势单诊断（按持仓时长分箱，280 笔 —— 铁证）**

| 持仓 | 笔数 | 净 PnL | 胜率 |
|---|---|---|---|
| <5 分钟 | 66 | **−180** | 9% |
| 5–15 分钟 | 58 | **−201** | 10% |
| 15–30 分钟 | 53 | +28 | 36% |
| 30–60 分钟 | 65 | +61 | 55% |
| **>60 分钟** | 38 | **+360** | **76%** |

**结论：趋势的"进场"没问题，是"止损太紧/太快"** —— 好单子在噪声里被 `sl` 提前震出（207 笔 sl vs 73 笔 trend_state_exit）。

**其他约定**
- **回测一律固定手数（0.01）、不开复利**（用户口径，已采纳）：若开复利，亏损时分不清是"复利放大"还是"策略本身"的问题；固定手数能把策略质量与资金管理**解耦**。复利是上实盘后的独立决策。
- 趋势参数优化方向：`InpTrendSL_ATR_Mult` 1.8→**2.5–3.5**、`InpTrendTrail_ATR_Mult` 1.6→**2.0–3.0**；给"网格门控"用的趋势要**快**、给"独立趋势单"用的可以**稳**（必要时拆两组参数）。
- 抗过拟合方法菜单：walk-forward 滚动验证；参数敏感性（高原 vs 尖峰）；按波动体制分层评估；**减自由度**（三档十几个参数 → 绑定系数）；成交序列 Bootstrap/蒙特卡洛。

**R1：波动率度量改"对数收益百分比波动 + 固定百分比阈值"**

- 有一条**基线 `G_Baseline`**（近 N 分钟均价）。价格跌破基线一个"网格间距" → 开多（赌回归）；继续跌 → 按马丁加多（间距 × `grid_exp_coef^count`、手数 × `multiplier`）。空头对称。

- **亏钱条件**：价格单边趋势走开 → 马丁不断加亏损单 → 浮亏堆积/爆仓。
- **波动档位的作用**：高波动 = 震荡幅度大 → 网格收割得动；低波动 = 价格几乎不动 → 小网格只在赚点差的反面 churn；趋势 = 马丁 death。

### 【目录 16 代】无新代码 · 彻底读懂代码、完整复述策略、给出干净统一模型设计

**完整策略复述（读源码后的准确版）**
- **(a) 基线 `G_Baseline`**：初始 = 近 `x_minutes` 分钟均价（`RecalculateBaselineByMinutes`）。**每分钟 `AdjustBaseline()` 调整一次**：
  - **空仓时**：价格在基线上方 → 基线 `+= move_points_b`；下方 → `-= move_points_b`。即**基线以 `move_points_b`/分钟的速度追价** → 缓慢上涨时基线跟着涨，价格不会远离基线、就不开单，**避免与慢趋势对赌**。
  - **持仓时**：按净持仓方向，基线朝持仓那侧移动 `Σ coef_c × coef_decay^i`（随净仓数递减）→ 缩短回归目标、帮已开的仓更容易回到基线平掉。
- **(b) 开网格（回归开单）**：空仓/已有同向仓时，价格**跌破** `baseline − 网格距` 开多；**涨破** `baseline + 网格距` 开空。网格距 = `base_grid_z × point × multiplier_a × grid_exp_coef^已有仓数`（越加越远，马丁）；手数随 `multiplier` 放大。
  - **能否开单取决于"价格偏离基线的速度" vs "基线追价速度(`move_points_b`)"**：偏离够快才触发；慢漂移被基线追上 → 不开。**所以 `base_grid_z` 与 `move_points_b` 必须匹配**（eva017 正是把前者放大、没动后者 → 失衡 → 不开单）。
- **(c) 出场**：主要靠**价格回到基线**。`base_profit` 是很大、几乎不触发的止盈上限。另有分级风控 `risk_l2/l3`、`last_order_stop`、冷静期。
- **(d) 三档 + 切换**：低/中/高各一套参数，用 RV 判档切换。
- **(e) 单边趋势反制（后加）**：检测到单边趋势 → 停止逆势回归、并**顺势开单**（`InpEnableTrendOrders`）、平掉逆势网格（`trend_close_opposite_grid`）、禁止逆势加仓（`InpBlockAgainstTrendGrid`）→ 把"趋势中马丁亏损"转成"顺势盈利"。

**统一模型设计（哪些字段该随波动缩放 —— 它们都是"点数=价格距离"）**

| 字段 | 含义 | 统一模型 |
|---|---|---|
| `base_grid_z` | 网格距 | `k_grid × RV` |
| `move_points_b` | 空仓基线追价速度 | `k_move × RV`（**关键：必须和网格距一起缩放，否则失衡不开单**） |
| `coef_c` | 持仓基线调整 | `k_coef × RV` |
| `base_profit` | 回归止盈上限 | `k_tp × RV`（或保留单一大值；待定） |

regime-无关、收敛为**单一值**：`grid_exp_coef`、`coef_decay`、`max_total_positions`、`lot_size`、`x_minutes`、`multiplier` 那套、`delays`、`risk_l2/l3`、`last_order_loss`、`cooldowns`。
→ 结果：**1 个基线窗口 + 4 个波动系数 + ~12 个单一参数**，取代 72 个硬编码；**删除** `LoadMid/HighVolParams`、44 个 `InpMid*/InpHigh*`、判档切换 `InpVolPct_*` 及 `UpdateVolatilityRegime` 的判档/切换逻辑（趋势反制不依赖 vol 档位，保留）。

**待用户拍板三点**：①`base_profit` 随波动缩放还是保留单一大值（倾向保留单一大值）；②`InpVolPct_*` / 判档逻辑是否整段删除（倾向删）；③`InpUnifiedVolModel` 开关是否保留（要"干净"就彻底删三档）。

### 【目录 21 代】eva022 · 定位并修复「趋势从不触发」的根因（量纲错配 bug）

**止损机制逐字确认（用户理解正确）**
```
max_n   = max_total_positions                       // 例如 3
geom    = Σ_{k=0}^{max_n-1} coef^k                   // coef=grid_exp_coef=1.4 → 1+1.4+1.96=4.36
cum_dist= base_grid_z × point × mult_cap × geom      // 到"第 max_n 单"的累计网格距
last_line = baseline ∓ cum_dist                      // 虚拟末单线(多:基线下方; 空:上方)
loss_dist = last_order_loss_per_lot 换算成价格        // 越过末单线后再容忍的亏损缓冲
止损触发  = 价格越过 (last_line ∓ loss_dist)
```
- **确认：完全是这样。** 即使只开了第 1 单，止损线**仍按"假设一直加到第 max_n(第3)单"的累计距离来算**，再加一段 `last_order_loss_per_lot` 缓冲 → 止损位与实际开了几单无关。

**趋势从不触发的根因（是 bug，不只是调参）**
```
if(InpTrendUseRVFilter)
   rv_ok = (G_RVRatio >= InpTrendMinRVRatio);   // 趋势信号必须 rv_ok
```
- `G_RVRatio` 自 **eva019** 起被改成"百分比波动" `= 100 × rv_short × point / price`，实测分布：中位 **0.016**、95 分位 **0.025**（enrich 的 `rv_ratio` 列 = G_RVRatio，已逐行核对）。
- 而 `InpTrendMinRVRatio` 默认 **1.35**（用户 set 用 1）。**0.01~0.03 永远 < 1** → `rv_ok` 恒 false → `up_signal/down_signal` 恒 false → **趋势永远不确认**。
- 这是 eva019 改 `G_RVRatio` 量纲后遗留的**单位错配**。
- **修复（唯一改动）**：`InpTrendMinRVRatio` 默认 `1.35 → 0.020`。阈值参考：取 0.024 → 约 7% 时段开闸；0.015 → 约 50%；0.030 → 约 1%。也可 `InpTrendUseRVFilter=false` 完全去掉这道闸做对照。

**钳制函数数值例（GridZ=350、RefVol=0.024、指数 2.7）**

| 0.006(极低) | 0.25 | 0.024 | **0.5** | 不再塌成 1pt |
| 0.012(低) | 0.50 | 0.16 | **0.5** | 托住 |
| 0.024(参考) | 1.00 | 1.00 | 1.00 | 正好 350pt |
| 0.036(高) | 1.50 | 3.0 | **3.0** | 封顶,不爆 |
| 0.060(极高) | 2.50 | 11.6 | **3.0** | 不再冲到 $62 |

**评分跨时长的关键在"除法"**：`expectancy = profit / n_trades`；`avg_sq_depth = sum_sq_depth / dd_episodes`；`tpd = n_trades / days`。

**一句话**：把评价函数从"鼓励多交易、按绝对金额算收益/回撤"改成：**收益按年化取 log 平滑；风险全部用百分比；回撤 20% 以内不惩罚，超过后连续、非线性、越接近爆仓越陡；交易频次只做月均区间约束；风险出口（末单/截止/砍单）按出场原因惩罚，砍单按 0.5 折算而非直接判死。**

```
FinalScore = ProfitScore − FinalLossPenalty − MaxDDPenalty − EpisodeDDPenalty
           − UnderwaterPenalty − TooFewTradesPenalty − TooManyTradesPenalty − TailExitPenalty
```
- `ProfitScore = W_profit · log(1 + max(0, 年化收益) / 目标年化)`
- `FinalLossPenalty = W_loss · ( LossPct/(1−LossPct) )^P_loss`
- `MaxDDPenalty = W_maxdd · ( max(0, MaxDD − 免费MaxDD)/(1−MaxDD) )^P_maxdd`
- `EpisodeDDPenalty = W_episode · Σ ( max(0, 单次DD − 免费Episode)/(1−单次DD) )^P_episode`
- `UnderwaterPenalty = W_underwater · ( max(0, 水下比 − 免费水下比) )^P_underwater`
- `TooFew = W_lowfreq · ( max(0, MinTPM/TPM − 1) )^P_freq`；`TooMany = W_highfreq · ( max(0, TPM/MaxTPM − 1) )^P_freq`
- `TailExitPenalty = W_tail · ( 年化尾损% )^P_tail`，**年化尾损% = (末单损 + 截止损 + CutWeight·砍单损) / 初始资金 / 年数**
- **对原始需求的修正**：原始 `TailLossPct = 尾损/初始资金` 是"全程累计量"，回测越长越虚高，与已年化的收益项口径不一致 → **÷年数**年化。

**指标计算层可靠性**：净利/年化收益 ✅ `STAT_PROFIT / STAT_INITIAL_DEPOSIT`；最大回撤% ✅ **最准** `STAT_EQUITY_DDREL_PERCENT`（官方逐 tick、峰值相对）；回撤事件数/深度 ⚠️ **近似**（由 OnTick 按间隔采样的净值曲线重建，MT5 无官方统计）；最长水下时间 ⚠️ 近似；月均交易数 ✅ `STAT_TRADES / 月数`；尾损 ✅ 三个出场点**平仓前累计浮动 PnL**（**不依赖审计，优化时也生效**）。
**关键工程点**：EA 审计日志在优化时被强制关闭，所以 `exit_reason` 落盘拆分在优化时不可用 → 新增**独立测量层**（`ScoreSampleEquity` + 三出场点 `ScoreSumFloatingPnL` 累计），纯读取、不改交易行为、**优化时同样运行**。采样精度默认 `InpScoreEquitySampleMinutes=60`。

**新增 input（第一版起点）**：`InpUseNewScore=true`、`InpScoreTargetAnnualReturn=0.20`、`InpScoreMinTotalTrades2=30`、`InpScoreFreeMaxDDPct=0.20`、`InpScoreFreeEpisodeDDPct=0.10`、`InpScoreFreeUnderwaterRatio=0.15`、`InpScoreMinTradesPerMonth=8`、`InpScoreMaxTradesPerMonth=45`、权重 `Profit=100 / Loss=100 / MaxDD=150 / EpisodeDD=30 / Underwater=50 / LowFreq=20 / HighFreq=50 / TailExit=50`、幂次 `Loss=2.0 / MaxDD=2.0 / EpisodeDD=1.5 / Underwater=1.5 / Freq=2.0 / Tail=1.5`、`InpScoreCutLossWeight=0.5`、`InpScoreEquitySampleCap=200000`。
（35 代版本追加：**所有金额型收益与风险项统一用固定参考资金 `InpScoreReferenceCapital` 归一**；**MaxDD 由 `STAT_EQUITY_DDREL_PERCENT` 改为 `STAT_EQUITY_DD / score_capital`（金额/固定参考资金），含 [0,0.999] 钳制与 fallback**。）

## A. 策略解剖（截至最后有文档的一代 eva025a 的精确机制）

**类型**：基线均值回归网格 + 马丁（"网格/现金牛"），叠加一个趋势状态机作为反制层，外加多层硬风控与审计落盘。两套独立 Magic（网格 `InpMagicNum=123456`、趋势 `InpTrendMagicNum=223456`），互不干扰平仓。周期 M1，趋势判定周期 M5。

**① 基线 `G_Baseline`**：初始 = 近 `InpX_Minutes` 分钟均价（`RecalculateBaselineByMinutes`，eva019 起为 **40 分钟**）。之后**每分钟** `AdjustBaseline()` 调整一次：
- **空仓时**：基线以 `move_points_b`（= `InpMoveB × 价/参考价 × 波动因子`，`InpMoveB=130`，随波动指数 0.8）**朝现价追价**——缓慢漂移时基线追上去，价格就不会远离基线、于是**不开单**（避免与慢趋势对赌）；
- **持仓时**：基线朝**亏损方向**移动 `Σ coef_c × coef_decay^i`（净仓数 i，`InpCoefC=63`、`InpCoefDecay=0.85`）——套牢越深移得越多，把整篮 TP 目标拉向现价帮其出场。**这是"砍仓有效"的机制根源。**

**② 网格开仓触发**：多单条件 `allow_grid_buy && bid < G_Baseline`，且首单（`buy_count==0`）要求 `bid < G_Baseline − final_grid_distance`，加仓要求 `bid < last_buy_price − final_grid_distance`；空单对称。
- `final_grid_distance = base_grid_z × point × multiplier_a × InpUniGridExpCoef^已有仓数`（马丁：越加越远；`InpUniGridExpCoef` 默认 1.4，a8 实测 1.0）。
- **网格距 `base_grid_z`（eva019 起）**：`base_grid_z = max( InpMinGridZ × (价/InpRefPrice), InpGridZ × (价/InpRefPrice) × vf_grid )`，其中 `vf_grid = ratio^(InpGridExpLow + InpGridExpSlope×ratio)`，`ratio = 当前波动%/InpRefVolPct`，上限 `InpVolFactorMax=40`。`InpRefPrice=4000`、`InpRefVolPct=0.024`。**常/低波动由 `InpMinGridZ` 地板接管（防塌陷 churn），高波动由 `InpGridZ × 因子` 接管（InpGridZ = 风暴时网格扩张倍率）。**
- **`multiplier_a`**：`avg_volume / base_avg_volume` 取 `InpMultiplierExp` 次幂，**下限地板 1.0（只放大不缩小）**；实测中位 1.17、最大 1.38、≈1 的占 39% → **实际几乎无缩放作用**。
- 开仓前过一串门闸：风险等级 L2+ 禁开、冷静期禁开、档位不允许禁开、量不足处理、总持仓上限（`InpUniMaxPos`，eva020 起固化 **3**）、`CheckAddPacingDelay`（加仓延迟门闸）、`InpBlockAgainstTrendGrid` 逆势方向门禁。
- 手数：固定 **0.01**，`InpUseDynamicLot=false`，**不开复利**（把策略质量与资金管理解耦）。

**③ 篮子止盈（现金牛核心，真正的主出场）**：`OnTick` 中，有多单且 `bid ≥ G_Baseline` → `EvaSetExit("grid_tp_baseline_revert")` + 平掉**该方向全部**网格单，return；空单且 `ask ≤ G_Baseline` 同理。即**"价格回到基线就把该方向整篮平掉"**，高胜率小利的来源（实测胜率 81.5~87.4%，PF 4.58~6.92）。`base_profit`（`InpUniBaseProfit=200000` 折算成 `tp_dist`）是**几乎不触发的止盈上限**，不是真正出场点。`InpMaxGridBasketLossMoney`（$20~40 整篮金额止损）是 eva028 才加的新机制。

**④ 趋势状态机信号**：在 M5（`InpTrendTimeframe=5`）上：
- `breakout_up = close[1] > 最近 InpTrendBreakoutBars 根的最高`（`InpTrendBreakoutBars`，真严格应 30~50，实测被优化器压到 2~13）；
- `ema_up = 快 EMA(20/15) > 慢 EMA(60/70) 且慢 EMA 比 InpTrendSlowSlopeLookback 根前更高`；
- `rv_ok = G_RVRatio ≥ InpTrendMinRVRatio`（0.013~0.030，**默认 0.020**；eva019 曾因此量纲错配导致趋势永不确认）；
- **`up_signal = rv_ok && ema_up && breakout_up`**（三条全满足），down 对称；
- 连续 `InpTrendConfirmBars` 根（真严格应 3~4，实测 2）→ 切 TREND_UP/DOWN；`exit_up = fast<slow`（或 `InpTrendExitOnFastEMA` 时 `close<fast` 也退出）；
- **eva025a 新增三个 AND 机制**：`mtf_up`（M15 EMA20/60 同向，`InpUseMTFConfirm`）、`adx_ok`（`ADX ≥ InpMinADX=25`，`InpUseADXFilter`）、`sep_ok`（`|快−慢| ≥ InpMinEMASepATR=0.5 × ATR`，`InpUseEMASepFilter`）。**实测 8 组寻参把这三个全部架空（MTF 全关、MinADX 10~15、EMASep 0.1~0.2）→ 机制未被真正验证。**

**⑤ 趋势层的三个出口**
1. **禁止逆势网格开新单**（`InpBlockAgainstTrendGrid`，默认 true）：趋势涨 → `allow_grid_sell=false`；趋势跌 → `allow_grid_buy=false`。
2. **砍逆势网格**（`InpCloseOppositeGridOnTrend`，默认 true，`CutOppositeGrid()`）：**仅在状态机切换到趋势的"同一瞬间"触发**（切 TREND_UP → 平所有 SELL 网格；切 TREND_DOWN → 平所有 BUY 网格），**ticket 级全砍、无部分平仓**（0.01 最小手数约束下的唯一正确形态）；出场原因 `trend_close_opposite_grid`（eva025 修 bug 后才能正确落盘）。eva025b 额外提供 `InpCutUseStrictTrend` 用"更严格更晚确认"的独立趋势专管砍仓。
3. **独立顺势趋势单**（`InpEnableTrendOrders`，默认 true，`ManageTrendOrders()`）：状态切 TREND_UP 且无趋势多单 → 开趋势多单，ATR 止损 `InpTrendSL_ATR_Mult`（实测 3.4~3.7）、移动止损 `InpTrendTrail_ATR_Mult`（实测 3.1~3.2，只升不降）、`InpTrendTP_ATR_Mult=0`（**无固定止盈，靠反转才平**）；`InpTrendCloseOnStateExit` 时状态回 RANGE 或翻向即平（出场原因 `trend_state_exit`），`InpTrendMaxPositions=1`。
- **关键耦合**：状态切到 TREND_UP 的**同一瞬间**既砍空网格、又开趋势多单 → **趋势单的对错 = 砍单的对错；趋势单胜率（33~40%）≈ 砍单准确率**。

**⑥ 风险等级与硬止损链**（`OnTick` 顺序）
- `GetCurrentRiskLevel()`：量 > `InpMaxAvgVolumePerMin`（或周一重开窗）→ **L2（禁开）**；周五收盘前 → **L3**；**L4（周五收盘前 30 分）→ `CloseAllStrategyPositions()` + 平趋势单，return**。
- `ClosePositionsNotAllowedByActiveProfile`：清掉当前档位不该留的仓。
- **`last_order_stop`**（`CheckLastOrderStopAndCooldown`）：达最大持仓数且**最后一单浮亏 ≥ `InpLastOrderLossPerLot × 手数`** → 全平 + 冷静期。
- **`cutoff_line_stop`**（`CheckCutoffLineStopAndCooldown`）：算"满仓时末单相对基线的**累计网格距** `base_grid_z × point × mult_cap × Σcoef^k`"得一条**虚拟止损线**，再加 `last_order_loss_per_lot` 缓冲；**价格越线即全平，不需先达满仓**。⚠ 止损位**与实际开了几单无关**，且**随网格距放大**（GridZ 5500 时末单线离基线约 $33 → 单笔尾亏 −$15~−$17，最差 −$106）。
- `ManageRiskByLevel()`：L2/L3 风险下平盈利/亏损单（`risk2_take_profit` / `risk3_take_profit` / `risk3_cut_loss` / `risk4_force_exit`）。
- **`max_cluster_floating_stop`**（eva010 新增，`InpMaxClusterFloatingUSD`，默认 $200）：汇总网格持仓 `POSITION_PROFIT+SWAP`，簇浮亏 ≤ −$200 即全平 + 冷静期。**实测它比趋势门控先触发**（价格几分钟跌 $200，趋势要等 K 线确认）→ 用户担心的"固定美元止损"反而成了实际起作用的保护。
- **已删除的同类机制**：`pacing_panic_stop`（加仓延迟窗内价格冲过"下一单+下下单"位置 → 全平 + 冷静期，**硬编码无开关**，eva019 里 714 笔全部亏损 −$868；eva020 删除）、`overshoot_stop`（`CheckMaxPositionsOvershootStop`，pacing 的孪生，eva021 删除）。
- 另有：加仓延迟门闸 `CheckAddPacingDelay`（`InpDelayOrder2/3/4Minutes`）、平常冷静期 `InpCooldown` / 大冷静期 `InpBigCooldown`、周末守护 `InpUseWeekendGuard`、`MaybeResetBaselineOnReopen`。
- **eva028 阶段1 新增**：网格整篮金额止损（`InpMaxGridBasketLossMoney` $20~40，冷静期 1440 分钟）、策略日损停止（$20）、账户净值高水位回撤锁（15%，**触发后不会因重启 MT5 自动解除**）。

**⑦ 评分（OnTester）**：`score = expectancy^p × D_max × D_freq × T_freq × S`，`expectancy = profit/n_trades`、`avg_sq_depth = Σ深度²/回撤段数`、`tpd = n_trades/days` —— 三项都是"率/均值"，**跨回测时长可比**（eva016 改造）。eva027 的 ScoreV2 进一步改为**年化 log 收益 + 全部百分比风险 + 20% 免费回撤区 + 非线性惩罚 + 水下时间惩罚 + 月均交易区间约束 + 按出场原因的年化尾损惩罚（砍单按 0.5 折算）**。

**⑧ 审计层**：`EvaCaptureGridPending/EvaCaptureTrendPending` 在下单点抓拍上下文（档位/RV/state/mult/网格距…），`EvaBindEntry` 按 `position_id` 绑定，`EvaOnDealAdd`（`OnTradeTransaction`）出场落盘一行；**优化模式自动关闭**（`MQL_OPTIMIZATION` 检测）；eva025 起出场原因按仓位记录（`pending_exit`）修正了"被砍网格错标 `trend_state_exit`"的 bug。

## B. 已确认的发现（高置信、跨代复现）

- **网格回归 `grid_tp_baseline_revert` 是唯一稳定的正期望来源，且每一年都为正。** eva024 7 组合计 **+$47,179**（11171 笔，胜率 **87.4%**，单均 +$4.22，**PF 6.92**）；单代样本 629~7102 笔、净 +$835~+$4802；eva025a 三分类网格栏 **+4410（1706 笔，胜率 81.5%，PF 4.58）**；eva027 两套参数**每一年**均为正（+583 ~ +2265）。
- **尾部出口（砍单 + 末单 + 截止）每年、每代都为负，是唯一持续放血点。** eva027：每年 −$853 ~ −$2,103；eva024 7 组：`trend_state_exit`（网格被砍）−$37,452 + `last_order_stop` −$2,540；eva019：`pacing_panic_stop` −$867.8 与 `cutoff_line_stop` −$207.6 合计吃掉几乎全部网格利润（+$835.4）。
- **边缘只在高波动体制（regime 2），中低波动长期漏血。** eva002 `true01_2`：regime2 仅 122 笔却贡献 **+2817（65%）**、胜率 83.6%；eva016 全程：regime1 **PF 0.90 亏 −413**，regime2 PF 1.29 赚 +1211；eva011：regime2 **PF 1.94**（117 笔 +1070）、regime1 PF 1.15、regime0 PF 1.14；eva025a（a2）网格胜率 81.5%。**"74% 利润来自高波动档（仅占 14% 成交）"、"最赚 2 个月占 90% 净利"**。
- **利润高度集中于极少数月份。** eva002：**2026-02(+1227) + 2026-03(+1563) = +2790 ≈ 65% 总利润**；eva024.3：**2026-02 单月 +$935** 贡献很大比例；eva011：最赚 2 个月 = 90% 净利。
- **样本外（OOS）长期接近打平或为负，是跨 30+ 代的固定结论。** eva002：**样本外合并 PF 1.10**（前段 2024 PF 0.90 亏 −40）、训练内 PF 2.75；eva011：样本外·后 **PF 0.95 / −36**；eva016：样本内 PF 1.12 / OOS 后 1.18 / OOS 前 2024 **PF 0.78**；eva010.1：样本内 PF 1.65 但样本外·后 **PF 0.91 / −94**；eva025b：测试集 **−27/+66/−68 ≈ 0**；eva027：单年训练参数样本外趋近于零甚至为负。
- **真实的头号风险是浮亏（权益回撤），不是已实现回撤。** 单仓 MAE 中位 **$4.7**、p90 $23、p95 $35、p99 $86、**最大 $266.7**；**63%（769/1216）的单子曾浮亏 ≥ $3**，其中 **54% 最终仍翻红**；簇级峰值浮亏最深 **$338.9（= $400 账户的 85%）**，**6 个簇 > $200、13 个簇 > $100**。已实现权益曲线（+4316）**严重低估真实风险**。
- **两种回撤朝相反方向变：已实现回撤 −245→−360（占净利比 5.7%→24.8%），但浮亏峰值 $338.9→$200.1、地板 $346→$375。** 去险后"会不会爆仓"更安全，但**净利掉 66%（4316→1450）** —— **旧版那 +4316 里很大一块本就是"扛 $339 浮亏赌回归"赚来的**（马丁本质）。
- **趋势单的进场逻辑没问题，问题是止损太紧。** 按持仓时长分箱（280 笔）：<5 分钟 **−180（9%）**、5–15 分钟 **−201（10%）**、15–30 分钟 +28（36%）、30–60 分钟 +61（55%）、**>60 分钟 +360（76%）**。207 笔 `sl` vs 73 笔 `trend_state_exit`。→ 放宽 `InpTrendSL_ATR_Mult` 1.8→2.5~3.5 是数据最支持的一步（eva010 已实施为 3.00）。
- **趋势机制已存在但曾被完全架空；激活后净利首次转正。** `InpCloseOppositeGridOnTrend=true` 在 eva002 全样本 **1223 笔里触发 0 次**（状态机太慢：BreakoutBars=45 ≈3.75h + ConfirmBars=4 + MinRVRatio=1.0，而 pacing 平均只扛 209 秒）。修复量纲错配（`InpTrendMinRVRatio` 1.35→0.020）并让趋势单"让位"后，**eva011 触发 179 次**，**eva023 净利首次转正 +$98**，灾难尾部基本消失（`cutoff_line_stop` 34 笔/−$1523 → **2 笔/−$39**；`last_order_stop` 60 笔/−$1474 → **18 笔/−$373**）。
- **"砍仓"净正确，不可一刀切关掉。** 关砍对照（.9f vs .9）：被砍的 898 笔网格大多回去回归了（回归笔数 1546→2377），**但回归账本胜率 86.5%→71.6%、利润 +$6276→+$2207**，并冒出 `cutoff_line_stop`(−$1115) + `last_order_stop`(−$692) 深尾灾难。关砍组净利 +$377~+$1003/组（即砍仓净正）。**机制：逆势网格堆积 → 基线被拖着追趋势 → 篮 TP 漂移 + 回归质量塌 + 深尾灾难；砍掉 = 基线干净重置。**
- **深水网格约 2/3 最终回归获利、1/3 被砍，但被砍的 1/3 集中了几乎全部砍单亏损。** eva025a 跨 8 组：回归占比 **66~70%**；被砍 1/3 贡献 **−$3.1k~−$3.4k/组**。a8 因网格更宽，深水回归单赚 **+$1601**（其它仅 +$323~573）。
- **"pacing_panic 该不该砍"被 followup 定量回答：砍得净正确、但判据太粗。** 18 笔中 **7/18（39%）72h 内从未回到入场价**（真单边，砍对）；但 **7/18（39%）1h 内就回到入场价**（噪声坑，砍早）。实际砍 −420，继续扛到任何时窗**合计都更亏**（8h −715、4h −767），且过程多吃 $60–480 浮亏。→ 判据应从"价格冲过两格"换成"趋势是否确认"。
- **趋势侧占全程利润 40~45%，不是小补贴。** eva024 逐组：41% / 44% / 38% / 42% / **53%** / 49% / 41%；趋势单胜率 33~39%，靠**不对称盈利**（最大赢 +$75~89 vs 最大亏 −$23~27）。eva025a 趋势栏 **+1007~+1436**（eva024.9 为 +826，接近翻倍）。
- **趋势单胜率 = 砍单准确率。** 代码层面：状态切到 TREND_UP 的同一刻，`CutOppositeGrid` 与 `ManageTrendOrders` 同时动作 → **趋势单对错 = 砍单对错**。提高趋势精度同时改善"趋势侧 ~45% 利润"与"砍单准确率"，是高杠杆方向。
- **砍仓频次是零和：砍多→误砍浪费；砍少→尾部漏出；净额守恒。** eva024(898 笔砍) vs eva025b(236~342 笔砍)：砍单亏损 **−4982 → −2300~−3447**（变小），但尾部 **≈0 → −$1.5k~−$2.5k**（变大）；总净利同量级（+1.5k~+2.4k vs +1486~+2386）。→ **单纯调"砍多少"动不了大局，能动针的只有"砍得更准"。**
- **马丁加仓从未失控，不是风险源。** eva024 7 组：第 1 单 26,718 笔、第 2 单 1747 笔（**avg +$1.47，盈利**）、第 3 单仅 85 笔；eva025a：第 1 单 ~3490 笔、第 2 单仅 84 笔、第 3 单个位数。`multiplier_a` 地板在 1.0（只放大不缩小），实测中位 1.17/最大 1.38。→ **"收紧马丁深度"不是主要矛盾**（`MaxPos=1` 时仅首单仍净 −$585 / PF 0.93）。
- **问题是"小赢对大亏"的结构性负偏。** eva020 寻参后：`grid_tp_baseline_revert` **+$4802（7102 笔，单均 +$0.68）** vs `last_order_stop` **−$3754（258 笔，单均 −$14.55）** + `cutoff_line_stop` **−$2330（136 笔，单均 −$17.13）** → 净 −$1041。394 笔尾部单亏 −$6085（最差单 −$106）。
- **"TP 太近/提前止盈"已被明确排除，不要优先动 TP。** 盈利单 `capture_ratio` 中位 **0.92**，仅 **10.4%** 的盈利单兑现 < 30%，`early_exit` 仅 30 笔。
- **宽网格提升胜率的同时把止损线推远、放大尾亏 —— 同一枚硬币的两面。** GridZ 5500：胜率 41.8%→**69.6%**，但截止线被推到离基线约 **$33**（cutoff 单 MAE 中位 $6.8、last_order 单 MAE 中位 $12.8），单笔尾亏 −$15~−$17。
- **评估口径必须只看已实现盈亏会严重误导；MAE/簇浮亏必须逐 tick 路径才能看到。** 成交表**不含开仓簇运行期间的浮亏**。
- **回测必须固定手数、不开复利**（隔离"策略问题 vs 复利问题"）；**研究阶段用高本金（如 $100k）** 避免提前爆仓中断——因为固定手数下本金高低不改变下单行为。
- **数据事实**：有效数据起点 = **2017-05**（更早 `tick_volume` 异常偏低，判定为问题数据，一律丢弃）；Exness 黄金**真实 tick 仅回溯近几年**，M1/M5 可回溯到 2010 年代初；本品种 **point=0.001（3 位）**。

## D. 反复出现的元问题：「第 N 次」——参数优化器反复架空精度参数

**症状**：任何"提高信号精度"的参数只要留在 MT5 优化空间里，优化器就**必然把它们拉到最低**——因为更灵敏的信号能在训练窗口内压住尾部、抬高 OnTester 分数（旧评分奖励高频、只惩罚**已实现**回撤、不惩罚浮亏/水下/尾部）。结果是"提精度"的实验从来没被真正测试过。

**已给出的对策（跨代反复重申）**
1. **把精度参数从优化空间移出、固定成有意义的值**（eva025a 方法1：`InpUseMTFConfirm=true`、`InpMinADX=25`、`InpTrendBreakoutBars=30`、`InpTrendConfirmBars=3` 全部固定，只优化网格/趋势管理参数）。
2. **限定窄范围**（如 breakout ∈ [30, 80]、`InpMinADX ∈ [22,30]`），别让优化器把阈值压到 0。
3. **不要只提交"加成"**（"严格参数下限钳制"被明确否决：治标不治本，优化器仍可让两者都低）。
4. **改评分函数，从根上去掉这个激励**（eva027 ScoreV2：全部百分比口径 + 20% 免费回撤区 + 非线性惩罚 + **水下时间惩罚** + **月均交易区间约束** + **按出场原因的年化尾损惩罚**）
    - 实测复评：train2024 / train2023 在新评分下**都是负分**，**主导减项是旧评分没有的"过密"（−40.5）与"水下"（−18.7）** —— 正是把优化器从"小网格高频"推开的力。
5. **优化范围必须真的覆盖"更宽网格 / 更少持仓"**（`InpGridZ`、`InpMinGridZ`、`InpUniGridExpCoef`、`InpUniMaxPos` 都要放开），否则新评分想选的参数根本不在搜索空间里。
6. **方法2 离线反事实诊断**（`eva025_signal_diagnose.py`：用原始 m1 重算 ADX/MTF/EMA 间距落到每笔趋势单入场，输出 ADX 分桶胜率 + "要求 ADX≥阈值 / MTF 同向"的**移除集净贡献**），用数据给固定阈值定标，而不是拍脑袋。

### G.2 行情仓库结构
```
eva_data/<SYMBOL>/
  ticks/YYYY-MM.csv   time_msc,time_iso,bid,ask,last,volume,volume_real,flags,spread_pts
  m1/YYYY-MM.csv      同上 bar 结构
  m5/YYYY-MM.csv
  m15/YYYY-MM.csv
  meta.json           symbol, symbol_digits, output_digits, point, exported_by,
                      bar_first_date, bar_last_date, tick_first_date, tick_last_date,
                      total_ticks, total_bars, generated
bar CSV 字段：time,time_iso,open,high,low,close,tick_volume,spread,real_volume
```
- 按 `品种/周期/月` 分块，便于只读需要的月份、多机并行、多参数批量复用同一份仓库。
- **官方接口导出**（`CopyTicksRange(COPY_TICKS_ALL)` / `CopyRates`），**不解析 MT5 底层私有文件**。
- 精度无损：`time_msc` 写毫秒整数；价格按 `Digits` 全精度（输出位数 = `max(Digits, 3)`）。
- **导出必须在策略测试器里以 EA 运行**（`eva008_TickDataExporterEA.mq5`），Optimization=Disabled；A 跑 M1/M5 全程用 "1 minute OHLC"（最快，含真实 `tick_volume`）、B 跑真实 tick 只取近几年用 "Every tick based on real ticks"（其他模型产出的是合成 tick，不可用）。
- `tick_volume` = **价格变化次数**（Exness 口径），非真实成交量。

### G.3 回测输出（EA 审计层，`Common\Files\eva_audit\<run_id>\`）
- **`eva_trade_events.csv`**（43 列；eva026 起删 4 个常量列 + 增 `vol_gate_low`）：
  `run_id, strategy_version, param_set_id, symbol, timeframe, position_id, deal_in, deal_out, order_kind(grid/trend), direction(±1), entry_reason(grid_buy/grid_sell/trend_buy/trend_sell), exit_reason, deal_reason_raw(tp/sl/expert/…), order_number(网格加仓序号), entry_time, entry_time_msc, entry_price, exit_time, exit_time_msc, exit_price, volume, sl_price, tp_price, profit, commission, swap, net_pnl, holding_seconds, vol_regime, real_vol_regime, regime_open_allowed, market_state(0震荡1涨2跌), rv_short_pts, rv_long_pts, rv_ratio, multiplier_a, grid_dist_pts, tp_dist_pts, baseline_at_entry, risk_level_at_entry, avg_vol_per_min, spread_pts_at_entry, atr_at_entry`

- **关键约束**：**优化模式自动关闭审计**（检测 `MQL_OPTIMIZATION`），避免多 pass 抢同一文件；单次回测才输出明细。

### G.4 Python 流水线（`eva00X/eva013/eva014/eva025_data_pipeline.py`）的角色
**唯一入口 = 文件顶部 `MODE` 变量**（`enrich / aggregate / slice / request / cache / followup / volscan`）；`CONFIG` 区集中放 `ROOT/SYMBOL/POINT/PATH_TF/BIG_MOVE_USD/N_WORKERS/PROGRESS/VOLSCAN_*/FOLLOWUP_*`。**不在 EA 里输出 tick 路径**——行情与回测事件解耦，Python 按交易时间切片。

| MODE | 作用 | 产物 |
|---|---|---|
| **enrich** | 读 `eva_trade_events.csv`，对**每笔单**从仓库切持仓期间路径，算 MFE/MAE（点 & 美元）、`realized_move_usd`、`capture_ratio`（顺向兑现率）、`path_type`（clean_win/grind_win/clean_loss/immediate_reverse/gave_back）、`path_source`（tick / m1 回退）、`problem_tag`、`year` | `trade_enriched.csv`、`problem_trades.csv`、`signal_performance.csv`、`regime_performance.csv` |
| **aggregate** | 只出聚合表 | `signal_performance.csv`、`regime_performance.csv` |
| **slice** | 按"周期 + 区间"切一段行情落盘 | `seg.csv` |
| **request** | 读请求文件（`range` / `around_time` / `trade_path` 三型）批量产出 | 指定切片 + `manifest.json` |
| **cache** | CSV → parquet（MQL5 端不原生支持 parquet，故在 Python 侧做） | parquet |
| **followup** | **平仓后价格路径分析**：给定出场原因，从每笔 `exit_time` 往后扫多时窗，输出是否/多久回到入场价、若继续扛到各时窗的盈亏、继续扛期间额外浮亏 | `followup.csv` |
| **volscan** | 用与 EA **完全一致**的公式扫训练集内每分钟"百分比波动"，输出各分位(min/p5/p50/p95/max)、对多个窗口 W 做敏感性、给出 `InpVolPct_*` 阈值建议与寻参范围 | `volscan_summary.csv` + 控制台建议值 |

**关键计算口径**
- **`problem_tag`（互斥优先级）**：`deep_underwater`（不利行程 ≥ `BIG_MOVE_USD`=3.0 美元，马丁深水）> `gaveback_loss`（有大顺向却亏损）> `early_exit`（顺向到位但兑现 < 30%）> `normal` > `no_path`。
- **`signal_performance.csv`**：按 `order_kind × entry_reason` 聚合（n / net_pnl / win_rate / avg_pnl / max_loss / profit_factor）。
- **`regime_performance.csv`**：按 `vol_regime × real_vol_regime × market_state × year` 聚合（同上指标）；eva026 删掉 4 个常量列后**自动退化为 `market_state × year`**。
- **tick 缺失自动回退 m1**（老年份没有真实 tick 也能算近似 MFE/MAE，`path_source` 标注实际用了哪个）。
- **点值自动识别**：优先读 `<root>/<symbol>/meta.json` 的 `point`，缺省 0.001（3 位）；`--point>0` 可强制覆盖。
- **`R` 仅在该单有止损价或显式给 `--default-r-pts` 时计算**（网格单常无 SL，避免编造 R）。
- **性能工程**：按月分组、每月文件**只读一次**、`np.searchsorted` 在排序时间数组上取极值、`multiprocessing.Pool` 并行、`imap_unordered` + 进度条/ETA；`N_WORKERS`（0=自动 CPU−1 / 1=单进程 / >1 指定）。

### G.6 工程纪律约定（跨代累积）
1. **代际命名**：eva 编号 = 这一轮输出**所有产物**的代数；有代码改动默认进位；无新产物则整轮不进位；同代分叉用字母后缀（a/b）。
2. **参数书写规范**（8 代起）：凡提到要调的参数，一律写**完整英文变量名 + 中文释义**，不用缩写。
3. **控制变量法**：一次只动一块；每个新机制都带一个可一键回退的开关（`InpUsePctVolRegime` / `InpUnifiedVolModel` / `InpUseVolGrid` / `InpCutUseStrictTrend` / `InpUseVolGateForTrendSide` / `InpUseNewScore` 等）；连续几轮不重编译 EA 以避免污染对照。
4. **删任何机制 → 全链扫除**（枚举 / 前向声明 / 定义 / 全部调用点 / 日志 / run_config / 仪表盘 / 相关 input 与 .set），删完 grep 残留 = 0 自证。
5. **每个产代码的轮次，交付前跑死代码审计**：①未引用的 input；②孤儿函数（全文出现 ≤2 次 = 仅声明 + 定义）；③删某函数后它专属的 helper 是否变孤儿。审计结果写进日志。
6. **审计/测量代码不得影响优化速度**：审计写盘在优化模式自动关闭；评分测量层设计为纯读取、优化时也运行。
7. **不构成投资建议**；改动后必须在测试器充分验证；实盘与回测存在差异；上实盘前先模拟至少 2 周。
