## 1. `JSB30` 是什么（与已否证结构的关系）

**名称**：`JSB30` = **J**PY **S**ession **B**reakout on **M30**

**结构**：**时段突破**（time-of-day / session breakout），单仓、每日最多一笔。

**与 JPY 已否证结构的差别**：

| 已否证 | 否证证据 | `JSB30` 的差别 |
|---|---|---|
| `dsh_TrendCore`（趋势突破） | 298/691 达标 pass 中 PF>1 = 0 | 用**固定时段区间**定义突破位，而非 N 根 K 线极值 |
| `dsh_JPYRev`（价格均值回归） | 同上 | **逆势→顺势**，方向相反 |
| `dsh_JPYGrid`（交易网格） | 7/7 窗口「加交易」低于「不做交易」 | **单仓、每日最多一笔**，无加仓 |
| 全天候入场 | — | **只在固定时段窗内入场**（这是本项目**从未覆盖**的维度） |

**★诚实说明**：GPT §3 说「时段/事件结构是明确未覆盖的方向」。我核对了五条线的报告标题与结构描述，
**确认没有任何一条线以「时段窗」作为信号定义的主轴**。**但不等于它有效** —— 下面的预期失败机制给出了它最可能的死法。

## 2. 确切时段定义（本次设计的核心，必须无歧义）

### 2.1 为什么不能直接写 UTC

```
MT5 测试器内 TimeCurrent() 返回的是【服务器时间】。
Exness 服务器随 DST 在 GMT+2 与 GMT+3 之间切换。
若把窗口硬编码为服务器时间 09:00，则在 DST 切换后它对应的 UTC 时刻会漂移 1 小时，
→ 同一个策略在不同年份会交易不同的真实时段 → 不可比、不可复现。
```

### 2.2 本设计的处理（**运行时推导服务器 UTC 偏移**）

```
① 不在代码里写死偏移量。
② 在 OnInit 中读取【真实 USDJPYm 历史 bar 的周界】来推导偏移：
   · 取最近 90 天的 M1 bar 时间戳；
   · 找到「周一第一根 bar」与「周五最后一根 bar」；
   · 外汇市场周界 = 周日 22:00 UTC 开盘 / 周五 22:00 UTC 收盘；
   · 用观测到的周日开盘小时数反推 offset = obs_hour_utc(已知22) → server_offset = 22 - obs_hour;
   · 结果限定在 {2, 3}，否则判 `offset_undetermined` 并【终止 run】。
③ 所有时段阈值以 UTC 常量声明，运行期换算成服务器时间：
   server_hour = (utc_hour + server_offset) % 24
④ 每个 run 把推导出的 `server_offset` 与几个样例换算写入审计头部，
   供事后核验「这两年是否用了同一个偏移」。
```
**→ 若推导失败（例如数据周界不清晰），则该 run 直接 `environment_error`，不得静默用默认偏移。**

### 2.3 时段窗口（以 UTC 声明）

```
· Tokyo range  : UTC 00:00 → UTC 06:00    （6 小时）—— 定义当日区间 [R_hi, R_lo]
· Breakout win : UTC 07:00 → UTC 12:00    （5 小时）—— 只在此时段内寻找突破入场
· Hard flat    : UTC 20:00                （无论盈亏，必须平仓）
· 每日最多一笔；当日已成交则不再入场。
```
**为什么这样切**：Tokyo 段给出亚洲盘的区间；London 开盘（约 UTC 07:00–08:00）是波动放大的时段；
UTC 20:00 前平仓可**避免跨纽约收盘的隔夜跳空**，同时把 swap 影响压到最小。

## 3. 三个固定变体（只改一个结构轴）

| 变体 tag | 唯一差异（结构轴） | 其余全部相同 |
|---|---|---|
| `JSB30_V1` | **区间长度** = UTC 00:00–06:00（6 小时，基准） | ✅ |
| `JSB30_V2` | **区间长度** = UTC 00:00–03:00（3 小时，更短→更易突破） | ✅ |
| `JSB30_V3` | **收益上限** = 固定 TP 改为 **1.0×R**（V1/V2 为 1.5×R） | ✅ |

**★三个变体只改「区间长度」与「收益上限」这一个轴。**
**不事后添加方向过滤、周期、附加指标。**

### 3.1 完整入场/出场规则（预先固定）

```
【入场】（仅在 breakout win 内，且当日未成交）
  · 区间定义：R_hi = max(high) over [UTC 00:00, UTC 06:00)，R_lo = min(low) 同区间
    （只使用【已收盘】的 M30 bar，当前未收盘 bar 不参与）
  · 突破：M30 收盘价 > R_hi → 做多；收盘价 < R_lo → 做空
  · 过滤：区间宽度 ≥ 0.5 × ATR(14, M30)，否则当日不入场（避免假突破窄区间）
  · 每日最多一笔；单仓（有仓时不看新信号）

【出场】
  · 止损：入场价 ∓ 1.0 × ATR(14, M30)（固定，不移动）
  · 止盈：入场价 ± 1.5 × R（V1/V2）或 ± 1.0 × R（V3），R = 该笔的止损距离
  · 时间退出：最多 16 根 M30（8 小时）
  · 硬平仓：UTC 20:00 前必须平仓（reason = `window_end`）

【风险】
  · InpRiskPct = 1.5（500 USD → 7.5 USD/笔预算）
  · InpAllowMinLotOvershoot = false
  · InpMinLotMaxRiskPct = 3.0
  · 最小手超预算 → 拒单，并落盘 reject_reason（不允许静默跳过）
```

## 6. 预期失败机制（先写清，避免事后解释）

```
① 时段突破在 JPY 上无边际           → 净利≤0 / PF≤1（最可能）
② 高回撤：假突破被反复止损          → 官方 Equity DD > 40%
③ 成本吃掉边际：M30 频率下点差占比过高 → 2× 成本后转负
④ ★尾单依赖：即使换了结构仍"去前10大单后转负"
   → 若发生，说明尾单依赖是【品种/资金规模】的属性，不是结构属性
⑤ 最小手地板主导：500 USD 下 0.01 手不可再分
   → 若"依赖最小手超配"或成交数被地板扭曲
⑥ 时段窗在 DST 边界漂移导致前后不可比 → `server_offset` 推导在跨 DST 年份不一致
⑦ 样本不足：每日最多一笔 → 训练段约 1,900 交易日 → 上限约 1,900 笔；
   但只有「有突破」的日子才成交，实际可能远低于 50 笔/年门槛
```

**★第 ⑦ 条是本设计最需要 GPT 预先裁定的**：
```
每日最多一笔 ⇒ 交易日数即笔数上限。JPY 训练段(2017-01 ~ 2024-05)约 1,900 交易日
→ 即使 30% 的日子成交也只有 ~570 笔 / 7.4 年 = 77 笔/年 ✅ 过 50 笔/年门槛
→ 但若只有 5% 的日子成交 → 6 笔/年 ❌ 直接 REJECT-lowfreq
★ 请裁定：是否允许「每日最多一笔」这一结构（它有低频风险）？
   替代方案：允许每日最多两笔（区间上破 + 下破各一次），但仍单仓。
```
